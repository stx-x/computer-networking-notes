# 5.1　导论

上一章考察了网络层的**数据平面**——即网络层中"逐路由器"的那部分功能：一个数据报到达路由器后，如何根据首部字段查表、被送到某条出链路。这一章补上网络层的另一半：**控制平面**。它是网络范围的逻辑，不仅控制一个数据报如何沿源主机到目的主机的端到端路径被选路，也控制网络层组件与服务如何被配置和管理。

5.2 节讲传统的路由算法——在图中计算最小代价路径；这些算法是两种广泛部署的因特网路由协议的基础：5.3 节的 OSPF 与 5.4 节的 BGP。OSPF 在一家 ISP 的网络内部运行；BGP 则把因特网中所有网络互联起来，因而常被称为把因特网黏合在一起的"胶水"。传统上，控制平面的路由协议与数据平面的转发功能是一体化地（monolithically）实现在路由器内部的。而**软件定义网络**（SDN）明确地把数据平面与控制平面分开，把控制平面功能实现为一个独立的"控制器"服务——它独立于、且远程于它所控制的路由器的转发组件。SDN 控制器见 5.5 节。

5.6、5.7 节讲管理一个 IP 网络的一些"螺母与螺栓"：ICMP（因特网控制报文协议）与 SNMP（简单网络管理协议）。

先回顾图 4.2 与图 4.3，为控制平面的学习设定语境。在那两幅图里我们看到：**转发表**（在基于目的地址的转发情形下）与**流表**（在广义转发情形下）是把网络层数据平面与控制平面连接起来的主要元素。这些表规定了路由器在本地数据平面上的转发行为。在广义转发的情形下，所采取的动作不仅可以包括把分组转发到路由器的某个输出端口，还可以包括丢弃分组、复制分组，以及／或者重写第 2、3、4 层分组首部字段。

本章研究这些转发表与流表是如何被**计算、维护与安装**的。在 4.1 节对网络层的介绍中我们学到，做到这一点有两种可能的途径。

- **逐路由器控制**（per-router control）。图 5.1 展示的情形是：路由算法在**每一台**路由器中运行，转发功能与选路功能都包含在每台路由器内部。每台路由器有一个选路组件（routing component），它与其他路由器中的选路组件通信，来计算自己转发表中的值。这种逐路由器控制的方法在因特网中已使用了数十年。5.3、5.4 节要学的 OSPF 与 BGP 协议正是基于这种逐路由器控制途径的。
- **逻辑集中式控制**（logically centralized control）。图 5.2 展示的情形是：一个逻辑上集中的控制器计算转发表，并把它们分发给每一台路由器使用。正如 4.4、4.5 节所见，广义的"匹配加动作"抽象使路由器既能执行传统的 IP 转发，又能执行丰富的其他功能（负载分担、防火墙、NAT）——这些功能以前是在独立的中间盒中实现的。

<Figure src="ch05/fig5-01.webp" caption="图 5.1　逐路由器控制：各路由器中的选路算法组件在控制平面中交互" />

控制器通过一个定义良好的协议，与每台路由器中的一个**控制代理**（control agent，CA）交互，来配置和管理该路由器的流表。通常 CA 的功能极少：它的工作就是与控制器通信，并照控制器的命令行事。与图 5.1 中的路由算法不同，CA 之间不直接交互，也不主动参与转发表的计算。这正是逐路由器控制与逻辑集中式控制之间的关键区别。

<Figure src="ch05/fig5-02.webp" caption="图 5.2　逻辑集中式控制：一个独立的（通常远程的）控制器与本地控制代理（CA）交互" />

所谓"逻辑集中式"控制 [Levin 2012]，是指选路控制服务被访问时**就像**它是一个单一的中心服务点——尽管出于容错与性能可扩展性的考虑，该服务很可能由多台服务器实现。5.5 节将会看到，SDN 采纳的正是这种逻辑集中式控制器的概念，这一途径在生产部署中正得到越来越多的使用。[Cisco Trends 2020] 指出，2020 年 SDN 已在数据中心（64%）、广域网（58%）与接入网（40%）中得到广泛采用。5.5 节将研究 Google 的 Orion SDN [Ferguson 2021]——Google 用它来控制其数据中心内部的网络，以及互联这些数据中心的全球广域网。

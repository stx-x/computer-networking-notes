# 5.4　ISP 之间的选路：BGP

我们刚学到，OSPF 是 AS 内部路由协议的一个例子。在同一 AS 内为源与目的之间选路时，分组所走的路径完全由该 AS 内部路由协议决定。然而，要跨多个 AS 为分组选路——比如说从廷巴克图的一部智能手机到硅谷某数据中心的一台服务器——我们就需要一个**自治系统间路由协议**（inter-autonomous system routing protocol）。由于 AS 间路由协议涉及多个 AS 之间的协调，相互通信的 AS 必须运行相同的 AS 间路由协议。事实上，因特网中所有 AS 都运行同一个 AS 间路由协议，称为**边界网关协议**（Border Gateway Protocol），更常简称为 **BGP** [RFC 4271; Stewart 1999]。

可以说 BGP 是所有因特网协议中最重要的一个（唯一可与之竞争的是 4.3 节学过的 IP 协议），因为正是它把因特网中成千上万个 ISP 黏合在一起。我们很快就会看到，BGP 是一种分散的、异步的协议，与 5.2.2 节描述的距离向量选路一脉相承。BGP 虽然复杂而富有挑战，但要在深层理解因特网，就必须熟悉它的基础与运行方式。我们花在学 BGP 上的时间是值得的。

## 5.4.1　BGP 的作用

要理解 BGP 的职责，先考虑一个 AS 及其中任意一台路由器。回忆每台路由器都有一张转发表，它在把到达分组转发到出向路由器链路的过程中起核心作用。我们已经知道，对于同一 AS 内的目的地，路由器转发表中的表项由该 AS 的 AS 内部路由协议决定。但 AS 之外的目的地呢？这正是 BGP 出场的地方。

在 BGP 中，分组不是被路由到某个具体的目的地址，而是被路由到**无类域间选路**（CIDR 化）的**前缀**，每个前缀代表一个子网或一组子网。在 BGP 的世界里，一个目的地可能形如 `138.16.68/22`，对这个例子来说包含 1 024 个 IP 地址。因此，路由器的转发表中会有形如 $(x, I)$ 的表项，其中 $x$ 是一个前缀（如 `138.16.68/22`），$I$ 是路由器某个接口的接口号。

作为 AS 间路由协议，BGP 为每台路由器提供了以下手段：

1. **从相邻 AS 获取前缀可达性信息**。特别地，BGP 允许每个子网向因特网其余部分通告自己的存在。一个子网大喊"我存在，我在这里"，BGP 则确保因特网中所有路由器都知道这个子网。如果没有 BGP，每个子网都会成为一座孤岛——孤独、不为人知、因特网其余部分无法到达。
1. **确定到各前缀的"最佳"路由**。一台路由器可能学到通往某个特定前缀的两条或更多不同路由。为确定最佳路由，路由器会在本地运行一个 BGP 路由选择过程（使用它通过相邻路由器获得的前缀可达性信息）。最佳路由将依据策略以及可达性信息来确定。

下面深入看 BGP 如何完成这两项任务。

## 5.4.2　通告 BGP 路由信息

考虑图 5.8 所示的网络。可以看到，这个简单网络有三个自治系统：AS1、AS2 与 AS3。如图所示，AS3 包含一个前缀为 $x$ 的子网。在每个 AS 中，每台路由器要么是**网关路由器**，要么是**内部路由器**。网关路由器是位于 AS 边缘、直接连接到一个或多个其他 AS 中路由器的路由器。内部路由器只连接自己 AS 内的主机与路由器。例如在 AS1 中，路由器 1c 是网关路由器；路由器 1a、1b、1d 是内部路由器。

<Figure src="ch05/fig5-08.webp" caption="图 5.8　有三个自治系统的网络。AS3 包含一个前缀为 x 的子网" />

考虑把前缀 $x$ 的可达性信息通告给图 5.8 中所有路由器这项任务。从高层看，这很直接。首先，AS3 向 AS2 发送一条 BGP 报文，说 $x$ 存在且位于 AS3 中；把这条报文记为 "AS3 x"。然后 AS2 向 AS1 发送一条 BGP 报文，说 $x$ 存在，并且先经过 AS2、再到 AS3 就能到达 $x$；把这条报文记为 "AS2 AS3 x"。这样，每个自治系统不仅会知道 $x$ 的存在，还会知道一条通往 $x$ 的自治系统路径。

上一段的讨论虽然把大意讲清楚了，但并不精确——因为自治系统之间实际上并不互发报文，互发报文的是**路由器**。为理解这一点，我们重新审视图 5.8 中的例子。在 BGP 中，成对的路由器通过半永久的 TCP 连接（使用端口 179）交换路由信息。每条这样的 TCP 连接，以及该连接上发送的所有 BGP 报文，称为一条 **BGP 连接**。此外，跨越两个 AS 的 BGP 连接称为**外部 BGP**（eBGP）连接，同一 AS 内路由器之间的 BGP 会话称为**内部 BGP**（iBGP）连接。图 5.9 给出了图 5.8 网络中的 BGP 连接示例。通常，每一条直接连接不同 AS 中网关路由器的链路对应一条 eBGP 连接；因此在图 5.9 中，网关路由器 1c 与 2a 之间有一条 eBGP 连接，网关路由器 2c 与 3a 之间有一条 eBGP 连接。

<Figure src="ch05/fig5-09.webp" caption="图 5.9　eBGP 与 iBGP 连接" />

各 AS 内部的路由器之间还有 iBGP 连接。特别地，图 5.9 展示了一种常见配置：AS 内每一对路由器之间有一条 BGP 连接，从而在每个 AS 内部形成一张 TCP 连接网格。图 5.9 中，eBGP 连接用长虚线表示，iBGP 连接用短虚线表示。注意 iBGP 连接并不总是对应物理链路。

为传播可达性信息，iBGP 与 eBGP 会话都要用到。再考虑把前缀 $x$ 的可达性信息通告给 AS1 与 AS2 中所有路由器这一过程。在这个过程中，网关路由器 3a 首先向网关路由器 2c 发送 eBGP 报文 "AS3 x"。网关路由器 2c 随后向 AS2 中所有其他路由器（包括网关路由器 2a）发送 iBGP 报文 "AS3 x"。网关路由器 2a 随后向网关路由器 1c 发送 eBGP 报文 "AS2 AS3 x"。最后，网关路由器 1c 用 iBGP 向 AS1 中所有路由器发送报文 "AS2 AS3 x"。这个过程完成后，AS1 与 AS2 中每台路由器都知道 $x$ 的存在，也知道一条通往 $x$ 的 AS 路径。

当然，在真实网络中，从某台给定路由器出发到某个给定目的地可能有许多不同路径，每条经过不同的 AS 序列。例如考虑图 5.10 中的网络：它是图 5.8 的原网络，另加了一条从路由器 1d 到路由器 3d 的物理链路。此时，从 AS1 到 $x$ 有两条路径：经路由器 1c 的路径 "AS2 AS3 x"，以及经路由器 1d 的新路径 "AS3 x"。

## 5.4.3　确定最佳路由

我们刚学到，从某台给定路由器到某个目的子网可能有许多路径。事实上，因特网中的路由器经常收到关于数十条可能路径的可达性信息。路由器如何在这些路径中做选择（并据此配置自己的转发表）？

在回答这个关键问题之前，需要再引入一点 BGP 术语。当一台路由器跨 BGP 连接通告一个前缀时，它会随该前缀附带若干 **BGP 属性**。用 BGP 的行话说，一个前缀连同它的属性称为一条**路由**。两个更重要的属性是 AS-PATH 与 NEXT-HOP。**AS-PATH** 属性包含该通告所经过的 AS 列表，正如上面例子所见。为生成 AS-PATH 值，当前缀传给某个 AS 时，该 AS 把自己的 ASN 加到 AS-PATH 中已有列表的前面。例如在图 5.10 中，从 AS1 到子网 $x$ 有两条路由：一条使用 AS-PATH "AS2 AS3"，另一条使用 AS-PATH "AS3"。BGP 路由器还利用 AS-PATH 属性检测并防止通告环路；具体地说，如果一台路由器发现自己的 AS 出现在路径列表中，它就拒绝该通告。

**NEXT-HOP** 属性提供了 AS 间路由协议与 AS 内路由协议之间的关键联系，其用途微妙而重要。NEXT-HOP 是 AS-PATH 起始处那台路由器接口的 IP 地址。为深入理解这个属性，再看图 5.10。如图所示，从 AS1 到 $x$、经过 AS2 的路由 "AS2 AS3 x" 的 NEXT-HOP 属性，是路由器 2a 左侧接口的 IP 地址。

从 AS1 到 $x$、绕过 AS2 的路由 "AS3 x" 的 NEXT-HOP 属性，是路由器 3d 最左侧接口的 IP 地址。总之，在这个玩具例子中，AS1 中每台路由器都会知道两条到前缀 $x$ 的 BGP 路由：

路由器 2a 最左侧接口的 IP 地址；AS2 AS3；x

路由器 3d 最左侧接口的 IP 地址；AS3；x

这里每条 BGP 路由都写成由三部分构成的列表：NEXT-HOP；AS-PATH；目的前缀。实践中 BGP 路由还包含其他属性，此处暂且忽略。注意 NEXT-HOP 属性是一台**不属于** AS1 的路由器的 IP 地址；但包含该 IP 地址的子网直接连在 AS1 上。

### 热土豆选路

现在终于可以精确地讨论 BGP 路由算法了。先从最简单的路由算法之一——**热土豆选路**（hot potato routing）——开始。

考虑图 5.10 网络中的路由器 1b。如上所述，这台路由器将学到两条到前缀 $x$ 的可能 BGP 路由。在热土豆选路中，所选择的路由（在所有可能路由中）是**到该路由起始的 NEXT-HOP 路由器代价最小**的那条。在这个例子中，路由器 1b 会查询自己的 AS 内选路信息，找出到 NEXT-HOP 路由器 2a 的最小代价 AS 内路径，以及到 NEXT-HOP 路由器 3d 的最小代价 AS 内路径，然后选择这两条最小代价路径中代价更小的那条路由。例如，假设代价定义为经过的链路数，那么从路由器 1b 到路由器 2a 的最小代价是 2，从路由器 1b 到路由器 3d 的最小代价是 3，因此会选择路由器 2a。路由器 1b 随后查询自己的转发表（由 AS 内算法配置），找出位于到路由器 2a 最小代价路径上的接口 $I$，然后把 $(x, I)$ 加入自己的转发表。

热土豆选路下向路由器转发表中添加一个 AS 外前缀的步骤，汇总在图 5.11 中。需要强调的是：在把 AS 外前缀加入转发表时，AS 间路由协议（BGP）与 AS 内路由协议（如 OSPF）**两者**都要用到。

<Figure src="ch05/fig5-11.webp" caption="图 5.11　向路由器转发表中添加 AS 外目的地的步骤" />

热土豆选路背后的想法是：让路由器 1b 尽快（更准确地说，以尽可能小的代价）把分组弄出自己的 AS，而不去操心自己 AS 之外到目的地那部分路径的代价。在"热土豆选路"这个名字里，分组就像一只在你手里烫手的土豆；因为烫，你想尽快把它扔给别人（另一个 AS）。因此热土豆选路是一种**自私**的算法——它力图降低自己 AS 内的代价，而忽略 AS 之外端到端代价的其他部分。注意在热土豆选路下，同一 AS 内的两台路由器可能为同一前缀选择两条不同的 AS 路径。例如我们刚看到，路由器 1b 会经 AS2 把分组送到 $x$；而路由器 1d 会绕过 AS2，直接把分组送给 AS3 以到达 $x$。

### 路由选择算法

实践中 BGP 使用的算法比热土豆选路更复杂，但它仍包含热土豆选路。对任意给定的目的前缀，BGP 路由选择算法的输入是该路由器已学到并接受的所有到该前缀的路由集合。如果只有一条这样的路由，BGP 显然就选它。如果到同一前缀有两条或更多路由，BGP 就依次施加以下消除规则，直到只剩一条路由：

1. 一条路由会被赋予一个**本地偏好**（local preference）值，作为它的属性之一（除 AS-PATH 与 NEXT-HOP 之外）。一条路由的本地偏好可以由该路由器设置，也可以从同一 AS 内的另一台路由器学到。本地偏好属性的值是一项策略决定，完全由该 AS 的网络管理员掌握。（稍后我们会较详细地讨论 BGP 策略问题。）本地偏好值最高的路由被选中。
1. 在剩下的路由（都具有相同的最高本地偏好值）中，选择 AS-PATH 最短的那条。如果这条规则是路由选择的唯一规则，那么 BGP 就会用距离向量算法来确定路径，只是距离度量用 AS 跳数而不是路由器跳数。
1. 在剩下的路由（都具有最高本地偏好值且 AS-PATH 长度相同）中，使用热土豆选路，即选择 NEXT-HOP 路由器最近的那条路由。
1. 如果还剩下多条路由，路由器就用 BGP 标识符来选择；见 [Stewart 1999]。

举个例子，再考虑图 5.10 中的路由器 1b。回忆到前缀 $x$ 恰好有两条 BGP 路由，一条经过 AS2，一条绕过 AS2。还回忆：如果只用热土豆选路，BGP 会经 AS2 把分组送到前缀 $x$。但在上述路由选择算法中，规则 2 先于规则 3 施加，于是 BGP 选择绕过 AS2 的那条路由，因为它的 AS-PATH 更短。所以可以看到，在这个路由选择算法下，BGP 不再是一个自私的算法——它首先寻找 AS 路径短的路由（从而很可能降低端到端时延）。

如上所述，BGP 是因特网 AS 间选路的事实标准。要查看从 tier-1 ISP 的路由器中提取的各种 BGP 路由表（很大！）的内容，见 http://www.routeviews.org。BGP 路由表常常包含超过 50 万条路由（即前缀及相应属性）。关于 BGP 路由表规模与特征的统计见 [Huston 2019b]。

## 5.4.4　IP 任播

除了作为因特网的 AS 间路由协议，BGP 还常被用来实现 **IP 任播**（IP-anycast）服务 [RFC 1546, RFC 7094]，这在 DNS 中被普遍使用。为说明 IP 任播的动机，考虑许多应用中我们关心两件事：(1) 把相同内容复制到许多不同地理位置的多台服务器上；(2) 让每个用户从**最近**的那台服务器访问内容。例如，一个 CDN 可能把视频及其他对象复制到不同国家的服务器上；类似地，DNS 系统可以把 DNS 记录复制到世界各地的 DNS 服务器上。当用户想访问这些复制的内容时，最好把用户指向拥有该复制内容的"最近"服务器。BGP 的路由选择算法为此提供了一种简单而自然的机制。

为把讨论落到实处，描述一下 CDN 可能如何使用 IP 任播。如图 5.12 所示，在 IP 任播配置阶段，CDN 公司给它的每台服务器分配**同一个** IP 地址，并用标准 BGP 从每台服务器通告这个 IP 地址。当一台 BGP 路由器收到关于这个 IP 地址的多条路由通告时，它把这些通告视为通往同一物理位置的不同路径（而实际上，这些通告是通往不同物理位置的不同路径）。在配置路由表时，每台路由器会在本地用 BGP 路由选择算法为该 IP 地址挑选"最佳"（例如按 AS 跳数确定的最近）路由。例如，若一条 BGP 路由（对应一个位置）距该路由器只有一跳 AS，而所有其他 BGP 路由（对应其他位置）都距它两跳或更多 AS，那么该 BGP 路由器就会选择把分组路由到一跳之外的那个位置。在这个初始的 BGP 地址通告阶段之后，CDN 就可以做它的主业——分发内容。当客户端请求视频时，无论客户端在哪里，CDN 都把那些地理上分散的服务器所使用的共同 IP 地址返回给客户端。当客户端向该 IP 地址发送请求时，因特网路由器就把请求分组转发到 BGP 路由选择算法所定义的"最近"服务器。

<Figure src="ch05/fig5-12.webp" caption="图 5.12　用 IP 任播把用户带到最近的 CDN 服务器" />

尽管上面的 CDN 例子很好地说明了 IP 任播可以怎么用，但实践中 CDN 一般**不**选择使用 IP 任播，因为 BGP 路由的变化可能导致同一条 TCP 连接的不同分组到达 Web 服务器的不同实例。不过，IP 任播被 DNS 系统广泛用于把 DNS 查询导向最近的根 DNS 服务器。回忆 2.4 节：目前根 DNS 服务器有 13 个 IP 地址，但对应这 13 个地址中的每一个，都有多台 DNS 根服务器，其中某些地址对应的根服务器超过 100 台，散布在世界的各个角落。当一条 DNS 查询被发往这 13 个 IP 地址之一时，就用 IP 任播把该查询路由到负责该地址的、最近的那台 DNS 根服务器。[Li 2018; Zhou 2023] 给出了说明因特网任播的使用、性能与挑战的近期测量研究。

## 5.4.5　选路策略

当路由器为某个目的地选择路由时，AS 的选路策略可能压过所有其他考虑，比如最短 AS 路径或热土豆选路。确实，在路由选择算法中，路由首先按本地偏好属性来选，而该属性的值由本地 AS 的策略固定。

用一个简单例子说明 BGP 选路策略的一些基本概念。图 5.13 展示了六个互联的自治系统：A、B、C、W、X 与 Y。要注意 A、B、C、W、X、Y 是 **AS**，不是路由器。假设自治系统 W、X、Y 是接入 ISP，A、B、C 是骨干提供商网络。再假设 A、B、C 之间直接互送流量，并向它们的客户网络提供完整的 BGP 信息。所有进入某个 ISP 接入网络的流量，其目的地必须在该网络中；所有离开某个 ISP 接入网络的流量，其源必须在该网络中。W 与 Y 显然是接入 ISP。X 是一个**多宿**接入 ISP，因为它通过两个不同的提供商连接到网络其余部分（这种情形在实践中越来越常见）。然而，与 W 和 Y 一样，X 自身必须是所有离开／进入 X 的流量的源／目的地。但这种端网络（stub network）行为如何实现和强制？如何防止 X 在 B 与 C 之间转发流量？这很容易通过控制 BGP 路由的通告方式来实现。具体地说，如果 X 向它的邻居 B 与 C 通告说，除它自己之外它没有任何通往其他目的地的路径，那么 X 就会像一个接入 ISP 网络那样行事。也就是说，即使 X 知道一条比如 XCY 这样到达网络 Y 的路径，它也不会把这条路径通告给 B。既然 B 不知道 X 有通往 Y 的路径，B 就永远不会把目的地为 Y（或 C）的流量经 X 转发。这个简单例子说明了如何用有选择的通告知策略来实现客户／提供商之间的选路关系。

<Figure src="ch05/fig5-13.webp" caption="图 5.13　一个简单的 BGP 策略场景" />

接着关注一个提供商网络，比如 AS B。假设 B 已从 A 学到 A 有一条通往 W 的路径 AW。B 因此可以把路由 AW 装入自己的路由信息库。显然，B 也想把路径 BAW 通告给它的客户 X，好让 X 知道它可以经 B 到达 W。但 B 应该把路径 BAW 通告给 C 吗？如果通告了，那么 C 就可以经 BAW 把流量送到 W。如果 A、B、C 都是骨干提供商，那么 B 大可以认为自己不该承担在 A 与 C 之间承载过境（transit）流量的负担（和费用！）。B 大可以认为，确保 C 能经 A 与 C 之间的直接连接往返于 A 的客户，是 A 和 C 的事（和费用！）。目前没有正式标准规定骨干 ISP 之间如何选路。不过商业 ISP 遵循的一条经验法则是：任何穿越某个 ISP 骨干网络的流量，其源或目的（或两者）必须位于该 ISP 的**客户**网络中；否则这些流量就是在该 ISP 的网络上"搭便车"。个别对等协议（将规定上面提出的这类问题）通常由成对的 ISP 之间协商，且常常保密；[Huston 1999a; Huston 2012] 对对等协议有有趣的讨论。关于选路策略如何反映 ISP 之间商业关系的详细描述，见 [Gao 2001; Dmitiropoulos 2007]；从 ISP 角度讨论 BGP 选路策略，见 [Caesar 2005b]。

<AsideCard title="原理与实践 · 为什么要有不同的 AS 间与 AS 内路由协议？">

学完当今因特网中部署的具体 AS 间与 AS 内路由协议的细节之后，最后来考虑关于这些协议也许最根本的一个问题（希望你一直有此疑问，而没有"见树不见林"）：**为什么使用不同的 AS 间与 AS 内路由协议？**

这个问题的答案切中了 AS 内选路与 AS 间选路目标差异的核心：

- **策略**。在 AS 之间，策略问题占主导地位。某个 AS 发出的流量不能穿过另一个特定 AS，这可能很重要；同样，某个 AS 也很可能想控制它在其他 AS 之间承载哪些过境流量。我们已经看到，BGP 携带路径属性，并提供路由信息的受控分发，以便做出这类基于策略的选路决定。在一个 AS 内部，一切名义上都处于同一管理控制之下，因此策略问题在 AS 内选路中的作用小得多。
- **规模**。路由算法及其数据结构能否扩展到处理大量网络之间／之中的选路，是 AS 间选路的关键问题。在一个 AS 内部，可扩展性没那么令人担心。一方面，如果单个 ISP 变得太大，总可以把它分成两个 AS，在这两个新 AS 之间做 AS 间选路。（回忆 OSPF 允许通过把 AS 划分为区域来建立这种层次结构。）
- **性能**。由于 AS 间选路如此偏向策略，所用路由的质量（例如性能）常常是次要考虑（也就是说，一条满足某些策略标准但更长、代价更高的路由，很可能胜过一条更短但不满足该标准的路由）。确实，我们看到在 AS 之间甚至没有与路由相关的代价概念（除了 AS 跳数）。而在单个 AS 内部，这类策略考虑没那么重要，因而选路可以更关注一条路由上实际达到的性能水平。

</AsideCard>

以上完成了对 BGP 的简要介绍。理解 BGP 很重要，因为它在因特网中起核心作用。建议读者查阅本节列出的 BGP 参考文献（特别是 [Stewart 1999; Huston 2019a]），以及 [NSRC 2025] 上出色的在线 BGP 资源。

## 5.4.6　把各部分拼起来：获得因特网在场

本小节虽然严格来说不是讲 BGP 本身，但它把到此为止学过的许多协议与概念——包括 IP 编址、DNS 与 BGP——串在了一起。

假设你刚创建了一家小公司，拥有若干服务器，包括一台描述公司产品与服务的公共 Web 服务器、一台供员工收发电子邮件的邮件服务器，以及一台 DNS 服务器。自然，你希望全世界都能访问你的网站，了解你那些令人激动的产品与服务；你还希望员工能与世界各地的潜在客户互发电子邮件。

为达到这些目标，你首先需要获得因特网连接，这通过与本地 ISP 签约并连接到它来实现。你的公司将有一台**网关路由器**，连接到本地 ISP 中的一台路由器。这条连接可以是经现有电话基础设施的 DSL 连接、到 ISP 路由器的租用线路，或第 1 章描述的许多其他接入方案之一。最简单的情形是：本地 ISP 还会给你一段 IP 地址范围，例如一个由 256 个地址组成的 /24 地址范围。有了物理连接与 IP 地址范围之后，你把其中一个地址（在你那段范围内）分配给 Web 服务器，一个给邮件服务器，一个给 DNS 服务器，一个给网关路由器，其他地址分配给公司网络中其他服务器与联网设备。（若你的 ISP 使用了 4.3.3 节描述的 NAT，你的服务器编址设置会稍复杂一些。）

除了与 ISP 签约，你还需要与因特网注册机构签约，为公司取得一个域名（如第 2 章所述）。例如，若公司名叫 Xanadu Inc.，你自然会去争取域名 `xanadu.com`。你的公司还必须在 DNS 系统中获得在场。具体地说，因为外界要联系你的 DNS 服务器以获取你各服务器的 IP 地址，你还需要向注册机构提供你 DNS 服务器的 IP 地址。注册机构随后会把你的 DNS 服务器表项（域名与相应 IP 地址）放入 `.com` 顶级域服务器中（如第 2 章所述）。这一步完成后，任何知道你域名（如 `xanadu.com`）的用户都能通过 DNS 系统获得你 DNS 服务器的 IP 地址。

为了让人们能发现你 Web 服务器的 IP 地址，你需要在 DNS 服务器中包含把 Web 服务器主机名（如 `www.xanadu.com`）映射到其 IP 地址的表项。你还应为你公司其他可公开访问的服务器（包括邮件服务器）设置类似表项。这样，如果 Alice 想浏览你的 Web 服务器，DNS 系统会联系你的 DNS 服务器，找到你 Web 服务器的 IP 地址并交给 Alice，Alice 随后就能与你的 Web 服务器建立 TCP 连接。

然而，要让全世界的外部用户访问你的 Web 服务器，还有另一个必要且关键的步骤。考虑一下：当知道你的 Web 服务器 IP 地址的 Alice 向该地址发送一个 IP 数据报（例如一个 TCP SYN 报文段）时会发生什么。这个数据报将经因特网路由，经过许多不同 AS 中的一系列路由器，最终到达你的 Web 服务器。任何一台路由器收到该数据报时，都会在自己的转发表中查找表项，以确定应把它转发到哪个输出端口。因此，**每一台**路由器都需要知道你公司那个 /24 前缀（或某个聚合表项）的存在。路由器如何得知你公司的前缀？正如我们刚看到的，它是通过 **BGP** 得知的！具体地说，当你的公司与本地 ISP 签约并获得一个前缀（即一段地址范围）时，本地 ISP 会用 BGP 把你的前缀通告给它所连接的 ISP；那些 ISP 又会用 BGP 继续传播该通告。最终，所有因特网路由器都会知道你那个前缀（或包含该前缀的某个聚合），从而能正确转发目的地为你 Web 与邮件服务器的数据报。

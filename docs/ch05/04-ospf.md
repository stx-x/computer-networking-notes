# 5.3　因特网中的自治系统内部选路：OSPF

到目前为止，我们在研究路由算法时把网络简单看作一组互联的路由器。路由器之间无从区分——所有路由器执行同一个路由算法，计算穿越整个网络的路由路径。实践中，这种模型及其"同构路由器集合执行同一路由算法"的看法过于简化，原因有两点很重要：

- **规模**。当路由器数量变得很大时，通信、计算与存储路由信息所带来的开销会变得无法承受。今天的因特网由数亿台路由器组成。要在每台路由器上为可能的目的地存储路由信息，显然需要巨量内存；在所有路由器之间广播连通性与链路代价更新的开销也会极其庞大！在如此多的路由器之间迭代的距离向量算法肯定永远不会收敛。显然，必须做点什么来降低像因特网这样大的网络中路由计算的复杂度。
- **管理自治**。如 1.3 节所述，因特网是一个 ISP 的网络，每个 ISP 由自己的路由器网络组成。一个 ISP 通常希望按自己的意愿运营其网络（例如在网内运行它选择的任何路由算法），或向外界隐藏其网络内部组织的某些方面。理想情况下，一个组织应当能够按自己的意愿运营和管理自己的网络，同时仍能把网络连接到其他外部网络。

这两个问题都可以通过把路由器组织成**自治系统**（autonomous system，AS）来解决，每个 AS 由一组处于同一管理控制之下的路由器组成。通常，一个 ISP 中的路由器以及互联它们的链路构成单个 AS。不过有些 ISP 把网络划分为多个 AS。特别地，一些 tier-1 ISP 用一个大得惊人的 AS 覆盖整个网络，另一些则把 ISP 拆成数十个互联的 AS。自治系统由其全球唯一的**自治系统号**（ASN）标识 [RFC 1930]。AS 号与 IP 地址一样，由 ICANN 的区域注册机构分配 [ICANN 2025]。

同一 AS 内的路由器都运行相同的路由算法，并且彼此拥有对方的信息。在一个自治系统内运行的路由算法称为**自治系统内部路由协议**（intra-autonomous system routing protocol）。

## 开放最短路径优先（OSPF）

OSPF 选路及其近亲 IS-IS，被广泛用于因特网中的 AS 内部选路。OSPF 中的"Open"表示该路由协议规范是公开可得的（与之相对，Cisco 的 EIGRP 协议在作为 Cisco 专有协议约 20 年之后，直到最近才开放 [Savage 2015]）。OSPF 的最新版本是版本 2，定义在公开文档 [RFC 2328] 中。

OSPF 是一种**链路状态**协议，使用链路状态信息的泛洪与 Dijkstra 最小代价路径算法。在 OSPF 中，每台路由器构造整个自治系统的完整拓扑图（即一个图），然后各自在本地运行 Dijkstra 最短路径算法，以自己为根节点，确定到所有子网的最短路径树。各条链路的代价由网络管理员配置（见专栏"原理与实践：设置 OSPF 链路权重"）。管理员可以选择把所有链路代价都设为 1，从而实现最小跳数选路；也可以选择让链路权重与链路容量成反比，以抑制流量使用低带宽链路。OSPF 并不规定链路权重如何设置的策略（那是网络管理员的事），而是提供机制（协议），对给定的一组链路权重确定最小代价路径选路。

<AsideCard title="原理与实践 · 设置 OSPF 链路权重">

我们对链路状态选路的讨论隐含地假设：链路权重已经设定，然后运行 OSPF 之类的路由算法，流量按 LS 算法计算出的路由表流动。从因果关系的角度看，链路权重是给定的（即先有它们），它们（通过 Dijkstra 算法）导致使总体代价最小的路由路径。在这种视角下，链路权重反映使用一条链路的代价（例如，若链路权重与容量成反比，那么使用高容量链路的权重就更小，从而从选路角度看更有吸引力），而 Dijkstra 算法的作用是最小化总体代价。

实践中，链路权重与路由路径之间的因果关系可能被**颠倒**过来：网络运营者配置链路权重，是为了得到能实现某些**流量工程**目标的路由路径 [Fortz 2000, Fortz 2002]。例如，假设某网络运营者估计了从每个入网点进入网络、并以每个出网点为目的地的流量。运营者可能希望实施一种特定的入到出流量选路，使网络中所有链路上的**最大利用率**最小。但对 OSPF 这样的路由算法而言，运营者调节流量在网络中路由的主要"旋钮"就是链路权重。因此，为了实现最小化最大链路利用率的目标，运营者必须找出能达到该目标的那组链路权重。这就是因果关系的颠倒——期望的流量路由是已知的，而要找出 OSPF 链路权重，使得 OSPF 路由算法产生这一期望的流量路由。

</AsideCard>

在 OSPF 中，路由器向自治系统内**所有**其他路由器广播路由信息，而不只是向相邻路由器。每当链路状态发生变化（例如代价变化或通断状态变化）时，路由器就广播链路状态信息；即使链路状态没有变化，它也周期性地（至少每 30 分钟一次）广播链路状态。RFC 2328 指出，"这种对链路状态通告的周期性更新增强了链路状态算法的健壮性"。OSPF 通告包含在 OSPF 报文中，这些报文由 IP 直接承载，OSPF 的上层协议号为 89。因此，OSPF 协议本身必须实现可靠报文传输与链路状态广播等功能。OSPF 协议还会检查链路是否可用（通过向相邻路由器发送 HELLO 报文），并允许 OSPF 路由器获取相邻路由器的全网链路状态数据库。

OSPF 所体现的一些进步包括：

- **安全**。OSPF 路由器之间的交换（例如链路状态更新）可以被鉴别。有了鉴别，只有可信路由器才能参与 AS 内的 OSPF 协议，从而防止恶意入侵者（或者把新学到的知识拿去"兜风"的网络课学生）向路由表注入错误信息。默认情况下，路由器之间的 OSPF 报文不做鉴别，可能被伪造。可以配置两种鉴别方式——简单鉴别与 MD5（MD5 与鉴别的一般讨论见第 8 章）。简单鉴别是在每台路由器上配置同一个口令；路由器发送 OSPF 报文时以明文形式带上该口令。显然简单鉴别不太安全。MD5 鉴别基于配置在所有路由器中的共享密钥：对每个要发送的 OSPF 报文，路由器计算"OSPF 报文内容 + 密钥"的 MD5 散列（参见第 8 章关于报文鉴别码的讨论），然后把得到的散列值放进 OSPF 报文。接收路由器用预配置的密钥计算报文的 MD5 散列，并与报文携带的散列值比较，从而验证报文的真实性。MD5 鉴别还配合使用序号，以防重放攻击。
- **支持多条同代价路径**。当到达某个目的地的多条路径代价相同时，OSPF 允许使用多条路径（即存在多条等代价路径时，不必只选一条来承载全部流量）。
- **集成支持单播与组播选路**。组播 OSPF（MOSPF）[RFC 1584] 对 OSPF 做了简单扩展以支持组播选路。MOSPF 使用现有的 OSPF 链路数据库，并在现有 OSPF 链路状态广播机制中增加一种新的链路状态通告类型。
- **支持单个 AS 内的层次结构**。一个 OSPF 自治系统可以按层次配置为多个**区域**（area）。每个区域运行自己的 OSPF 链路状态路由算法，区域内每台路由器把其链路状态广播给该区域内所有其他路由器。每个区域内有一台或多台**区域边界路由器**负责把分组路由到区域之外。最后，AS 中恰好有一个 OSPF 区域被配置为**骨干区域**（backbone area）。骨干区域的主要作用是在 AS 内其他区域之间路由流量。骨干区域总是包含 AS 中所有区域边界路由器，也可以包含非边界路由器。AS 内的区域间选路要求：分组先被路由到一台区域边界路由器（区域内选路），再经骨干区域路由到位于目的区域的区域边界路由器，然后路由到最终目的地。

OSPF 是一个相对复杂的协议，我们这里的介绍只能简短；更多细节见 [Huitema 1998; Moy 1998; RFC 2328]。

# 6.4　交换式局域网

<Figure src="ch06/fig6-15.webp" caption="图 6.15　由四台交换机连接起来的机构网络" />

上一节讨论了广播网络与多路访问协议，接下来把注意力转向**交换式局域网**。图 6.15 展示了一个交换式局域网，它用四台交换机把三个系、若干服务器和一台路由器连接起来。由于这些交换机工作在链路层，它们交换的是**链路层帧**（而不是网络层数据报），不认识网络层地址，也不用 OSPF 之类的路由算法来确定穿越二层交换机网络的路径。它们不用 IP 地址，而是很快会看到，它们用**链路层地址**在交换机网络中转发链路层帧。我们研究交换式局域网，先从链路层编址开始（6.4.1 节），然后考察大名鼎鼎的以太网协议（6.4.2 节），再看链路层交换机如何工作（6.4.3 节），最后看这些交换机通常如何被用来构建大规模局域网（6.4.4 节）。

## 6.4.1　链路层编址与 ARP

主机和路由器都有链路层地址。回想第 4 章学过主机和路由器也有网络层地址，你也许会觉得这很奇怪：我们到底为什么要在网络层和链路层**都**有地址？本节除了描述链路层地址的语法与功能，还希望说明这两层地址为什么有用、事实上为什么不可或缺。本节还会讨论**地址解析协议**（ARP），它提供了把 IP 地址翻译成链路层地址的机制。

### MAC 地址

严格说来，拥有链路层地址的并不是主机和路由器，而是它们的**适配器**（即网络接口）。因此，一台有多个网络接口的主机或路由器会有多个链路层地址与之关联，正如它也会关联多个 IP 地址一样。不过要注意，链路层交换机连接主机和路由器的那些接口并没有关联的链路层地址。这是因为链路层交换机的职责是在主机与路由器之间承载数据报；交换机完成这项工作是**透明**的，即主机或路由器不必显式地把帧地址写成中间那台交换机。图 6.16 说明了这一点。链路层地址有各种叫法：局域网地址、物理地址或 **MAC 地址**。由于 MAC 地址似乎是最流行的说法，下文我们把链路层地址称为 MAC 地址。对大多数局域网（包括以太网与 802.11 无线局域网），MAC 地址长 6 字节，共有 $2^{48}$ 个可能的 MAC 地址。如图 6.16 所示，这 6 个字节通常用十六进制表示，每个字节写成一对十六进制数字。虽然 MAC 地址当初设计为永久的，但现在已可以通过软件修改适配器的 MAC 地址。不过本节余下部分仍假定适配器的 MAC 地址是固定的。

<Figure src="ch06/fig6-16.webp" caption="图 6.16　连到局域网的每个接口都有一个唯一的 MAC 地址" />

MAC 地址的一个有趣性质是：没有两个适配器具有相同的地址。考虑到适配器由许多国家的许多公司制造，这似乎令人惊讶。在台湾制造适配器的公司如何确保自己用的地址与比利时某公司不同？答案是 IEEE 管理着 MAC 地址空间。具体地说，当一家公司想制造适配器时，它花一点象征性的费用购买一块由 $2^{24}$ 个地址组成的地址空间。IEEE 通过固定 MAC 地址的前 24 比特来分配这块 $2^{24}$ 的地址，并让该公司为每个适配器在后 24 比特上创造唯一组合。

适配器的 MAC 地址是**扁平**结构（相对于层次结构），无论适配器到哪里都不改变。带以太网接口的笔记本电脑，无论计算机到哪里都始终具有相同的 MAC 地址；带 802.11 接口的智能手机，无论手机到哪里都始终具有相同的 MAC 地址。回想相比之下，IP 地址具有层次结构（即一个网络部分加一个主机部分），主机移动（即改变所连接的网络）时其 IP 地址需要改变。适配器的 MAC 地址类似于人的**社会保障号**——它也是扁平编址结构，无论人到哪里都不变；IP 地址则类似于人的**邮政地址**——它是层次的，人一搬家就必须改变。正如一个人会发现同时拥有邮政地址和社会保障号很有用，主机与路由器接口同时拥有网络层地址和 MAC 地址也是有用的。

当一个适配器想向某个目的适配器发送帧时，发送适配器把目的适配器的 MAC 地址插入帧中，然后把帧发送到局域网中。很快会看到，交换机会偶尔把收到的帧广播到它的所有接口上；第 7 章会看到 802.11 也广播帧。因此，一个适配器可能收到并非发给它的帧。所以适配器收到帧时会检查帧中的目的 MAC 地址是否与自己的 MAC 地址匹配：若匹配，适配器取出封装的数据报并上交协议栈；若不匹配，适配器丢弃该帧，不上交网络层数据报。这样，只有当帧是发给它的时候，目的方才被打断。

不过，有时发送适配器确实想让局域网上的所有其他适配器都接收并处理它要发送的帧。这时发送适配器在帧的目的地址字段中填入一个特殊的 **MAC 广播地址**。对使用 6 字节地址的局域网（如以太网与 802.11），广播地址是 48 个连续的 1（即十六进制的 `FF-FF-FF-FF-FF-FF`）。

<AsideCard title="原理与实践 · 保持各层独立">

主机与路由器接口除了网络层地址之外还要有 MAC 地址，有几个原因。第一，局域网是为任意网络层协议设计的，而不只是为 IP 和因特网。如果适配器被分配 IP 地址而不是"中立"的 MAC 地址，那么适配器就不容易支持其他网络层协议（例如 IPX 或 DECnet）。第二，如果适配器改用网络层地址而不是 MAC 地址，那么网络层地址就必须存放在适配器的 RAM 中，并且每次适配器被移动（或上电）时都要重新配置。另一种选择是完全不在适配器中使用地址，让每个适配器把它收到的每个帧的数据（通常是 IP 数据报）都上交协议栈，由网络层去检查网络层地址是否匹配。这种选择的一个问题是：主机将被局域网上发送的**每一个**帧打断，包括那些目的地是同一广播局域网中其他主机的帧。总之，要使各层成为网络体系结构中大体独立的构建块，不同层就需要有各自的编址方案。至此我们已见过三类地址：应用层的主机名、网络层的 IP 地址、链路层的 MAC 地址。

</AsideCard>

### 地址解析协议（ARP）

由于既有网络层地址（例如因特网 IP 地址）又有链路层地址（即 MAC 地址），就需要在两者之间进行翻译。对因特网而言，这是**地址解析协议**（ARP）[RFC 826] 的职责。

为理解为什么需要 ARP 这样的协议，考虑图 6.17 所示的网络。在这个简单例子中，每台主机和路由器只有一个 IP 地址和一个 MAC 地址。照例，IP 地址用点分十进制表示，MAC 地址用十六进制表示。为便于讨论，本节假定交换机广播所有帧，即每当交换机在一个接口上收到帧，就把它从所有其他接口转发出去。下一节将给出交换机工作方式的更准确说明。

<Figure src="ch06/fig6-17.webp" caption="图 6.17　局域网上的每个接口都有一个 IP 地址和一个 MAC 地址" />

现在假设 IP 地址为 `222.222.222.220` 的主机想向主机 `222.222.222.222` 发送一个 IP 数据报。在这个例子中，源与目的在 4.3.3 节编址意义上属于同一子网。要发送数据报，源不仅要给它的适配器 IP 数据报，还要给出目的地 `222.222.222.222` 的 MAC 地址；发送适配器随后构造一个包含目的 MAC 地址的链路层帧，并把帧发送到局域网中。

本节要回答的重要问题是：发送主机如何确定 IP 地址为 `222.222.222.222` 的目的主机的 MAC 地址？你可能已经猜到，它使用 ARP。发送主机中的 ARP 模块以同一局域网上的任意 IP 地址为输入，返回相应的 MAC 地址。在手头的例子里，发送主机 `222.222.222.220` 把 IP 地址 `222.222.222.222` 交给它的 ARP 模块，ARP 模块返回相应的 MAC 地址 `49-BD-D2-C7-56-2A`。

可见 ARP 把 IP 地址解析为 MAC 地址。在许多方面它类似于 DNS（2.5 节研究过），后者把主机名解析为 IP 地址。但这两个解析器有一个重要区别：DNS 为因特网中**任何地方**的主机解析主机名，而 ARP 只为**同一子网**上的主机和路由器接口解析 IP 地址。如果加利福尼亚的某个节点试图用 ARP 解析密西西比州某节点的 IP 地址，ARP 会返回一个错误。

说明了 ARP 做什么，接下来看它如何工作。每台主机和路由器在内存中都有一张 **ARP 表**，其中包含 IP 地址到 MAC 地址的映射。图 6.18 给出主机 `222.222.222.220` 中 ARP 表可能的样子。ARP 表还包含一个**生存期**（TTL）值，表明每个映射何时从表中删除。注意，表里不一定有子网上每台主机和路由器的表项：有些可能从未被加入表中，有些可能已经过期。表项典型的过期时间是自放入 ARP 表起的 20 分钟。

<Figure src="ch06/fig6-18.webp" caption="图 6.18　222.222.222.220 中一张可能的 ARP 表" />

现在假设主机 `222.222.222.220` 想发送一个以该子网上另一台主机或路由器为 IP 目的地的数据报。发送主机需要在给定 IP 地址的情况下取得目的地的 MAC 地址。如果发送方的 ARP 表中已有目的节点的表项，这件事很容易。但如果 ARP 表当前没有目的地的表项呢？特别地，假设 `222.222.222.220` 想向 `222.222.222.222` 发送数据报。这时发送方用 ARP 协议来解析地址。首先，发送方构造一个称为 **ARP 分组**的特殊分组。ARP 分组有几个字段，包括发送方与接收方的 IP 地址和 MAC 地址。ARP 查询分组与响应分组格式相同。ARP 查询分组的用途是向子网上所有其他主机和路由器查询"被解析的那个 IP 地址对应哪个 MAC 地址"。

回到我们的例子，`222.222.222.220` 把一个 ARP 查询分组交给适配器，并指示适配器把该分组发送到 MAC 广播地址，即 `FF-FF-FF-FF-FF-FF`。适配器把 ARP 分组封装进链路层帧，用广播地址作为帧的目的地址，并把帧发送到子网中。回想我们关于社会保障号／邮政地址的类比，ARP 查询相当于一个人在某公司（比如 AnyCorp）拥挤的隔间办公室里大喊："邮政地址是加利福尼亚帕洛阿尔托 AnyCorp 112 房间 13 号隔间的那个人，社会保障号是多少？"包含 ARP 查询的帧被子网上所有其他适配器收到，并且（由于是广播地址）每个适配器都把帧中的 ARP 分组上交自己的 ARP 模块。每个 ARP 模块检查自己的 IP 地址是否与 ARP 分组中的目的 IP 地址匹配；匹配的那一个向查询主机回送一个包含所需映射的 ARP 响应分组。查询主机 `222.222.222.220` 随后就可以更新自己的 ARP 表，并发送它的 IP 数据报——封装在一个链路层帧中，该帧的目的 MAC 地址就是刚才响应 ARP 查询的那台主机或路由器的地址。

关于 ARP 协议，有几点值得注意。第一，ARP **查询**报文是在广播帧中发送的，而 ARP **响应**报文是在标准帧中发送的（继续往下读之前，你应当想一想为什么会这样）。第二，ARP 是**即插即用**的：ARP 表自动建立，不需要系统管理员配置；而且如果某台主机从子网上断开，它的表项最终会从子网上其他 ARP 表中删除。

学生常问：ARP 是链路层协议还是网络层协议？如我们所见，ARP 分组封装在链路层帧中，因此在体系结构上位于链路层之上。但 ARP 分组含有链路层地址字段，因此可以说它是链路层协议；它又含有网络层地址，因此也可以说是网络层协议。归根到底，ARP 最好被看作一个横跨链路层与网络层边界的协议——它并不整齐地落入我们在第 1 章学过的简单分层协议栈。现实世界中的协议就是这般复杂！

### 向子网之外发送数据报

现在应该清楚主机向同一子网上另一台主机发送数据报时 ARP 如何工作了。但接下来看更复杂的情形：子网上的一台主机想向子网**之外**（即跨过一台路由器到另一个子网）的主机发送网络层数据报。我们结合图 6.19 来讨论这个问题，该图展示了一个由路由器互联的两个子网组成的简单网络。

<Figure src="ch06/fig6-19.webp" caption="图 6.19　由一台路由器互联的两个子网" />

关于图 6.19 有几点值得注意。每台主机恰好有一个 IP 地址和一个适配器。但如第 4 章所述，路由器为其每个接口都有一个 IP 地址；每个路由器接口还各有一个（路由器中的）ARP 模块和一个适配器。由于图 6.19 中的路由器有两个接口，它有两个 IP 地址、两个 ARP 模块和两个适配器。当然，网络中每个适配器都有自己的 MAC 地址。

还要注意，子网 1 的网络地址是 `111.111.111/24`，子网 2 的网络地址是 `222.222.222/24`。因此，连接到子网 1 的所有接口地址形如 `111.111.111.xxx`，连接到子网 2 的所有接口地址形如 `222.222.222.xxx`。

现在考察子网 1 上的一台主机如何向子网 2 上的一台主机发送数据报。具体地，假设主机 `111.111.111.111` 想向主机 `222.222.222.222` 发送一个 IP 数据报。发送主机照例把数据报交给它的适配器，但发送主机还必须向适配器指明一个合适的**目的 MAC 地址**。适配器该用哪个 MAC 地址？人们可能忍不住猜：合适的 MAC 地址是主机 `222.222.222.222` 那个适配器的地址，即 `49-BD-D2-C7-56-2A`。但这个猜测是**错的**！如果发送适配器使用那个 MAC 地址，那么子网 1 上没有任何适配器会把该 IP 数据报上交网络层，因为帧的目的地址不匹配子网 1 上任何适配器的 MAC 地址。这个数据报只会直接"死掉"、上数据报天堂。

仔细看图 6.19 就会发现，要让数据报从 `111.111.111.111` 到达子网 2 上的主机，必须先把数据报发给路由器接口 `111.111.111.110`，它是通往最终目的地路径上的**第一跳路由器**的 IP 地址。因此，帧合适的目的 MAC 地址是路由器接口 `111.111.111.110` 那个适配器的地址，即 `E6-E9-00-17-BB-4B`。发送主机如何获得 `111.111.111.110` 的 MAC 地址？当然还是用 ARP！一旦发送适配器拿到这个 MAC 地址，它就构造一个帧（其中含有目的地为 `222.222.222.222` 的数据报）并把帧发送到子网 1。子网 1 上的路由器适配器看到链路层帧是发给自己的，于是把帧交给路由器的网络层。好极了——IP 数据报已成功从源主机移动到路由器！但事情还没完，我们还得把数据报从路由器送到目的地。路由器现在必须确定应该从哪个接口转发该数据报。如第 4 章所述，这是通过查询路由器中的转发表完成的。转发表告诉路由器：该数据报应经路由器接口 `222.222.222.220` 转发。这个接口随后把数据报交给它的适配器，适配器把数据报封装进一个新帧并把帧发送到子网 2。这一次，帧的目的 MAC 地址确实是最终目的地的 MAC 地址。路由器如何获得这个目的 MAC 地址？当然还是从 ARP！

以太网的 ARP 定义在 RFC 826 中。RFC 1180 这份 TCP/IP 教程对 ARP 作了很好的介绍。我们将在章末习题中更详细地探讨 ARP。

## 6.4.2　以太网

以太网几乎已经占领了有线局域网市场。20 世纪 80 年代与 90 年代初，以太网面临来自其他局域网技术（包括令牌环、FDDI 与 ATM）的诸多挑战，其中一些技术在几年里确实抢到了一部分局域网市场。但自 20 世纪 70 年代中期发明以来，以太网不断发展壮大，并一直保持主导地位。今天，以太网是迄今最普遍的有线局域网技术，而且在可预见的未来很可能仍将如此。可以说，以太网之于局域网，正如因特网之于全球网络。

以太网成功的原因很多。第一，以太网是第一个广泛部署的高速局域网。由于部署得早，网络管理员对以太网非常熟悉——它的奇妙之处与种种怪癖——因而不愿在别的局域网技术出现时转投过去。第二，令牌环、FDDI 与 ATM 都比以太网更复杂、更昂贵，这进一步抑制了网络管理员转投的意愿。第三，转投另一种局域网技术（如 FDDI 或 ATM）最有说服力的理由，通常是新技术更高的数据速率；然而以太网总能反击，推出速率相当或更高的版本。20 世纪 90 年代初问世的交换式以太网进一步提高了其有效数据速率。最后，由于以太网如此流行，以太网硬件（特别是适配器与交换机）已成为大宗商品，价格便宜得惊人。

最初的以太网局域网由 Bob Metcalfe 与 David Boggs 在 20 世纪 70 年代中期发明。最初的以太网用同轴电缆总线互联节点；以太网的**总线拓扑**一直延续到 80 年代、进入 90 年代中期。总线拓扑的以太网是一个广播局域网——所有发送的帧都会到达总线上连接的每个适配器并被其处理。回忆 6.3.2 节我们讨论过以太网采用二进制指数退避的 CSMA/CD 多路访问协议。

到 20 世纪 90 年代末，多数公司和大学已把局域网换成了采用**基于集线器的星形拓扑**的以太网。在这种安装方式中，主机（和路由器）用双绞铜线直接连到一台**集线器**（hub）。集线器是一种物理层设备，作用于单个比特而不是帧。当一个表示 0 或 1 的比特从某个接口到达时，集线器只是重新生成该比特、增强其能量强度，并把它发送到所有其他接口。因此，基于集线器星形拓扑的以太网也是一个广播局域网——每当集线器从某个接口收到一个比特，它就向所有其他接口发送一份拷贝。特别地，如果集线器同时从两个不同接口收到帧，就会发生冲突，产生这些帧的节点必须重传。

21 世纪初，以太网又经历了一次重大演进。以太网安装仍采用星形拓扑，但中心的集线器被**交换机**取代。本章后面将深入考察交换式以太网。这里只需指出：交换机不仅"无冲突"，而且是名副其实的**存储转发分组交换机**；但与一直工作到第 3 层的路由器不同，交换机只工作到第 2 层。

### 以太网帧结构

通过考察以太网帧（图 6.20）可以了解以太网的许多方面。为给这段关于以太网帧的讨论一个具体语境，考虑从一台主机向另一台主机发送 IP 数据报，两台主机在同一个以太网局域网中（例如图 6.17 中的以太网局域网）。（虽然我们这里以太网帧的载荷是 IP 数据报，但要指出以太网帧也可以承载其他网络层分组。）设发送适配器 A 的 MAC 地址为 `AA-AA-AA-AA-AA-AA`，接收适配器 B 的 MAC 地址为 `BB-BB-BB-BB-BB-BB`。发送适配器把 IP 数据报封装进以太网帧，并把帧交给物理层；接收适配器从物理层收到帧，取出 IP 数据报，并把它交给网络层。在这个语境下，来看图 6.20 所示以太网帧的六个字段。

<Figure src="ch06/fig6-20.webp" caption="图 6.20　以太网帧结构" />

- **数据字段（46–1 500 字节）**。该字段承载 IP 数据报。以太网的**最大传输单元**（MTU）是 1 500 字节，这意味着若 IP 数据报超过 1 500 字节，主机就必须按 4.3.2 节所述对数据报分片。数据字段的最小长度是 46 字节，这意味着若 IP 数据报不足 46 字节，数据字段就必须"填充"（stuffing）到 46 字节。使用填充时，交给网络层的数据既包含填充也包含 IP 数据报；网络层用 IP 数据报首部中的长度字段去掉填充。
- **目的地址（6 字节）**。该字段包含目的适配器的 MAC 地址 `BB-BB-BB-BB-BB-BB`。当适配器 B 收到一个目的地址为 `BB-BB-BB-BB-BB-BB` 或 MAC 广播地址的以太网帧时，它把该帧数据字段的内容交给网络层；若收到目的地址为其他任何 MAC 地址的帧，它就丢弃该帧。
- **源地址（6 字节）**。该字段包含把帧发送到局域网上的那个适配器的 MAC 地址，本例中为 `AA-AA-AA-AA-AA-AA`。
- **类型字段（2 字节）**。类型字段使以太网能多路复用网络层协议。要理解这一点，需记住主机除 IP 之外还可以使用其他网络层协议；事实上，一台给定主机可能为不同应用支持多个网络层协议。因此，当以太网帧到达适配器 B 时，适配器 B 需要知道应把数据字段的内容交给（即多路分用给）哪个网络层协议。IP 及其他网络层协议（例如 Novell IPX 或 AppleTalk）各有自己标准化的类型号。此外，ARP 协议（上一节讨论过）有自己的类型号；若到达的帧包含 ARP 分组（即类型字段为十六进制 `0806`），ARP 分组就会被多路分用上交 ARP 协议。注意，类型字段类似于网络层数据报中的协议字段以及运输层报文段中的端口号字段——这些字段都起到把一层的协议"粘"到上一层协议的作用。
- **循环冗余检测（CRC）（4 字节）**。如 6.2.3 节所述，CRC 字段的用途是让接收适配器 B 检测帧中的比特差错。
- **前同步码（8 字节）**。以太网帧以一个 8 字节的**前同步码**（preamble）字段开始。前同步码的前 7 个字节每个都是 `10101010`，最后一个字节是 `10101011`。前 7 个字节用于"唤醒"接收适配器，并把它们的时钟同步到发送方时钟。为什么时钟会不同步？要记住，适配器 A 的目标是以 10 Mbit/s、100 Mbit/s 或 1 Gbit/s（取决于以太网类型）发送帧；但由于没有什么是绝对完美的，适配器 A 不会恰好以目标速率发送，总会有某种偏离目标速率的漂移，而局域网上其他适配器事先并不知道这种漂移。接收适配器只要锁定前同步码前 7 个字节中的比特，就能锁定适配器 A 的时钟。前同步码第 8 个字节的最后 2 个比特（最先出现的两个连续 1）提醒适配器 B："重要的东西"就要来了。

所有以太网技术都向网络层提供**无连接**服务。也就是说，当适配器 A 想向适配器 B 发送数据报时，适配器 A 把数据报封装进以太网帧并把帧发送到局域网中，而不先与适配器 B 握手。这种二层无连接服务类似于 IP 的三层数据报服务与 UDP 的四层无连接服务。

以太网技术向网络层提供**不可靠**服务。具体地说，当适配器 B 从适配器 A 收到帧时，它对帧做 CRC 校验，但帧通过 CRC 校验时不发送确认，帧未通过 CRC 校验时也不发送否定确认；帧未通过 CRC 校验时，适配器 B 只是丢弃该帧。因此适配器 A 根本不知道它发送的帧是否到达适配器 B、是否通过了 CRC 校验。这种（链路层）可靠传输的缺失有助于使以太网简单廉价，但也意味着交给网络层的数据报流中可能出现空缺。

如果因为以太网帧被丢弃而出现空缺，主机 B 上的应用也会看到空缺吗？如第 3 章所学，这取决于应用用的是 UDP 还是 TCP。若应用使用 UDP，主机 B 上的应用确实会看到数据空缺；若应用使用 TCP，主机 B 中的 TCP 不会确认被丢弃帧中所含的数据，从而使主机 A 中的 TCP 重传。注意，TCP 重传数据时，这些数据最终会回到当初丢弃它的那个以太网适配器。因此在这个意义上，以太网确实重传了数据——尽管以太网并不知道自己发送的是一个带全新数据的全新数据报，还是一个含有至少已发送过一次的数据的数据报。

### 以太网技术

上面的讨论中我们把以太网当作单一协议标准来谈。但事实上以太网有许多不同"口味"，其缩写令人眼花缭乱：10BASE-T、10BASE-2、100BASE-T、1000BASE-LX、10GBASE-T、40GBASE-T 等等。这些以及许多其他以太网技术多年来由 IEEE 802.3 CSMA/CD（以太网）工作组标准化 [IEEE 802.3 2020]。这些缩写看似令人困惑，其实很有规律：缩写的第一部分指标准的速度——10、100、1000 或 10G，分别表示 10 兆比特（每秒）、100 兆比特、千兆、10 吉比特与 40 吉比特以太网；"BASE" 指**基带**以太网，即物理介质只承载以太网流量，几乎所有 802.3 标准都是基带以太网；缩写的最后一部分指物理介质本身——以太网既是链路层规范也是物理层规范，可运行在同轴电缆、铜线、光纤等多种物理介质上，通常 "T" 指双绞铜线。

历史上，以太网最初被设想为一段同轴电缆。早期的 10BASE-2 与 10BASE-5 标准规定在两种同轴电缆上运行 10 Mbit/s 以太网，每种长度限制为 500 米；更长的距离可以通过**中继器**（repeater）实现——一种在输入端接收信号、在输出端重新生成信号的物理层设备。同轴电缆非常契合我们把以太网看作广播介质的观点——一个接口发送的所有帧都会被其他接口收到，以太网的 CSMA/CD 协议正好解决多路访问问题。节点只要接到电缆上，瞧，我们就有了一个局域网！

多年来以太网经历了一系列演进，今天的以太网与最初使用同轴电缆的总线拓扑设计已大不相同。今天大多数安装中，节点通过铜线或光纤构成的点对点段连接到交换机，如图 6.15–6.17 所示。

到 2000 年代中期，千兆以太网的各种标准已经就位——顾名思义，它以每秒 1 吉比特传输比特。早期 10 Mbit/s 与 100 Mbit/s 的以太网 MAC 协议与帧格式被保留下来，但为双绞铜线（1000BASE-T）、光纤（1000BASE-SX、1000BASE-LX、1000BASE-LX10、1000BASE-BX10）与铜缆（1000BASE-CX）定义了更高速的物理层。允许的以太网距离从几十米（双绞线）到某些光纤物理层的几十公里不等。图 6.21 展示了这些不同标准与共同的以太网 MAC 协议及帧格式。千兆以太网今天仍在使用，而为 10、40、100、200 与 400 Gbit/s 的更高速度以太网标准也已制定。

<Figure src="ch06/fig6-21.webp" caption="图 6.21　100 Gbit/s 以太网标准：共同的链路层，不同的物理层" />

最后用一个也许一直困扰你的问题来结束以太网技术的讨论。在总线拓扑与基于集线器的星形拓扑时代，以太网显然是（6.3 节所定义的）广播链路，节点同时发送时会发生帧冲突；为处理这些冲突，以太网标准包含了 CSMA/CD 协议，它对覆盖较小地理范围的有线广播局域网特别有效。但如果今天以太网的主流用法是基于交换机的星形拓扑、使用存储转发分组交换，那么还需要以太网 MAC 协议吗？我们很快会看到，交换机会协调其传输，任何时候都不会向同一接口转发一个以上的帧；此外现代交换机是**全双工**的，交换机和节点可以同时互相发送帧而不受干扰。换句话说，在基于交换机的以太网局域网中不存在冲突，因而也就不需要 MAC 协议！

如我们所见，今天的以太网与 40 多年前 Metcalfe 和 Boggs 构想的最初以太网已大不相同——速率提高了三个数量级，以太网帧运行在多种介质上，交换式以太网占据主导，如今甚至常常不需要 MAC 协议！这一切还算是以太网吗？答案当然是"按定义，是的"。不过有意思的是，在所有这些变化中，确实有一个近 50 年不变的恒量——以太网的**帧格式** [Metcalfe 2025]。也许这才是以太网标准中唯一真正永恒的核心。

## 6.4.3　链路层交换机

到此为止，我们一直有意含糊地谈交换机究竟做什么、如何工作。交换机的职责是接收到达的链路层帧并把它们转发到出链路上；本小节详细研究这一转发功能。我们会看到，交换机本身对子网中的主机和路由器是**透明**的——主机／路由器把帧寻址到另一台主机／路由器（而不是寻址到交换机），然后把帧高高兴兴地发送到局域网中，完全不知道会有交换机接收并转发该帧。帧到达交换机某个输出接口的速率可能暂时超过该接口的链路容量。为解决这个问题，交换机输出接口设有缓冲区，很像路由器输出接口为数据报设有缓冲区。下面更仔细地看交换机如何工作。

### 转发与过滤

**过滤**（filtering）是交换机确定一个帧应当被转发到某个接口还是应当被丢弃的功能。**转发**（forwarding）是交换机确定一个帧应被导向哪些接口、然后把帧移到那些接口的功能。交换机的过滤与转发通过**交换机表**完成。交换机表包含局域网上**部分**（而不一定是全部）主机和路由器的表项。交换机表中的一个表项包含：(1) 一个 MAC 地址；(2) 通向该 MAC 地址的交换机接口；(3) 该表项被放入表中的时间。图 6.15 中最上方那台交换机的交换机表例子如图 6.22 所示。这段关于帧转发的描述听起来也许类似于第 4 章关于数据报转发的讨论。确实，在 4.4 节关于广义转发的讨论中我们学到，许多现代分组交换机可以配置为基于二层目的 MAC 地址转发（即作为二层交换机工作），或基于三层 IP 目的地址转发（即作为三层路由器工作）。不过我们仍要强调一个重要区别：交换机基于 MAC 地址而非 IP 地址转发分组。我们还会看到，传统（即非 SDN 语境下的）交换机表的构建方式与路由器转发表**非常**不同。

<Figure src="ch06/fig6-22.webp" caption="图 6.22　图 6.15 中最上方交换机的交换机表的一部分" />

要理解交换机过滤与转发如何工作，假设一个目的地址为 `DD-DD-DD-DD-DD-DD` 的帧从接口 $x$ 到达交换机。交换机用 MAC 地址 `DD-DD-DD-DD-DD-DD` 索引其表。有三种可能的情况：

- 表中**没有** `DD-DD-DD-DD-DD-DD` 的表项。这时交换机把该帧的拷贝转发到除接口 $x$ 之外所有接口之前的输出缓冲区。换句话说，若目的地址没有表项，交换机就**广播**该帧。
- 表中有表项，把 `DD-DD-DD-DD-DD-DD` 与接口 $x$ 关联。这时该帧来自包含适配器 `DD-DD-DD-DD-DD-DD` 的那段局域网。既然没有必要把帧转发到任何其他接口，交换机就执行**过滤**功能，丢弃该帧。
- 表中有表项，把 `DD-DD-DD-DD-DD-DD` 与接口 $y \ne x$ 关联。这时该帧需要被转发到连接在接口 $y$ 上的那段局域网。交换机执行**转发**功能，把帧放入接口 $y$ 之前的输出缓冲区。

用图 6.15 中最上方那台交换机及其图 6.22 的交换机表走一遍这些规则。假设一个目的地址为 `62-FE-F7-11-89-A3` 的帧从接口 1 到达交换机。交换机查表，看到该目的地就在接口 1 所连的那段局域网（即电气工程系）上。这意味着该帧早已在包含目的地的这段局域网上广播过了，因此交换机**过滤**（即丢弃）该帧。现在假设一个目的地址相同的帧从接口 2 到达。交换机再次查表，看到该目的地在接口 1 的方向上，于是把帧转发到接口 1 之前的输出缓冲区。从这个例子应当清楚：只要交换机表完整且准确，交换机就会朝着目的地转发帧而无需任何广播。

在这个意义上，交换机比集线器"更聪明"。但这张交换机表最初是如何配置的？有链路层版本的网络层路由协议吗？还是必须由一位忙得不可开交的管理员手工配置交换机表？

### 自学习

交换机有一个美妙的性质（对已经忙不过来的网络管理员尤其如此）：它的表是自动、动态、自主地建立的——不需要网络管理员或配置协议的任何干预。换句话说，交换机是**自学习**（self-learning）的。这一能力这样实现：

1. 交换机表初始为空。
1. 对每个接口上收到的每个入帧，交换机在表中存入 (1) 该帧源地址字段中的 MAC 地址，(2) 帧到达的那个接口，(3) 当前时间。这样，交换机就在表中记录了发送方所驻留的那段局域网。如果局域网中每台主机最终都发送过帧，那么每台主机最终都会被记录到表中。
1. 若在某段时间（**老化时间**，aging time）之后没有收到以某个地址为源地址的帧，交换机就把该地址从表中删除。这样，如果一台 PC 被另一台 PC（带不同适配器）替换，原 PC 的 MAC 地址最终会从交换机表中清除。

用图 6.15 中最上方那台交换机及其图 6.22 的交换机表走一遍自学习性质。假设 9:39 有一个源地址为 `01-12-23-34-45-56` 的帧从接口 2 到达，并假设该地址不在交换机表中；于是交换机向表中加入一个新表项，如图 6.23 所示。

继续这个例子，假设该交换机的老化时间是 60 分钟，而 9:32 到 10:32 之间没有以 `62-FE-F7-11-89-A3` 为源地址的帧到达交换机。那么在 10:32，交换机就把该地址从表中删除。

<Figure src="ch06/fig6-23.webp" caption="图 6.23　交换机学习地址为 01-12-23-34-45-56 的适配器的位置" />

交换机是**即插即用**设备，因为它们不需要网络管理员或用户的任何干预。想安装交换机的网络管理员只需把各段局域网连到交换机接口上，不必在安装时或在某台主机从某段局域网移除时配置交换机表。交换机还是**全双工**的，即任何交换机接口都可以同时发送和接收。

### 链路层交换的性质

描述了链路层交换机的基本运行之后，来考虑它们的特性与性质。可以识别出用交换机（而不是总线或基于集线器的星形拓扑这类广播链路）的若干优点：

- **消除冲突**。在由交换机（且不含集线器）构成的局域网中，没有因冲突而浪费的带宽！交换机缓存帧，任何时候都不会在一段链路上发送一个以上的帧。与路由器一样，交换机的最大总吞吐量是所有交换机接口速率之和。因此，交换机相对广播链路局域网带来显著的性能提升。
- **异构链路**。由于交换机把一条链路与另一条链路隔离开，局域网中不同链路可以运行在不同速率上、使用不同介质。例如，图 6.15 中最上方那台交换机可能有三条 1 Gbit/s 的 1000BASE-T 铜缆链路、两条 100 Mbit/s 的 100BASE-FX 光纤链路和一条 100BASE-T 铜缆链路。因此，交换机非常适合把旧设备与新设备混用。
- **管理**。除了提供更强的安全性（见"安全聚焦"专栏），交换机还简化了网络管理。例如，若某个适配器发生故障并不断发送以太网帧（称为**喋喋不休的适配器**，jabbering adapter），交换机可以检测到该问题并在内部断开这个故障适配器。有了这个特性，网络管理员不必半夜起床开车回单位去排除故障。同样，电缆被切断只会断开使用该电缆连接到交换机的那台主机。在同轴电缆时代，许多网络管理员花数小时"沿线巡查"（更准确地说，"在地板上爬行"）以找出导致整个网络瘫痪的电缆断点。交换机还收集带宽使用、冲突率与流量类型的统计信息，并把这些信息提供给网络管理员；这些信息可用于调试与纠错，以及规划局域网未来的演进。研究者正在原型部署中探索为以太网局域网增加更多管理功能 [Casado 2007; Koponen 2011]。

<AsideCard title="安全聚焦 · 嗅探交换式局域网：交换机投毒">

当一台主机连接到交换机时，它通常只收到发给它的帧。例如考虑图 6.17 中的交换式局域网：当主机 A 向主机 B 发送帧、且交换机表中有主机 B 的表项时，交换机只会把该帧转发给主机 B。如果主机 C 恰好在运行嗅探器，主机 C 就无法嗅探这个 A 到 B 的帧。因此在交换式局域网环境中（与 802.11 局域网或基于集线器的以太网局域网这类广播链路环境不同），攻击者更难嗅探帧。不过，由于交换机会广播目的地址不在交换机表中的帧，C 处的嗅探器仍能嗅探到一些并非发给 C 的帧；此外嗅探器还能嗅探所有目的地址为广播地址 `FF-FF-FF-FF-FF-FF` 的以太网广播帧。一种针对交换机的著名攻击叫**交换机投毒**（switch poisoning）：向交换机发送大量携带许多伪造源 MAC 地址的分组，从而用伪造表项填满交换机表，使合法主机的 MAC 地址无处可存。这会导致交换机广播大多数帧，随后被嗅探器捕获 [Skoudis 2006]。由于这种攻击即使对老练的攻击者也相当复杂，交换机受嗅探的危害显著小于集线器和无线局域网。

</AsideCard>

### 交换机与路由器

如第 4 章所学，路由器是使用网络层地址转发分组的存储转发分组交换机。交换机虽然也是存储转发分组交换机，但与路由器有本质区别：它使用 MAC 地址转发分组。路由器是三层分组交换机，交换机是二层分组交换机。不过回忆 4.4 节学过，使用"匹配加动作"操作的现代交换机既能基于帧的目的 MAC 地址转发二层帧，也能基于数据报的目的 IP 地址转发三层数据报。确实，我们看到使用 OpenFlow 标准的交换机可以基于 11 个不同的帧、数据报与运输层首部字段中的任意一个执行广义分组转发。

尽管交换机与路由器有本质区别，网络管理员在安装互联设备时常常必须在两者之间选择。例如对图 6.15 的网络，网络管理员完全可以用一台路由器（而不是交换机）来连接各系局域网、服务器和因特网网关路由器。确实，路由器可以在不产生冲突的情况下实现系间通信。既然交换机和路由器都是互联设备的候选，两种途径各有什么优缺点？

先看交换机的优缺点。如上所述，交换机是即插即用的，这一性质深受全世界忙不过来的网络管理员喜爱。交换机的过滤与转发速率也可以相当高——如图 6.24 所示，交换机只需处理到第 2 层的帧，而路由器必须处理到第 3 层的数据报。另一方面，为防止广播帧循环，交换式网络的活动拓扑被限制为一棵**生成树**（spanning tree）。此外，大型交换式网络需要在主机和路由器中维护大型 ARP 表，并会产生大量 ARP 流量与处理开销。再者，交换机易受**广播风暴**（broadcast storm）影响——若某台主机失控、发送无休止的以太网广播帧流，交换机将转发所有这些帧，导致整个网络崩溃。

<Figure src="ch06/fig6-24.webp" caption="图 6.24　交换机、路由器与主机中的分组处理" />

再看路由器的优缺点。由于网络编址通常是层次的（而不像 MAC 编址那样扁平），即使网络存在冗余路径，分组通常也不会在路由器之间循环。（当然，路由器表配置错误时分组可能循环；但如第 4 章所学，IP 使用一个特殊的数据报首部字段来限制循环。）因此分组不受生成树限制，可以使用源与目的之间的最佳路径。正因为路由器没有生成树限制，才使因特网得以建立在丰富拓扑之上，例如欧洲与北美之间存在多条活动链路。路由器的另一个特性是它们对二层广播风暴提供防火墙式保护。不过路由器最显著的缺点也许是它们不是即插即用的——路由器以及连接其上的主机都需要配置 IP 地址。此外，路由器每分组的处理时间通常比交换机更长，因为它们必须处理到第 3 层字段。最后，"router" 这个词有两种读法（"rootor" 或 "rowter"），人们为正确读音浪费了大量时间争论 [Perlman 1999]。

既然交换机和路由器各有优缺点（汇总于表 6.1），那么一个机构网络（例如大学校园网或公司园区网）何时该用交换机、何时该用路由器？通常，由几百台主机组成的小型网络只有几段局域网。对这些小网络来说交换机就够了，因为它们能本地化流量、提高总吞吐量，而且不需要配置任何 IP 地址。但由数千台主机组成的大型网络通常会在网内（除交换机之外）使用路由器：路由器提供更健壮的流量隔离、控制广播风暴，并在网络主机之间使用更"智能"的路由。

|  | **集线器** | **路由器** | **交换机** |
| --- | --- | --- | --- |
| 流量隔离 | 否 | 是 | 是 |
| 即插即用 | 是 | 否 | 是 |
| 最优路由 | 否 | 是 | 否 |

## 6.4.4　虚拟局域网（VLAN）

前面讨论图 6.15 时我们指出，现代机构局域网常按层次配置：每个工作组（系）有自己的交换式局域网，再通过交换机层次连接到其他组的交换式局域网。这种配置在理想世界里运行良好，但现实世界往往远非理想。图 6.15 的配置可以识别出三个缺点：

- **缺乏流量隔离**。虽然这种层次结构把组内流量本地化到一台交换机内，但广播流量（例如携带 ARP 与 DHCP 报文的帧，或目的地尚未被自学习交换机学到的帧）仍必须穿越整个机构网络。限制这类广播流量的范围会改善局域网性能。也许更重要的是，出于安全／隐私考虑也可能希望限制局域网广播流量。例如，若一个组包含公司高管团队，另一个组包含心怀不满、正在运行 Wireshark 嗅探器的员工，网络管理员很可能希望高管的流量根本不要到达员工主机。这类隔离可以通过把图 6.15 的中心交换机换成路由器来提供；很快会看到，这种隔离也可以用交换式（二层）方案实现。
- **交换机利用效率低**。如果机构不是三个组而是十个组，就需要十台一级交换机。如果每个组都很小（比如不到 10 人），那么一台 96 端口的交换机大概就足以容纳所有人，但这台单一交换机无法提供流量隔离。
- **用户管理**。如果某员工在组之间调动，就必须改变物理布线，把他接到图 6.15 中另一台交换机上。属于两个组的员工会让问题更难办。

幸运的是，这些困难都可以由支持**虚拟局域网**（VLAN）的交换机来处理。顾名思义，支持 VLAN 的交换机允许在单一物理局域网基础设施上定义多个虚拟局域网。一个 VLAN 内的主机彼此通信，就好像它们（且只有它们）连接在这台交换机上一样。在**基于端口的 VLAN** 中，交换机的端口（接口）由网络管理员划分为若干组，每组构成一个 VLAN，每个 VLAN 中的端口形成一个**广播域**（即来自一个端口的广播流量只能到达该组内的其他端口）。图 6.25 展示了一台有 16 个端口的单一交换机：端口 2 到 8 属于 EE VLAN，端口 9 到 15 属于 CS VLAN（端口 1 与 16 未分配）。这个 VLAN 解决了上面提到的所有困难——EE 与 CS 的 VLAN 帧彼此隔离，图 6.15 中的两台交换机被一台单一交换机取代，而如果端口 8 上的用户转到计算机科学系，网络运营者只需重新配置 VLAN 软件，使端口 8 现在关联到 CS VLAN。很容易想象 VLAN 交换机是如何配置和运行的——网络管理员用交换机管理软件声明某个端口属于某个给定 VLAN（未声明的端口属于默认 VLAN），交换机内部维护一张端口到 VLAN 映射的表，交换机硬件只在属于同一 VLAN 的端口之间交付帧。

<Figure src="ch06/fig6-25.webp" caption="图 6.25　配置了两个 VLAN 的单台交换机" />

但把两个 VLAN 完全隔离开，又引入了一个新困难！EE 系的流量如何送到 CS 系？一种处理方式是把一个 VLAN 交换机端口（例如图 6.25 中的端口 1）连到一台外部路由器，并把这个端口配置为同时属于 EE 与 CS 两个 VLAN。这样，尽管 EE 与 CS 系共享同一台物理交换机，逻辑配置看起来就像两个系各有一台交换机、通过一台路由器相连。从 EE 到 CS 的 IP 数据报会先经 EE VLAN 到达路由器，再由路由器经 CS VLAN 转发回 CS 主机。幸运的是，交换机厂商把 VLAN 交换机与路由器做在同一个设备里，使这种配置对网络管理员来说很容易，无需单独的外部路由器。章末有一道习题更详细地探讨这个场景。

再回到图 6.15，现在假设不是单独设一个计算机工程系，而是有些 EE 和 CS 的教师被安排到另一座楼里，他们（当然！）需要网络接入，而且（当然！）希望属于自己系的 VLAN。图 6.26 展示了第二台 8 端口交换机，其端口已按需定义为属于 EE 或 CS VLAN。但这两台交换机应当如何互联？一个简单的办法是在每台交换机上定义一个属于 CS VLAN 的端口（EE VLAN 同理），并把这些端口互连，如图 6.26(a) 所示。然而这种方案不可扩展：$N$ 个 VLAN 就需要在每台交换机上占用 $N$ 个端口，仅仅用于互联这两台交换机。

一种更具可扩展性的 VLAN 交换机互联方式称为 **VLAN 干线**（VLAN trunking）。在图 6.26(b) 所示的干线方式中，每台交换机上的一个特殊端口（左交换机端口 16、右交换机端口 1）被配置为**干线端口**（trunk port），用于互联两台 VLAN 交换机。干线端口属于所有 VLAN，发往任何 VLAN 的帧都经干线链路转发到另一台交换机。但这就引出了另一个问题：交换机如何知道到达干线端口的帧属于哪个 VLAN？IEEE 为跨越 VLAN 干线的帧定义了一种扩展以太网帧格式 **802.1Q**。如图 6.27 所示，802.1Q 帧由标准以太网帧加上插入首部的 4 字节 **VLAN 标签**构成，该标签携带帧所属 VLAN 的标识。VLAN 标签由 VLAN 干线发送侧的交换机加入帧中，由干线接收侧的交换机解析并移除。VLAN 标签本身由 2 字节的**标签协议标识符**（TPID）字段（固定十六进制值 `81-00`）、2 字节的**标签控制信息**字段（其中含 12 比特的 VLAN 标识符字段）以及 3 比特的**优先级**字段（用意类似于 IP 数据报的 TOS 字段）组成。

<Figure src="ch06/fig6-26.webp" caption="图 6.26　用两个 VLAN 连接两台 VLAN 交换机：(a) 两根电缆；(b) 干线方式" />

<Figure src="ch06/fig6-27.webp" caption="图 6.27　原始以太网帧（上）与带 802.1Q 标签的以太网 VLAN 帧（下）" />

以上讨论只简要涉及 VLAN，并且聚焦于基于端口的 VLAN。还应提到，VLAN 还可以用其他几种方式定义。在**基于 MAC 的 VLAN** 中，网络管理员规定每个 VLAN 所属的 MAC 地址集合；每当设备接入某个端口，该端口就根据设备的 MAC 地址被接入相应的 VLAN。VLAN 也可以基于网络层协议（例如 IPv4、IPv6 或 AppleTalk）以及其他准则来定义，详见 802.1Q 标准 [IEEE 802.1q 2005]。VLAN 还可以跨 IP 路由器扩展，从而把若干"局域网孤岛"连接起来，形成可覆盖全球的单一 VLAN [Yu 2011]。确实，我们将在 6.5.2 节讨论的 VXLAN（虚拟可扩展局域网）技术，允许创建覆盖比 VLAN 更大地理范围的虚拟局域网。

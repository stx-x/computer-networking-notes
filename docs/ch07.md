过去 15 年，无线与移动网络的部署和使用经历了惊人的增长。2008 年，固定（有线）宽带因特网用户数大约与通过无线技术接入的宽带用户数相当；此后两者都在增长，而如今（2025 年）联网的无线用户已是有线用户的**五倍**。据估计，2025 年约 60% 的网站流量是流向移动设备而非固定设备的 [Statista Mobile 2025]。无线接入的诸多优势人人可见——通过一个高度便携的轻量设备，随时随地、无拘无束地接入全球因特网。越来越多的设备正以无线方式连入因特网：游戏主机、家用电器、安防系统、手表、眼镜、汽车、可穿戴衣物等等。确实，有人提出，一场由无线网络与融合物理世界和数字世界的信息物理系统所使能的、极其重要的**第四次工业革命** [Schwab 2016] 正在进行之中。

无线与移动设备联网所带来的挑战，与传统有线计算机网络如此不同，以至于专门用一章（即本章）来研究无线与移动网络是恰当的。本章既讲无线与移动网络的原理，也讲其实践。7.1 节先设定"全局图景"。

作为本书读者，你已知道我们是"自顶向下"方法的忠实拥趸。但无线网络太多方面都源于无线物理信道复杂、时变、容量受限且共享的本性，因此要领会无线网络几乎任何其他方面，都需要尽早掌握无线电信道。所以，我们对无线与移动网络的深入研究将从**自底向上**开始：7.2 节先学习无线电信道的性质；7.3 节聚焦第一跳无线接入网，学习共享无线信道、网络发现与设备附着、帧传输调度、节能等技术；7.4 节学习无线网络"核心"，它提供身份与移动性管理等控制平面服务，以及通往更大因特网的数据平面连通性。在 7.2–7.4 节中，我们都先识别并研究超越任何特定网络技术的基本原理，然后在 WiFi 与蜂窝网络的语境中展示这些原理的实践。我们的目标是把"为什么"和"怎么做"从"做什么"中分离出来。有许多书和文档描述某个特定无线网络体系结构"做什么"——确实有（相当枯燥的）标准，其中许多长达数千页，极为详尽地描述了"做什么"。7.2–7.4 节因此旨在提供理解"为什么"的基础——为什么一个体系结构要这样组织，为什么一个协议要用某种特定途径完成某项任务。这种更深的理解也将远远超越任何具体无线技术的生命周期，帮助你的无线与移动网络知识"面向未来"。

设备移动性是无线网络如此独特的特征，我们将用整整一节（7.5 节）讨论这个重要主题。本章主要聚焦 5G 与 WiFi 网络，但还有其他广泛部署的无线网络体系结构；7.6 节因此简要介绍蓝牙、卫星与 IoT 无线网络。7.7 节总结本章。无线网络中的安全问题留到下一章讨论。

## 7.1　导论

图 7.1 给出了我们讨论无线与移动网络的场景。我们先让讨论足够一般，以覆盖范围广泛的网络，包括 5G 蜂窝网络、WiFi 局域网（WLAN），以及包括蓝牙与 IoT 网络在内的自组织网络。

<Figure src="ch07/fig7-01.webp" caption="图 7.1　无线网络的组成要素" />

可以识别出无线网络中以下关键的共同要素：

- **无线接入网**（wireless access network）。在最高层面，一个无线网络有一个或多个无线接入网。无线接入网位于整个网络最外侧的"边缘"，通过无线电信道把设备连入更大的网络。接入网可以看作第 6 章研究过的一类局域网：地理范围有限、由单一服务提供商控制、主要提供链路层服务。在蜂窝网络中，无线接入网称为**无线接入网**（Radio Access Network，RAN）；在 WiFi 网络中，无线接入网常被称为**无线局域网**（WLAN）。
- **无线核心网**（wireless core network）。无线核心网由服务器、存储、路由器以及（通常有线的）链路组成，位于提供商接入网中的设备与外部网络之间。核心网可以地理上分散——例如一部分与接入网中的基础设施同址，另一部分位于远处数据中心。核心网实现较高层的控制平面与管理平面服务（例如用户与设备身份、移动性、接入安全管理），以及把数据报从接入网中的设备转发到更大因特网（反之亦然）的数据平面服务。蜂窝网络有一个由蜂窝网络运营商运营的、定义良好的核心网；我们将在 7.4 节研究 4G/5G 核心网。与 4G/5G 不同，WiFi 没有对应的无线核心网；企业把 WLAN 所用的基础设施与其有线局域网所用的基础设施合而为一。在这个意义上，企业把 WiFi 只看作其企业网络中的又一种链路层技术。
- **无线设备**（wireless device）。无线设备可以是智能手机、平板电脑或笔记本电脑，也可以是传感器、家电等 IoT 设备。与有线网络一样，正是这些设备承载并运行应用。如图 7.1 所示，无线设备附着到无线接入网。要注意，无线设备**不一定**是移动的——这个主题我们将在 7.5 节回到。
- **基站**（base station）。基站可以说是无线网络中最重要、最独特的部件，因为它在有线网络中没有对应物。基站负责向与其关联的无线用户设备收发分组。也就是说，所有向因特网发送分组、以及从因特网接收分组的无线设备，都是经由基站完成的。一台基站通常负责多台关联的无线设备。当我们说某台无线设备与某台基站"关联"时，指的是：(1) 该设备处于该基站的无线通信距离之内；(2) 该设备与基站已执行某个协议，结果是基站充当该设备与更大因特网之间的分组中继。从基站向关联设备发送帧，常称为在**下行**（downstream/downlink）信道上进行；从关联设备向基站发送帧，则在**上行**（upstream/uplink）信道上进行。
- 在 5G 网络中，基站称为 **gNodeB**，缩写 **gNB**，在 5G 标准中意为"下一代节点 B"（Next Generation Node B）。在 4G 网络中，基站称为 **eNodeB**，即"演进的节点 B"（evolved Node B），缩写 **eNB**。这些也许是整个网络领域中最不直观、最不自解释、最令人费解的缩写！因此，为了始终偏好使用描述性语言而不是行话，我们干脆把 4G 与 5G 网络中的基站称为"基站"。不过如果你要钻研技术标准，请记住 "eNB" 与 "gNB" 分别是 3GPP 术语中 4G 与 5G 网络的"基站"。在 WiFi 网络中，基站称为**接入点**（Access Point，AP）。由于这个术语更具描述性且被普遍使用，我们也会偶尔把 WiFi 基站称为 AP。

与基站关联的设备，常被称为工作在**基础设施模式**（infrastructure mode），因为传统网络服务（例如地址分配、身份与接入权限、选路）由设备经基站所连接的网络基础设施提供。在**自组织网络**（ad hoc network）中，无线设备没有这样的基础设施可连；在没有这类基础设施的情况下，设备必须自行组织，并自行提供选路、地址分配、类 DNS 的名字翻译等服务。WiFi 网络既可以工作在基础设施模式，也可以工作在自组织模式，但本章通篇假设 WiFi 网络有基站，即工作在基础设施模式。我们将在 7.6 节研究的蓝牙网络就是纯自组织网络的一个例子。关于自组织网络的详细研究见 [Mohapatra 2004]。

当一台移动设备移出一台基站的范围、进入另一台基站的范围时，它会改变接入更大网络的附着点，即改变与之关联的基站——这个过程称为**切换**（handoff/handover）。这种移动性引出许多富有挑战的问题：如果无线设备可以移动，如何找到移动设备在网络中的当前位置，以便把数据转发给它？既然设备可能处于许多可能位置之一，编址如何进行？如果设备在一次 TCP 连接或语音／视频通话期间移动，数据报如何转发才能让连接不中断？我们将在 7.5 节回答这些以及许多其他与移动性有关的问题。

下面自底向上、从网络边缘开始，深入研究无线电信道。

## 7.2　无线网络中的物理层

你可能已经注意到，我们此前的网络学习大体上避开了物理层。一本书能覆盖的内容有限，而理解比特传输速率、误码率、传播时延这几个简单的物理层特性，已足以理解第 2 至第 6 章的内容。但在无线网络中并非如此！因此本节与下一节将深入无线网络物理层的细节。我们将更多采取计算机科学的视角而非传统电子工程的视角来看待无线信道，给出更直观的描述而不是更精确的数学描述。

### 7.2.1　无线信道的特性

在最基本的层面上，某处天线（发送方）中随时间变化的电流会产生电磁（无线电）波，电磁波在空间中传播，并在其他地方（们）的接收天线中产生电流。发送方通过改变（也就是"调制"）电磁波的特征，把信息编码进电磁信号。既然信息被编码在电磁信号中，理解电磁波的一些基本特征就很重要。

#### 无线电波：幅度、频率与相位

图 7.2 展示了电磁波的电场分量——这幅图你也许在基础物理课上见过。电磁波由以下量刻画：

- **幅度**（amplitude）：波在空间与时间中某一点的高度；
- **波长** $\lambda$：波中两个相邻波峰之间的距离；
- **周期时间**（cycle time）：两个相邻波峰之间的时间；
- **频率**：1 除以周期时间，以赫兹（Hz）计。例如 1 兆赫兹（MHz）的波每秒有 $10^{6}$ 个周期；
- **相位**（phase）：截至时刻 $t$ 已经走过的周期比例。如图 7.2 所示，相位从某个参考时刻起算，通常取波幅为零且正在上升的时刻。相位也常用角度单位表示，即从 0 到 360 度。因此若相位等于一个周期的 75%，对应相位角就是 270 度。

<Figure src="ch07/fig7-02.webp" caption="图 7.2　电磁波：幅度、波长与相位" />

电磁波有方向，并以接近光速（$3 \times 10^{8}$ m/s）传播。

#### 无线电传输：功率与带宽

从日常经验我们大致知道，无线电信号可以强或弱，可以清晰或充满静电（"噪声"）。下面把这些概念形式化。

**功率**（power）是发送方在单位时间内投入其所发电磁波的能量。可以非正式地把功率理解为信号的强度。功率以瓦特为单位，无线网络中通常用毫瓦（mW）。电子工程师有时喜欢用分贝毫瓦（"dBm"）来度量功率，即信号功率（以 mW 计）与 1 mW 之比的对数。但这里我们用更常见的线性度量 mW。

图 7.2 中理想化的电磁波只有一个频率，即全部辐射的电磁能量都集中在一个特定频率上。实践中，发送方的功率会散布在不止一个频率上。图 7.3(a) 所示的**功率谱密度**函数刻画了发送方信号中功率随频率的分布。功率谱密度函数通常围绕所谓的**载波频率**（carrier frequency）居中，图 7.3(a) 例子中的载波频率为 1 GHz。

有了功率谱密度的概念，我们就可以仔细定义无线信号**带宽**这一无线网络中的关键物理层概念。顾名思义，无线电信号的带宽是信号所占用频率范围的宽度（以 Hz 计）。图 7.3(b) 中的信号带宽为 22 MHz，功率均匀分布在 2.427 到 2.429 GHz 之间。7.3.2 节将看到，这个 22 MHz 宽的"信道"——即带宽 22 MHz 的无线信道——对应 WiFi 网络中的信道 6。

<Figure src="ch07/fig7-03.webp" caption="图 7.3　(a) 信号功率谱密度；(b) 信号带宽（理想化）" />

要特别注意，无线物理层中信号"带宽"的这个精确含义——无线电信号所占频带的宽度——与网络其他部分中"带宽"一词相当不正式地指链路比特传输速率或容量的用法非常不同。学生常常为此困惑，这完全可以理解。首先，无线电信号带宽以赫兹计，而链路的传输速率以比特每秒（bit/s）计。我们将看到，无线电信道的带宽（Hz）与比特经无线链路传输的速率（bit/s）是相关的：一般来说，带宽越大，比特传输速率越高。例如，20 MHz 宽的 802.11n WiFi 信道（7.3.2 节）支持最高 72.2 Mbit/s 的传输速率，而 40 MHz 宽的 802.11n WiFi 信道最高速率为 150 Mbit/s [Intel 2024]。但我们将看到，无线电信道带宽（Hz）与链路传输带宽（bit/s）之间的关系相当复杂。本章中我们会小心地只用"带宽"一词表示无线电信号所占频带的宽度。

从日常经验（例如听 AM、FM 或卫星广播）我们知道，无线电信号有时清晰，有时充满噪声。图 7.4 上部是图 7.2 中原始的"干净"信号，中部是在发送方与接收方之间引入的噪声信号，下部是接收到的信号。看看中部那个含噪的接收信号，你也许能体会到从含噪接收信号中提取原始发送信号的难度。噪声的来源很多：

- **干扰发送方**。某些射频频段被保留供"免许可"使用，意味着许多工业与消费设备可以在该频段发射无线电波，只受功率限制。2.4–2.5 GHz 频段就是其中之一：婴儿监视器、车库门开启器以及许多其他家用设备都可以在该频段发射信号。更重要的是，许多网络——例如 WiFi、蓝牙与 Zigbee（IEEE 802.15.4）网络——都使用免许可的 2.4–2.5 GHz 频段，而且是以互不协调的方式使用。当然，你自己的 WiFi 网络用这个频段没问题，但附近别人拥有的网络对你的网络来说就像噪声！俗话说，"一个人的网络传输就是另一个人的噪声"。
- **电磁辐射源**。电动机与微波炉（尤其是屏蔽较差的旧型号）会发射无线电波。
- **热噪声与电子噪声**。发送方或接收方处自然的温度变化以及电子器件的不完美，都会给信号增添噪声。

#### 无线电信道：噪声、信噪比（SNR）与容量

信号功率与噪声功率之比称为**信噪比**（SNR）。SNR 通常以分贝（dB）度量：

$$
\text{SNR (dB)} = 10 \log _{10}(\frac{\text{接收信号功率}}{\text{噪声功率}})
$$

注意 SNR 为 0 意味着信号与噪声的量相等。对 WiFi 网络，接收信号中可接受的最低 SNR 约为 20 dB [Meraki 2023]；对 LTE，可接受的最低值从 −5 到 18 dB 不等，取决于所用的调制技术（见 7.2.2 节）[Rohde and Schwarz 2013]。

有了功率、带宽与噪声的概念，就可以陈述通信理论中最重要的结果之一——**香农容量定理**。香农定理把通信信道容量 $C$——在该信道上无差错传输数据可能达到的最大速率（bit/s）——与信道带宽 $B$ 以及接收信号功率和噪声功率（都按线性度量，例如 mW）联系起来：

$$
C = B \log _{2}(1 + \frac{\text{接收信号功率}}{\text{噪声功率}})
$$

要注意，香农容量定理给出的是信道容量的**上界**。它说的是：无论把数据编码、调制进无线信号的手法多么巧妙，在给定信道带宽与 SNR 下，接收到的数据量都将小于或等于 $C$。香农容量定理还有几个重要的实践推论：

- 在给定 SNR 下，最大信道容量随信道带宽**线性**增长。更宽的信道带宽意味着每秒可能传输更多比特。
- 在 SNR 很高时，再费力提高 SNR 几乎没有额外收益，因为最大容量只随 SNR 对数增长，即次线性增长。

#### 无线电信道的特性：路径损耗、多径与隐藏终端

无线电信号从发送方传播到接收方时会发生重要的变化。最根本的是，波在传播中会损失强度。无线电信号在传播中的这种减弱称为**路径损耗**（path loss）或**衰减**（attenuation）。在从发送方到接收方存在无遮挡视距路径的情况下，发送功率与接收功率之比按**平方反比定律**下降：

$$
P_{\text{received}} \propto \frac{P_{\text{transmitted}}}{(f d)^{2}}
$$

其中 $P_{\text{transmitted}}$ 与 $P_{\text{received}}$ 分别是发送功率与接收功率，$f$ 是信号频率，$d$ 是发送方与接收方之间的距离。

这种二次路径损耗的直觉如图 7.5 所示。由于球面面积随中心到表面距离的平方增长，距发送方 $d$ 处单位面积穿过的能量，与距发送方 $2 d$ 处四倍面积穿过的能量相同，与 $3 d$ 处九倍面积穿过的能量也相同。路径损耗指数 2 是所谓空气中的**自由空间路径损耗**。室外城市环境中路径损耗指数常约为 3，建筑物内常为 4 或更高——这使路径损耗成为更令人担忧的问题。

<Figure src="ch07/fig7-05.webp" caption="图 7.5　自由空间路径损耗按发送方与接收方距离的平方下降" />

距离与频率上的二次路径损耗对无线电通信有重要影响：低频（如 kHz）无线电往往用于远距离、低数据率的无线电应用（如无线电导航），而高频（如 GHz）往往用于距离相对较短的陆地应用，包括蜂窝与 WiFi 网络。

接收功率随距离指数下降，引出了**隐藏终端问题**（hidden terminal problem）——这一现象将驱动无线链路层多路访问协议（如 WiFi 的 CSMA/CA，7.3.1 节）的设计。图 7.6(a) 展示了节点 A 与 B 能"听到"彼此的情形，即它们信号的接收功率高于检测门限；类似地，节点 B 与 C 也能听到彼此。然而由于路径损耗，节点 A 与 C 无法听到彼此，因为它们信号的接收功率已降到检测门限以下。于是节点 A 与 C 对彼此是"隐藏"的。你已能体会隐藏终端会如何影响无线 CSMA 协议——如果 A 与 C 都想向 B 发送，它们可能侦听信道、听不到对方在发送（因为路径损耗），而它们发给 B 的传输会在 B 处相互干扰。图 7.6(b) 展示了另一种隐藏终端情形：A 与 B 的信号在物理上被彼此阻挡，但同样地，它们的传输在 B 处相互干扰。显然，在无线信道上通信比在有线信道上通信复杂得多！

<Figure src="ch07/fig7-06.webp" caption="图 7.6　隐藏终端：A 与 B 能互相听到，B 与 C 能互相听到，但 A 与 C 听不到彼此" />

平方反比定律还说明，接收功率不仅在距离上、也在频率上指数下降。随频率的这种指数下降在无线网络中同样有非常重要的后果。例如，它意味着把一个固定带宽的信道从 5 GHz 搬到 50 GHz，在 50 GHz 处收到的功率会低 100 倍！因此高频信道往往覆盖距离更短，而低频信道往往用于覆盖更长距离。

图 7.7 说明了无线通信的另一个重要特性：**多径信号**（multipath signal）。图中发送方发出的部分无线电信号沿直接视距路径到达接收方，在图 7.7(a) 中概念性地表示为一个绿色的接收脉冲。然而发送的信号也会被环境中的物体（如建筑物）反射，由于反射脉冲从发送方到接收方走了更长的距离，它们稍晚一些到达接收方。这些多径接收信号在图 7.7(b) 中表示为红色与紫色脉冲。由于多径，发送方在某一瞬间发出的信号，在接收方会被摊开在一段时间上。显然，多径会使接收方重建原始发送信号的工作变得复杂。

<Figure src="ch07/fig7-07.webp" caption="图 7.7　(a) 视距（LoS）信号；(b) 视距信号与反射信号的接收" />

多径还对发送方改变其发送信号的最大速率构成约束，从而约束发送方传输比特的速率。图 7.8 展示了发送方的两个发送脉冲。发送方必须把各次信号／脉冲发送间隔得足够远，使得视距信号（图 7.8 中的绿色脉冲）及其所有多径反射（红色与紫色脉冲）都在下一个视距信号／脉冲被接收之前到达接收方。若不如此，两个脉冲及其反射就会在接收方处混在一起。这个由接收方决定的、发送方两次信号变化之间所需的最小时间量，称为接收方的**相干时间**（coherence time）。

#### 天线：MIMO

今天大多数无线蜂窝与 WiFi 基站及设备中部署的天线，完全不像你祖父母（甚至父母）时代的天线！从 2000 年代初开始，无线网络从发送方一根天线、接收方一根天线的系统，转向在发送方与接收方都使用多根天线的**多输入多输出**（MIMO）天线。我们将会看到，这些创新的 MIMO 技术使无线网络能显著提高链路吞吐量（成功接收的比特每秒数）。

接收方有多根天线的一个直接好处应当很明显——$N$ 根接收天线意味着（粗略地说）接收到的总信号功率大 $N$ 倍。但 MIMO 系统的意义远不止于此！

MIMO 通过以下两种根本不同的方式利用收发天线之间的多条路径，从而获得优于单天线系统的增益：

- **MIMO 空间分集**（spatial diversity）。MIMO 空间分集技术从发送方到接收方发送**冗余**的信息流，利用的是：在一根或多根发送天线到一根或多根接收天线之间不同物理路径上传播的无线电信号会经历不同的损伤（例如多径效应）。这项技术对抵抗**多径衰落**的不利影响至关重要——来自建筑物、树木与其他障碍物的信号反射会造成信号强度的起伏。通过不同路径接收信号的多个拷贝，MIMO 系统可以把这些信号以最大化信号强度、最小化差错率的方式合并起来。即使天线之间只相隔几厘米（例如在手机上），不同路径上收到的信号也可能经历相当不同的信道条件。图 7.9(a) 展示了单根发送天线与两根接收天线的例子。空间分集也可以用多根发送天线来获得，但这里聚焦于最简单的情形；更一般情形的可读性介绍见 [Halperin 2010]。
- 假设发送方发出原始信号 $x$。上方天线收到的信号为 $y_{1} = H_{1, 1}(x)$，其中 $H_{1, 1}()$ 函数表示发送信号在那根发送天线与上方接收天线之间被如何改变（例如幅度与相位）。类似地，下方天线收到不同的信号 $y_{2} = H_{1, 2}(x)$。但接收方该拿这两个不同的接收信号怎么办？这正是物理层信号处理技术的用武之地。简单地把两个信号"相加"本质上只会重现单天线多径的效果。也可以选择 $y_{i}$ 中 SNR 最大的那个；或者先把接收信号的相位对齐（传输可能造成相移），再相干地相加，也许按各自 SNR 对两个信号的贡献加权。这些只是从多个接收信号中恢复原始信号的众多技术中的两种 [Goldsmith 2005; Tze 2005]。
- **MIMO 空间复用**（spatial multiplexing）。在 MIMO 空间复用中，多个不同的信息流沿发送天线到接收天线的不同路径并行发送。图 7.9(b) 给出一个例子：两个不同的信息流 $x_{1}$ 与 $x_{2}$ 由两根不同的发送天线发出。在接收方，每根天线都收到含有两个信息流的信号，每个分量流都经历了不同的损伤。例如，上方接收天线收到的信号表示为 $y_{1} = H_{1, 1}(x_{1}) + H_{2, 1}(x_{2})$，其中求和表示信号在空气中叠加，原始信号 $x_{1}$ 在去往上方接收天线的路上按 $H_{1, 1}()$ 变换，$x_{2}$ 则按 $H_{2, 1}()$ 变换。下方天线收到的信号 $y_{2}$ 有类似解释。
- 接收方的任务是：给定接收信号 $y_{1}$、$y_{2}$，确定原始信号 $x_{1}$、$x_{2}$。当然，$H_{1, 1}()$ 与 $H_{2, 1}()$ 在实践中是未知的，但只要发送方与接收方配合就可以估计出来。这一点，加上图 7.9(b) 中有两个方程（一个关于 $y_{1}$、一个关于 $y_{2}$）而只有两个未知量（$x_{1}$ 与 $x_{2}$）这一观察，暗示了接收方可用来计算原始信号的信号处理算法类型。实践中，发送方还可以做编码与调制，帮助接收方改进对 $x_{1}$、$x_{2}$ 的估计。

<Figure src="ch07/fig7-09.webp" caption="图 7.9　简单 MIMO：(a) 空间分集；(b) 空间复用" />

MIMO 信号处理技术的理论与实践远超本书范围。我们这里的目标只是介绍空间分集与空间复用，并让你体会作为 MIMO 系统基础的信号处理类型。更深入的论述请参阅 [Goldsmith 2005; Tze 2005; Halperin 2010]。

#### 波束成形与定向天线

**波束成形**（beamforming）是指把发送信号导向某个特定用户或区域，而不是向所有方向辐射。使用定向天线的波束成形能增强接收方的信号强度、减少干扰，并改善无线通信的整体性能。

波束成形通常用天线阵列实现。通过调整每根发送天线上信号的相位与幅度，系统可以在期望方向上形成相长干涉、在其他方向上形成相消干涉，从而形成一束无线电波"波束"。波束成形可以是动态的，系统根据用户位置不断调整波束方向，从而即使用户移动也能保证最佳信号质量。波束成形有以下好处：

1. **增强信号强度**：把信号聚焦在特定方向上，波束成形提高了目标用户收到的信号强度，带来更高的数据率与更可靠的连接。
1. **减少干扰**：波束成形通过尽量减少向非期望方向的信号泄漏，减少对其他用户的干扰，从而在设备密集的环境中带来更好的性能。
1. **改善覆盖**：定向波束可以扩展无线网络的覆盖范围，在覆盖区边缘提供更好的连通性。
1. **提升容量**：通过更高效地使用可用频谱，波束成形可以提高网络总体容量，同时支持更多用户。

波束成形广泛用于 WiFi、现代蜂窝网络与卫星通信。

#### 多用户 MIMO（MU-MIMO）

上面关于 MIMO 的讨论，迄今隐含地聚焦于**单用户 MIMO**（SU-MIMO）——用发送方和／或接收方的多根天线向单个设备发送，如图 7.10(a) 所示。实践中，这类系统的天线数量不多，例如 WiFi 基站中 2 到 4 根天线。

在蜂窝网络中，MIMO 技术还被用来从一个发送方同时向许多接收方发送，这称为**多用户 MIMO**（MU-MIMO），有时也称为**大规模 MIMO**（Massive MIMO）。MU-MIMO 用不同的天线子集同时向多个不同设备发送，如图 7.10(b) 所示。每个天线子集又利用 MIMO 空间分集，向一个设备发送携带相同信息的多个信号。此外，MU-MIMO 常常采用前面描述并示于图 7.10(b) 的波束成形。一个现代 5G 基站的 MU-MIMO 天线可以包含多达 64 个波束成形发射阵元，以及数量相等或相近的接收天线阵元 [Ericsson 2024; Samsung 2021]。

#### 无线电频谱

**无线电频谱**（radio spectrum）是电磁频谱中 3 Hz 到 3 THz 的范围。无线电频谱被视为国家资产，因而其使用由各国监管，由联合国机构**国际电信联盟**（ITU）提供一定的协调（但不做监管）。通常，一个国家为特定用途分配无线电频谱中的特定频率范围。一张广为流传的海报图（至少在无线电极客中"流行"）[NTIA 2016] 展示了美国无线电频谱的分配，用途包括海事与航空无线电导航、地面 AM/FM 与电视广播、卫星广播、无线电定位（如 GPS）、业余无线电、射电天文、气象雷达、消费无线设备，当然还有 7.3 至 7.6 节所涵盖的无线网络。

频谱使用类型有两大类：

- **许可频谱**（licensed spectrum）。顾名思义，在许可频谱频段上运行发射机必须获得政府颁发的许可证；这包括商业蜂窝网络提供商使用的频段（见表 7.1）。在许多国家，频谱通过**频谱拍卖**分配给商业蜂窝网络提供商，在印度、英国与美国已产生数百亿到数千亿美元的许可费。商业购买昂贵频谱权利（以及运营蜂窝网络所需的铁塔与土地准入成本）的一个后果是：蜂窝商业服务（不同于 WiFi 提供商）必须为其服务定价，以覆盖所有这些成本并盈利。由于许可频谱的稀缺与昂贵，人们正在开发新的频谱共享方法，允许非在册设备（即与频谱持证方无关的设备）在特定规则与条件下使用在册方的许可频谱。例如在美国，3.5 GHz 的 CBRS 频段（见表 7.1）允许蜂窝基站（非在册方）在没有海军雷达（在册方）占用频谱时发射。人们正在探索许多途径，包括动态感知并使用当前未被占用频谱的**认知无线电**方案。近期综述见 [Parvini 2023]。
- **免许可频谱**（unlicensed spectrum）。部分频谱也可供免许可使用。这意味着机构和个人可以购买并使用在免许可频谱中工作的设备（例如车库门开启器、婴儿监视器、微波炉等等）与无线网络（尤其是 WiFi 网络），而无需取得许可证。但这些设备必须遵守使用规则，例如限制其发射功率水平。此外，由于许多互不协调的设备都可以在免许可频谱中发射，它们会相互干扰。本章通篇会看到，在免许可频谱中工作的无线网络采取了许多不同途径来避免、缓解并应对这种干扰。

### 7.2.2　编码与调制：从比特到符号再到波形

本小节沿协议栈"向上"走（但仍停留在物理层内），讨论无线发送方如何把要发送的比特分组成"符号"，符号再被编码为波形，然后经无线信道发送；在接收方，符号再从接收波形中提取出来并翻译回比特。

图 7.11 展示了物理层发送与接收的主要步骤。在发送方，数据比特由上层链路层交给物理层；这些比特随后被处理成电磁波形，经信道传播到接收方，在那里被变换回比特并交给链路层。理想情况下，这些比特还应尽可能快地穿过这条处理与传输流水线。

<Figure src="ch07/fig7-11.webp" caption="图 7.11　物理层发送与接收的主要步骤" />

#### 物理层编码

在第一步（"编码"）中，来自链路层的原始数据比特可能被**扩展**——例如在最简单的情形下，可以把原始比特的冗余拷贝加到原始比特集合上，以对抗信道噪声对部分发送比特的损坏。要特别注意，这里在物理层增加的比特，是**额外于**链路层已增加的校验和或 CRC 比特（第 6 章学过）的。若链路层帧含有校验和或 CRC 比特，这些比特在物理层被与链路层帧中任何其他比特同样对待，因而它们本身也可能受到所加物理层比特的保护！

发送的比特还可能被**重排**，例如把冗余比特分散到所发送的比特之中，使一阵噪声不会同时影响某个比特的所有拷贝。接收方随后逆转编码步骤，恢复原始比特流。例如，8 个原始数据比特

d1 d2 d3 d4 d5 d6 d7 d8

可能被扩展为 16 个比特（其中 $d_{i} '$ 表示第 $i$ 个比特的拷贝）：

d1 d1' d2 d2' d3 d3' d4 d4' d5 d5' d6 d6' d7 d7' d8 d8'

然后再被打乱为：

d1 d5 d2 d6' d3 d7 d4 d8' d5' d1' d6' d2' d7' d3' d8 d4'

如果发送时例如有连续三个比特遭遇一阵干扰（其中 x 表示接收方无法从接收信号中提取的比特）：

d1 d5 d2 x x x d4 d8' d5' d1' d6' d2' d7' d3' d8 d4'

那么接收方把收到的比特解乱后得到：

d1 d1' d2 d2' d3 x d4 d4' d5 x d6 d6' d7 d7' d8 x

接收方仍有足够多的接收比特来恢复原始 8 个数据比特，即使存在一阵突发差错。还有远比上面这种简单冗余码更高效的复杂编码技术，这本身足以开设整门课程；见 [Goldsmith 2005]。

最后要指出，图 7.11 顶部从接收方指向发送方的虚线箭头表示**接收方反馈**，发送方用它来选择最适合当前（仍在变化的）无线信道条件的调制技术——这是本节末尾将要讨论的主题。

#### 调制：幅度、频率与相位

调制位于无线发送方物理层的核心。调制取出图 7.11 所示编码模块输出的编码比特，生成编码这些比特的波形。

如图 7.12 所示，把信息编码进无线电信号（有时称为**载波信号**）有三种常见途径。每种途径都通过改变（"调制"）7.2.1 节讨论的三个基本无线电波特征之一来编码信息：信号的幅度、频率或相位。

<Figure src="ch07/fig7-12.webp" caption="图 7.12　幅度调制、频率调制与相位调制" />

- **幅度调制**（amplitude modulation），也称**幅移键控**（ASK）：通过把信号幅度在若干离散值之间改变，把比特值编码进载波信号。图 7.12 中"幅度调制"那条时间线显示，顶部在不同时间区间要发送的 0、1 比特值，如何分别通过把载波信号幅度设为 0 或 1 来编码。
- **频率调制**（frequency modulation），也称**频移键控**（FSK）：通过在不同时间区间改变载波信号的频率来编码比特值。图 7.12 中"频率调制"那条时间线显示，如何把信号频率设为两个频率之一来编码 0 或 1。
- **相位调制**（phase modulation），也称**相移键控**（PSK）：通过在不同时间区间改变载波信号的相位来编码比特值。图 7.12 中"相位调制"那条时间线上，红色信号在一个时间区间起点处取零且上升的值，这个相位在本例中编码比特 0；蓝色曲线与红色曲线相位相差 180 度，它在时间区间起点处取零且下降的值，编码比特 1。

在这些例子中可以看到，接收方只需测量无线电信号的幅度、频率或相位，就能判断发送方的模拟无线电信号中编码的是 0 还是 1。注意，能够检测频率与相位偏移，意味着发送方与接收方的时钟已被仔细同步。

#### 正交相移键控（QPSK）

图 7.12 的例子用两个幅度、频率或相位值来编码单个比特值。但为什么止步于两个值？为什么不用两个以上的幅度、相位或频率值来编码两个以上的取值？又为什么不**同时**调制幅度、相位或频率，从而编码更多信息？这些问题的答案，正是为 4G/5G、WiFi、蓝牙及其他无线网络标准化的现代物理层调制技术的核心。

于是，接下来考虑把图 7.11 中编码模块输出的串行比特**两两分组**：若两个串行比特是 0 后跟 0，它们被分为一组，成为单个符号 "00"；若两个串行比特是 0 后跟 1，则成为另一个符号 "01"；若是 1 后跟 0，则成为符号 "10"；若是 1 后跟 1，则成为符号 "11"。发送方"发送一串比特"的任务，于是转变为"发送符号"的任务。既然有四个符号值（"00"、"01"、"10"、"11"）可以发送，用四个不同的相位偏移值来表示这四个符号值就很合适。这种用四个相位值编码四个不同符号（代表四对不同的二比特值）的途径，称为**正交相移键控**（QPSK），如图 7.13 所示。

<Figure src="ch07/fig7-13.webp" caption="图 7.13　正交相移键控（QPSK）" />

注意在 QPSK 中，所有信号幅度相同，但相位值彼此相隔 90 度：45°（红）、135°（绿）、225°（蓝）、315°（紫）。接收方只需测量信号相位，就能确定发送的是四个符号中的哪一个。还要注意，符号的处理速率只有比特率的一半，这为符号级信号处理留出了比逐比特处理更多的时间。

QPSK 中的四个符号可以用一种称为**星座图**（constellation diagram）的图简洁刻画。星座图中的一点表示符号的相位（从东向即 3 点钟位置起逆时针以度计）与幅度（到原点的距离）。四个 QPSK 符号在图 7.14 中表示为红点。例如，东北象限中的符号相位为 45 度。如我们所料，图 7.14 所示的四个 QPSK 符号具有相同的相位 45°、135°、225°、315°，且幅度全部相同。

<Figure src="ch07/fig7-14.webp" caption="图 7.14　QPSK 星座图——四个符号由四个相位不同、幅度相同的信号波形表示" />

#### 正交幅度调制（QAM）

在 QPSK 中只调制了信号的相位。在**正交幅度调制**（QAM）中，信号的相位与幅度**都**被调制。用星座图可以很好地展示 QAM。图 7.15 给出了 4-QAM、16-QAM 与 64-QAM 的星座图。"-QAM"前面的数字指这种 QAM 中符号的个数。4-QAM 本质上与 QPSK 相同，有 4 个符号。图 7.15 还给出了每个符号所编码的比特值——4-QAM 为 2 比特，16-QAM 为 4 比特，64-QAM 为 6 比特。16-QAM、64-QAM 与 256-QAM 用于 4G/5G 与 WiFi 网络，更高阶的 QAM（1024、4096）则出现在 WiFi-6 与 WiFi-7 标准中。

<Figure src="ch07/fig7-15.webp" caption="图 7.15　4-QAM、16-QAM、64-QAM 的比特编码（WiFi 用星座图）" />

星座图还能让我们进一步理解噪声如何引起比特（更准确地说，符号）差错。考虑图 7.16 中的 16-QAM 星座，假设发送方发送实心红点所示的 "1111" 符号。由于接收方处不断变化的电磁噪声与测量噪声，每次发送该 "1111" 信号时，其幅度与相位被接收到的值都会不同。图 7.16 中黄色阴影点表示接收方测得的幅度与相位的可能取值。多数黄点（对应测得的幅度与相位）离 "1111" 符号的幅度与相位比离任何其他星座符号都近；这些情况下接收方会正确地推断原始发送符号是 "1111"。但注意有一个接收信号离 "1011" 符号比离 "1111" 更近；这时接收方会错误地推断发送的是 "1011"，而实际上发送的是 "1111"，从而造成错误的符号接收。

<Figure src="ch07/fig7-16.webp" caption="图 7.16　发送的 16-QAM 调制信号与接收到的信号" />

#### 自适应调制

图 7.15 与 7.16 还提示：当星座图在更高阶 QAM 下变得更密集时，噪声与接收方测量误差的影响会更明显，从而导致更高的符号差错率，进而更高的比特差错率。更高的传输速率看起来总是可取的，因而使用更高阶 QAM 看起来也总像是好主意——但如果差错率太高，这就**不**成立了！这一观察为物理层无线通信提供了一个宝贵的洞见：**发送方与接收方选择与信道条件相匹配的调制技术至关重要**。

图 7.17 说明了这一洞见。假设目标是把比特差错率（BER）保持在 $10^{- 4}$ 以下，同时当然希望在这一约束下取得尽可能高的比特率。图 7.17 表明：若信噪比（SNR，以 dB 计）低于 13，则应使用 4-QAM；若 SNR 在 13 与 17 之间，则可以使用 16-QAM，比特率相应更高；若 SNR 高于 17，则可以使用 64-QAM。随着 SNR 随时间变化，发送方与接收方所用的调制技术可以动态改变，以便在给定 BER 约束下实现当时可能的最大吞吐量。当然，这要求发送方与接收方协调测量并报告 BER 与 SNR，并协调调制技术的变更。我们研究 4G/5G 无线网络时会看到这是如何做到的。

<Figure src="ch07/fig7-17.webp" caption="图 7.17　4-QAM、16-QAM、64-QAM 的 SNR 与 BER 关系" />

以上结束了对无线物理层的讨论。我们走了很长的路！确实，正如本节开头所指出的，无线网络是一个低层功能无法用几个易于理解的概念就抽象掉的例子。如果你是计算机科学家，无线物理层对你可能是相当陌生的领域。不过，本节学到的物理层概念将为你更深入、更广泛地理解无线网络提供极好的基础。

## 7.3　无线接入网

本节讨论无线接入网背后的原理与实践，包括 802.11 WiFi WLAN 与 4G/5G RAN。我们刚研究的无线信道以及调制与编码属于物理层话题；本节要研究的接入网原理与实践属于链路层话题，建立在这一物理层基础之上。

7.3.1 节先研究无线电信道如何在接入网中的众多设备与基站之间共享。由于第 6.3 节已研究过多路访问问题，这里聚焦于那些基本技术（FDM、TDM 与随机接入）如何针对无线信道做专门化。有了这个共同基础，加上 7.2 节的基础，我们随后在 7.3.2 与 7.3.3 节研究两大无线接入网：802.11 WiFi WLAN 与 4G/5G RAN。接着转向与无线接入网相关的更专门的话题：7.3.4 节学习无线设备如何发现一个无线接入网的存在，以及加入该网络的最初步骤；7.3.5 节更深入地研究信道共享，学习带宽分配以及上下行信道上帧传输的调度；7.3.6 节讨论无线网络设备的能耗。

### 7.3.1　共享无线信道

6.3 节学习了共享多路访问信道的各种途径：

- **信道划分**技术，包括时分多路复用（TDM）与频分多路复用（FDM）；
- **随机接入**协议，包括 Aloha 与载波侦听多路访问（CSMA）协议；
- **轮流**协议，包括轮询。

这里把 6.3 节作为背景，你可能想回看那一节以刷新理解。我们将看到，这些技术全都会用在我们要研究的无线网络体系结构中！有些情形下它们的用法相当直接，另一些情形下这些基本途径被专门为无线网络做了组合或扩展。本小节讨论两种共享无线信道的具体途径：(i) **正交频分多址**（OFDMA），用于 4G、5G 与 WiFi-6/7 网络；(ii) **带冲突避免的载波侦听多路访问**（CSMA/CA），用于各代 WiFi 网络。我们还会了解物理无线电信道如何被划分为上行与下行信道，用于链路层数据帧传输、信道测量、网络发现等。

#### FDM 与 OFDM：信道与子信道

图 7.18 给出 OFDM 讨论的起点。图 7.18(a) 是一个理想化的单一宽带信道，其功率谱（见 7.2 节）在所使用频谱上均匀分布。由于单一宽带信道在实践中难以实现（例如不同频率处存在不同的损伤），而且设备并不需要宽带信道的全部带宽，因此一个频段常被划分为多个窄带**信道**，每个带宽更小，如图 7.18(b) 所示。图 7.18(b) 中每个窄带信道用不同颜色表示。该图还显示了窄带信道之间的**保护带**（guard band）——一小段不传输任何信号的频率范围，用于防止一个子信道的传输干扰相邻子信道的传输。

<Figure src="ch07/fig7-18.webp" caption="图 7.18　功率谱：(a) 理想化的单一宽带信道；(b) 有 12 个子信道的频分多路复用（FDM）；(c) 有 12 个子信道的正交 FDM（OFDM）" />

**正交频分多路复用**（OFDM）是一种对 FDM 子信道载波信号进行调制的技术，使不同信道上重叠的信号相互抵消，如图 7.18(c) 所示。OFDM 不需要保护带，因而能更充分地利用可用信道频谱。注意图 7.18(c) 中功率谱密度曲线下的面积比图 7.18(b) 中大——也就是说，OFDM 的**频谱效率**高于带保护带的 FDM。既然频谱是稀缺而昂贵的资源（见 7.2.1 节），频谱效率就很重要！

7.3.3 节将看到 4G/5G 与 WiFi 网络具体如何定义其各种信道与子信道的带宽。

#### 正交频分多址（OFDMA）

**正交频分多址**（OFDMA）把频分多路复用与时分多路复用结合起来。图 7.19 说明每个 OFDM 频率子信道如何被划分为时间上的**微时隙**。一个 **OFDMA 资源单元**（Resource Element，RE）是某个子信道频率上的一个时间微时隙。与图 7.18(c) 一样，图 7.19 中每个子信道频率用不同颜色表示，12 种子信道颜色与图 7.18 一致。RE 是 OFDMA 信道资源的最小单位——发送方在一个 RE 中恰好可以发送一个符号（见 7.2.2 节），图 7.19 中用黑点表示。在 4G/5G 网络中，一个 RE 占据 15 kHz 的子信道带宽，持续 66.6 微秒；在支持 OFDMA 的 WiFi 网络中，一个 RE 占据 78 kHz 的子信道带宽，持续 12.8 微秒。

尽管 RE 是 OFDMA 信道资源的最小单位，RE 本身并不单独使用。相反，相邻（在频率与时间上都相邻）的 RE 被成组，组内所有符号使用相同的调制技术、相同的功率发送。在 4G/5G 网络中，一组 RE 称为**资源块**（Resource Block，RB）；在 WiFi OFDM 网络中，一组 RE 称为**资源单元**（Resource Unit，RU）。基站或无线设备把一个或多个 RB／RU 中的数据作为符号发送，详见 7.3.5 节。在 4G 网络中，一个 RB 由 84 个符号组成，位于 7 个各长 66.6 微秒的时间微时隙与 12 个各宽 15 kHz 的频率子信道之中，如图 7.19 所示。5G 与 WiFi 网络定义了不同的 RB／RU 大小。

<Figure src="ch07/fig7-19.webp" caption="图 7.19　正交频分多址（OFDMA）：把频分与时分多路复用结合起来" />

#### 随机接入：Aloha 与 CSMA/CA

6.3.2 节学过，随机接入协议简单（例如没有把帧发送时刻集中分配给发送节点的机制），在信道负载低时很理想。我们学过，在 Aloha 中节点只要有数据要发就直接发送，使用整个信道带宽。若两个或更多发送方同时发送报文，重叠的传输会"冲突"，在它们的目的地处都没有被成功接收。要特别注意，冲突表现在**目的地**（即接收方）处收到重叠、相互干扰的信号，而不是在发送方或中间位置。随后用更高层的重传机制从这种冲突中恢复。Aloha 协议最早是 50 多年前为无线卫星网络开发的 [Abramson 1972; Schwartz 2009]。我们将看到，它们今天仍用于卫星与 IoT 网络，并在 4G/5G 网络的某些控制平面功能中实现。

#### 带冲突避免的载波侦听多路访问（CSMA/CA）

**带冲突避免的载波侦听多路访问**（CSMA/CA）是 WiFi 网络最初使用（且在许多年里唯一使用）的信道接入方法。如 7.3.2 节后面所述，最新的 WiFi 标准（WiFi-6 起）同时提供 CSMA/CA 与 OFDMA 两种信道接入技术。

CSMA/CA 是一种载波侦听多路访问（CSMA）协议，具有我们在 6.3.2 节学过的"先听后发"行为。但 CSMA/CA 还有其他特性，用来应对无线环境特有的两个挑战：

- **隐藏终端问题**。由于隐藏终端问题，第一个发送方可能根本听不到某个"隐藏"的第二个发送方也在向第一个发送方的目标目的地发送。
- **无法做冲突检测**。检测冲突的能力要求能**同时**发送（发送方自己的信号）与接收（以判断是否有另一站也在发送）。由于收到的无线信号强度通常远小于发送方自己发送信号的强度，无线发送方很难在自身发送的同时检测到冲突（即使在自己电台处也难以做到），这就排除了使用 CSMA/CD 冲突检测技术的可能。由于 CSMA/CA 不做冲突检测，一旦某站开始发送一帧，它就把该帧完整发完——也就是说，一旦开始就没有回头路。可以想见，在冲突频发时完整发送整帧（尤其是长帧）会显著降低多路访问协议的性能。

<Figure src="ch07/fig7-20.webp" caption="图 7.20　CSMA/CA 使用链路层确认" />

由于这两个挑战，目的地处的冲突在无线网络中通常比有线网络更常见。因此 CSMA/CA 有一个显式的**链路层确认**机制。如图 7.20 所示，当目的站正确收到一帧（例如收到的帧通过了 CRC 比特差错检查）后，它等待一小段称为**短帧间间隔**（SIFS）的时间，然后回送一个确认帧。如果发送站在给定时间内没有收到确认，它就认为发生了差错，并用 CSMA/CA 协议接入信道重传该帧；若重传若干固定次数后仍未收到确认，发送站就放弃并丢弃该帧。

讲完 CSMA/CA 如何使用链路层确认，现在可以更完整地描述 CSMA/CA 协议了。假设某站（无线设备或 AP）有一帧要发送。

1. 若该站最初侦听到信道空闲，它在一段称为**分布式帧间间隔**（DIFS）的短时间之后发送该帧；见图 7.20。
1. 否则，该站用**二进制指数退避**（6.3.2 节遇到过）选择一个随机退避值，并在 DIFS 之后、侦听到信道空闲时对这个值倒计数。当侦听到信道忙时，计数值保持冻结。
1. 当计数减到零（这只可能在侦听到信道空闲时发生），该站发送整帧，然后等待确认。
1. 若收到确认，发送站就知道自己的帧已被目的站正确接收。若还有另一帧要发，它从第 2 步重新开始 CSMA/CA 协议。若没有收到确认，发送站重新进入第 2 步的退避阶段，随机值从一个更大的区间中选取。

回忆以太网的 CSMA/CD 多路访问协议（6.3.2 节）：一站一旦侦听到信道空闲就**立刻**开始发送。而在 CSMA/CA 中，即使侦听到信道空闲，该站在倒计数期间也不发送。为什么 CSMA/CD 与 CSMA/CA 在这里采取不同做法？

要回答这个问题，考虑这样一个场景：两个站各有一帧数据要发，但因为都侦听到第三个站正在发送，所以都没有立即发送。在以太网的 CSMA/CD 下，这两个站会在检测到第三个站发完之后立刻各自发送，这会造成冲突——而冲突在 CSMA/CD 中不是严重问题，因为两个站都会中止发送，从而避免把各自帧的剩余部分无用发完。然而在 WiFi 网络中情况相当不同：由于 WiFi 发送方不检测也不中止冲突，遭遇冲突的帧会被完整发完。因此 WiFi 的目标是尽可能**避免**冲突。在 WiFi 中，若这两个站侦听到信道忙，它们都立即进入随机退避，希望选到不同的退避值。若这两个值确实不同，两站之一最终会先于另一个开始发送，（若两站彼此不隐藏）"输的站"会听到"赢的站"的传输，冻结自己的计数器，并在赢的站发完之前不再发送。这样，一次代价高昂的冲突就被避免了。当然，在这个场景中 802.11 仍可能发生冲突：两站可能彼此隐藏，或者两站选到的随机退避值彼此太接近，以致先开始发送的站的传输尚未到达第二个站。回忆我们在图 6.12 讨论随机接入算法时遇到过这个问题。

#### 应对隐藏终端：RTS 与 CTS

WiFi 的 CSMA/CA 协议还有一个巧妙（但可选）的预留机制，即使在存在隐藏终端时也有助于避免冲突。回忆图 7.6：在隐藏终端问题中，站 A 与 B 能互相听到，站 B 与 C 能互相听到，但站 A 与 C 听不到彼此。假设 A 正向 B 发送一帧，而在 A 的传输进行到一半时，C 想向 B 发送一帧。站 C 听不到 A 的传输，于是先等一个 DIFS 间隔，然后发送该帧，结果在 B 处发生冲突。于是信道在 A 与 C 两次传输的整个期间都被浪费。

为避免这个问题，CSMA/CA 协议有两个可选的控制帧：短的**请求发送**（RTS）帧与短的**允许发送**（CTS）帧，用来（隐含地）预留对信道的访问。我们以"某站想向一个接入点（AP）发送帧"这一常见场景来描述它。当发送方想发一个 DATA 帧时，它先向 AP 发送一个 RTS 帧，指明传输该 DATA 帧与 ACK 帧所需的总时间。目的方收到 RTS 帧后，广播一个 CTS 帧。这个 CTS 帧有两个作用：明确许可发送方发送；并指示目的方听距内的其他站在预留时长内不要发送。

<Figure src="ch07/fig7-21.webp" caption="图 7.21　用 RTS/CTS 实现冲突避免" />

图 7.21 显示，在发送 DATA 帧之前，源先广播一个 RTS 帧，其听距内的所有站（包括 AP）都听到它。注意 AP 右侧的那些站不在发送方的听距内，收不到这个 RTS。然而 AP 随后回送一个 CTS 帧，其范围内的所有站都听到，包括发送方以及 AP 右侧的其他站。这些其他站听到 CTS 后，在 CTS 帧所指定的时长内不再发送。图 7.21 中显示了 RTS、CTS、DATA 与 ACK 帧。

使用 RTS/CTS 从两方面改善性能：

- 隐藏站问题被缓解，因为长的 DATA 帧只在信道已被预留之后才发送。
- 由于 RTS 与 CTS 帧很短，涉及 RTS 或 CTS 帧的冲突只会持续该短帧的时长。一旦 RTS 与 CTS 帧被正确传输，随后的 DATA 与 ACK 帧通常可以无冲突地传输。不过你应当说服自己：RTS/CTS 机制并不总能成功地为 DATA 报文预留信道，因为 RTS/CTS 报文本身也可能因信道衰落或噪声而丢失。

尽管 RTS/CTS 交换有助于减少冲突，它也引入时延并消耗信道资源。因此，RTS/CTS 交换只在（如果要用的话）为**长** DATA 帧的传输预留信道时才使用。

### 7.3.2　WiFi：802.11 无线局域网

无线局域网如今普遍存在于工作场所、家庭、教育机构、咖啡馆、机场、体育场与街角，是因特网最重要的接入网技术之一。虽然 20 世纪 90 年代开发过许多无线局域网，但有一种技术明显胜出：IEEE 802.11 无线局域网，也就是 WiFi。正如以太网统治了有线局域网，WiFi 也统治了无线局域网。802.11 无线局域网标准由 IEEE 802.11 标准委员会制定 [IEEE 802.11 Standards 2024]。自 2000 年以来，若干（并非全部）802.11 标准还被 WiFi 联盟冠以"WiFi"品牌，编号的 WiFi 世代在概念上与蜂窝网络标准的"第几代"类似。虽然有一些 802.11 标准并不属于 WiFi 品牌（例如工作在表 7.1 所示更高或更低频率范围的标准），但我们仍会把"WiFi"与"802.11"两个词交替使用，因为每个主要商用 802.11 标准都对应一个 WiFi 世代，如表 7.2 所示。

#### 802.11 无线局域网概览

我们在 7.3.1 节已讲过 WiFi 的许多基础方面，包括 CSMA/CA、OFDM 与 OFDMA，所以在理解 WiFi 上已有了很好的开端！本节给出 WiFi 网络的概览，讨论其信道结构、帧格式，以及如何与有线以太网局域网互联。本章后面还会讲设备如何发现并附着到 WiFi 网络（7.3.4 节）、WiFi 帧传输的调度（7.3.5 节），以及设备如何通过睡眠／唤醒周期在 WiFi 网络中节能（7.3.6 节）。7.5.2 节还会讲无线网络（包括 WiFi）如何支持设备移动性。

表 7.2 展示了 IEEE 802.11 标准的演进。从表 7.2 可以得到一个结论：WiFi 一直在不懈地提高用户所见的最大吞吐量——毕竟，越多越好！这在 WiFi 早期尤其成立，但 WiFi 网络并不总是（甚至常常不是）以给单个用户提供最大持续吞吐量为部署目标。确实，推动许多 WiFi 发展的最新用例是 WiFi 网络在企业、机场、体育场与公共场所的**密集部署**——大量用户同时想收发数据。在密集部署中，重点在于高效支持众多同时用户，而不是给单个用户提供最大吞吐量。

那么，让我们越过最大吞吐量的提升，对 WiFi 演进作以下几点观察：

- **频率**。多数 WiFi 网络工作在免许可频段（一个例外是用于车对车通信的 802.11p，它工作在许可频段）。WiFi 使用的频段已从仅 2.4 GHz（回忆该频段挤满了众多消费电子设备，是 WiFi 网络的潜在干扰源）扩展到 5 GHz，如今又加上 6 GHz。有些 802.11 标准（如 802.11ah）使用 1 GHz 以下频段，另一些（802.11ad、802.11ay）使用 60 GHz 及更高的所谓毫米波频段。
- **带宽**。WiFi 网络使用的带宽被划分为不同信道带宽的信道，每一代 WiFi 都宣称提高了最大信道带宽。最小信道带宽为 20 MHz，更高的信道带宽通过把多个相邻的 20 MHz 信道"绑定"（bonding）在一起获得。一个具体的 WiFi 网络只在这些信道之一上运行。
- **物理层**。802.11 物理层已从与 3G 蜂窝网络所用扩频调制相关的形式，演进到 OFDM，再到 OFDMA——与支持密集部署场景的 4G 与 5G 网络相同的调制技术。考虑到一个 AP 必须支持一系列遗留设备（例如从古老的 802.11g 设备到支持 WiFi 6 的现代设备），AP 必须**同时**支持 OFDM、OFDMA 与 CSMA/CA。我们很快就会看到这个技术挑战是如何解决的。

<Figure src="ch07/fig7-22.webp" caption="图 7.22　802.11 无线局域网的组成要素" />

图 7.22 展示了 802.11 无线局域网体系结构的主要组成部分。基本构建块称为**基本服务集**（Basic Service Set，BSS）。一个 BSS 包含两个或更多无线节点，其中一个通常是中心基站，用 802.11 的行话说称为**接入点**（AP）。图 7.22 中两个 BSS 各自的 AP 连接到一个互联设备（如交换机或路由器），后者再通往因特网。在典型的家庭网络中，有一个 AP、一台二层交换机和一台三层路由器（通常集成在一个物理"盒子"里），把该 BSS 连接到因特网。下文我们会偶尔不太严格地用 802.11 行话，把 AP 连同交换机（可能还有路由器）的组合简单称为"AP"。但按 802.11 标准，AP 是仅工作于第二层的设备。网络设备只能向 AP 发送／从 AP 接收；设备之间不能直接通信。

#### WiFi 信道结构

图 7.23 展示了 WiFi 如何把对 2.4 GHz 与 5 GHz 频段的使用划分为信道，每个信道有唯一的信道编号。在 2.4 GHz 频段，802.11 定义了 11 个部分重叠的信道，每个带宽 20 MHz。这里两个信道**不**重叠，当且仅当它们相隔四个或更多信道。特别地，信道 1、6、11 是唯一一组三个互不重叠的信道。这意味着如果三个 AP 都在同一物理空间中使用信道 1、6、11 运行，那么这三个网络上的传输不会相互干扰；而如果其中两个网络工作在重叠信道上，这两个网络上的设备就会相互干扰。当然，当同一物理空间中有多个 WiFi 网络各自独立运行时（例如你的家庭 WiFi 网络，以及你公寓 30 米范围内所有其他家庭 WiFi 网络），这会特别成问题。

#### 把它们合起来：WiFi 6 中的 CSMA/CA、OFDM 与 OFDMA

如表 7.2 所示，过去 20 年的所有 802.11 标准都支持**正交频分多路复用**（OFDM），用于创建图 7.23 中多个彼此分开的 WiFi 信道。一个 WiFi AP 可以配置为只使用这些固定带宽信道之一，该 AP 的 WLAN 中所有设备都在这一信道上与 AP 通信。另一种方式是给 AP 分配一个**主信道**，然后通过把一个或多个相邻的**辅信道**与主信道绑定，动态增大可用带宽。在 OFDM 下，设备或 AP 发送时使用整个信道带宽。我们还学到，WiFi 6（及以后）还支持 OFDMA，这与纯 OFDM 不同，在密集部署场景中特别有用。7.3.1 节学过，OFDMA 把信道划分为多个子信道，允许同时与多个设备收发，每个设备使用不同的子信道集合与时隙；7.3.1 节还学过，WiFi 也用 CSMA/CA 随机接入来共享 WiFi 信道。但这三种信道共享途径——OFDM、OFDMA 与 CSMA/CA——怎么可能在同一个 WiFi 网络中同时使用？这到底怎么可能？

答案在于对 WiFi 基本 RTS/CTS 机制的巧妙扩展——它最初是为帮助解决隐藏终端问题而开发的，如今又被用来解决 OFDM、OFDMA 与 CSMA/CA 共存的问题。WiFi 6 引入了一种新的 RTS 报文，称为**多用户 RTS**（MU-RTS）报文。在下行方向上，当 AP 想向多个设备发起 OFDMA 传输时，它发送 MU-RTS。MU-RTS 含有一份 OFDMA 资源单元（RU）分配列表，指明 AP 将用哪些 RU 同时向哪些设备发送数据，以及信道将被使用的时长。MU-RTS 用 OFDM 发送给所有设备（无论其是否支持 OFDMA），作为 CSMA/CA 协议的一部分。因此所有设备都会收到 MU-RTS 报文。只支持 OFDM 的设备按前面所述、如图 7.20 所示那样用一个 CTS 回应 RTS；支持 OFDMA 的设备则只用分配给它的那些频率发送 CTS 来回应。与普通 RTS/CTS 报文一样，RTS 报文可能不成功。但如果这次 MU-RTS/CTS 交换成功，AP 就已预留了信道，随后可以用 OFDMA 向多个设备发送 RU。在上行方向上，设备向 AP 的传输也由 AP 用 MU-RTS 报文协调；细节见 [Meraki WiFi6 2020]。

CSMA/CA、OFDM 与 OFDMA 的交互如图 7.24 所示。这个例子中有两台遗留的 802.11g（WiFi 4 之前！）设备 a 与 b，以及五台 802.11ax（WiFi 6）设备。例子中，设备 a 与 b 分别在 $t_{0}$ 与 $t_{1}$ 之后用 CSMA/CA 协议取得了整个 OFDM 信道的使用权。在 $t_{2}$，AP 用 CSMA/CA 加 MU-RTS 机制（在 $t_{2}$ 开始的灰色阴影框所示的时间与频率上）成功为向设备 1、2、4、5 的同时 OFDMA RU 传输预留了信道。在 $t_{3}$，设备 b 再次用 CSMA/CA 取得信道访问权，并用 OFDM 发送另一帧。在 $t_{4}$，AP 用 MU-RTS 机制成功为向设备 1、2、3 的 OFDMA RU 传输预留了信道。

#### 载荷与 CRC 字段

帧的核心是**载荷**，通常是一个 IP 数据报、一个 MAC 控制帧或一个 ARP 分组。虽然该字段允许长达 2 312 字节，但通常小于 1 500 字节。与以太网帧一样，802.11 帧包含一个 32 比特的循环冗余检测（CRC），使接收方能检测所收帧中的比特差错。如我们所见，无线局域网中的比特差错比有线局域网常见得多，因此 CRC 在这里更有用。

#### 地址字段

802.11 帧与以太网帧最显著的差别也许是：802.11 帧有**四个**地址字段，每个可存放 6 字节的 MAC 地址。但为什么要四个地址字段？一个源 MAC 字段加一个目的 MAC 字段还不够吗，就像以太网那样？原来，为了互联目的——具体地说，为了把网络层数据报从无线站点经 AP 送到路由器接口——需要**三个**地址字段；第四个地址字段用于设备在自组织模式下（无 AP）相互转发帧时。既然这里只考虑基础设施网络，我们把注意力集中在前三个地址字段上。802.11 标准对这三个字段的定义如下：

- **地址 2** 是发送该 802.11 帧的设备的 MAC 地址。因此，若是（非 AP 的）无线设备发送帧，其 MAC 地址被填入地址 2 字段；类似地，若是 AP 发送帧，AP 的 MAC 地址被填入地址 2 字段。
- **地址 1** 是要接收该帧的无线设备的 MAC 地址。因此，若是（非 AP 的）无线设备发送帧，地址 1 含目的 AP 的 MAC 地址；类似地，若是 AP 发送帧，地址 1 含目的无线设备的 MAC 地址。
- 要理解**地址 3**，回忆 BSS（由 AP 与无线设备组成）是某个子网的一部分，而这个子网经某个路由器接口连接到其他子网。地址 3 含这个路由器接口的 MAC 地址。

<Figure src="ch07/fig7-27.webp" caption="图 7.27　802.11 帧地址字段的用法：在 H1 与 R1 之间发送帧" />

为进一步理解地址 3 的用途，走一遍图 7.27 中的例子。图中有两个 AP，各负责若干无线设备；每个 AP 都有一条以太网连接连到一台路由器，路由器再连到全球因特网。要记住 AP 是链路层设备，因此既不"讲"IP，也不理解 IP 地址。现在考虑把一个数据报从路由器接口 R1 送到无线设备 H1。路由器并不知道在它与 H1 之间有一个 AP；从路由器的角度看，H1 只是它所连接的一个子网中的某台设备。

- 路由器从数据报的目的地址知道 H1 的 IP 地址，像在普通以太网局域网中一样用 ARP 确定 H1 的 MAC 地址。取得 H1 的 MAC 地址后，路由器接口 R1 把数据报封装进一个以太网帧：该帧源地址字段含 R1 的 MAC 地址，目的地址字段含 H1 的 MAC 地址。
- 当以太网帧到达 AP 时，AP 在把帧发送到无线信道之前，把 802.3 以太网帧转换成 802.11 帧。AP 按上面所述把地址 1 与地址 2 分别填入 H1 的 MAC 地址与自己的 MAC 地址；对地址 3，AP 填入 R1 的 MAC 地址。这样，H1 就能从地址 3 确定把数据报送入该子网的那台路由器接口的 MAC 地址。

现在考虑无线设备 H1 反过来向 R1 发送数据报时会发生什么。

- H1 创建一个 802.11 帧，按上面所述把地址 1 与地址 2 分别填入 AP 的 MAC 地址与 H1 的 MAC 地址；对地址 3，H1 填入 R1 的 MAC 地址。
- 当 AP 收到该 802.11 帧时，它把帧转换成以太网帧：该帧的源地址字段是 H1 的 MAC 地址，目的地址字段是 R1 的 MAC 地址。可见，地址 3 使 AP 在构造以太网帧时能确定合适的目的 MAC 地址。

总之，地址 3 在把 BSS 与有线局域网互联中起关键作用。

#### 序号、时长与帧控制字段

回忆在 802.11 中，每当一站正确收到另一站的帧时都要回送确认。由于确认可能丢失，发送站可能发送某一帧的多个拷贝。正如我们讨论 rdt2.1 协议（3.4.1 节）时所见，序号使接收方能区分新发送的帧与先前帧的重传。802.11 帧中的**序号**字段在链路层的作用，与它在第 3 章运输层中的作用完全相同。

回忆 802.11 协议允许发送站预留信道一段时间，包括传输其数据帧的时间与传输确认的时间。这个时长（以微秒计）被放入帧的**时长**字段，数据帧以及 RTS、CTS 帧都有该字段。

如图 7.26 所示，**帧控制**字段包含许多子字段。这里只对几个较重要的子字段略作说明；更完整的讨论见 [Wikipedia 802.11*frame*types 2024]。**类型**与**子类型**字段用于标识 802.11 控制帧与数据帧，控制报文包括我们在图 7.21 遇到的 RTS、CTS 与 ACK 报文；设备加入网络时会用到几类控制帧，见 7.3.4 节。**功率管理**比特（顾名思义）用于设备为省电而睡眠时，见 7.3.6 节。

### 7.3.3　5G 无线接入网

本小节讨论 4G 与 5G 蜂窝网络中无线接入网（RAN）的关键方面。我们会大量依赖本章前面关于无线信道、尤其是 OFDMA 的基础材料。这里主要聚焦 5G，但在适当处会涉及 4G LTE 蜂窝网络。

#### 5G 网络的体系结构组成：全局图景

在深入 5G RAN 本身之前，先把 RAN 放到更大的 5G 蜂窝网络语境中。如图 7.28 所示，一个 5G（以及 3G、4G）蜂窝网络有两个主要部分——边缘与核心。

- **无线接入网**（RAN）。RAN 位于 5G 网络的边缘。一个 RAN 由 (i) 终端用户无线设备（蜂窝行话中称为**用户设备**，UE）组成，它们经 (ii) 称为**新空口**（New Radio，NR）的本地 5G 无线信道（想必是为了区别于"旧的"4G 无线信道）附着到 (iii) 基站，即**下一代节点**（gNB）。如 7.1 节所述，由于 UE、NR、gNB 这套命名晦涩且不直观，这里我们采用更直观、更具描述性的说法：用"基站"而不是"gNB"，用"用户设备"而不是"UE"，用"无线信道"或"无线电信道"而不是"NR"。RAN 相当于蜂窝网络中的 WiFi 无线局域网——它包含用户与更大网络之间的第一跳无线链路、无线用户设备，以及一个 5G 基站；这个基站与无线局域网中的 WiFi 接入点（AP）相似，但功能多得多，也复杂精巧得多。
- **5G 核心**。5G 核心由链路、路由器、服务器以及**核心网功能**（Core Network Function）组成，位于 RAN 与蜂窝提供商网络通往更大因特网（包括其他蜂窝提供商网络）的网关之间。一个典型蜂窝网络只有一个核心，但附着多个边缘网络。蜂窝核心中的链路与路由器通常是有线的，使用我们第 4、5、6 章学过的同一套因特网协议与技术。我们前面在第 4、5 章所做的网络层数据平面与控制平面的区分，在 5G 中同样存在，只是数据平面在 5G 术语中称为**用户平面**。确实，控制平面与用户平面的逻辑分离在 5G 体系结构中如此基础，以至于（当然！）它在 5G 标准中还有自己的缩写：CUPS，即"控制平面与用户平面分离"（Control Plane and User Plane Separation）！
- 5G 核心中真正独特之处，是一组称为**5G 核心网功能**的控制与管理功能，它们提供 RAN 接入与鉴权、对用户设备移动性的支持等 5G 服务。我们将在 7.4 节研究这些服务（图 7.28 中的蓝色方框）。这些核心服务实现在何处，各 5G 网络不同。例如，对小型私有 5G 网络，实现核心服务的服务器可能与基站同址；也可能实现在核心内、但靠近 RAN 的一个物理上独立的小型数据中心（常称为**边缘云**）；还可能实现在一个物理上遥远的大型数据中心。唯一的绝对要求是这些服务可以经 IP 到达。用户应用代码也可以运行在基站或 5G 核心中的服务器上，与 RAN 中的无线设备通信以实现应用服务。这称为**本地疏导**（local breakout），因为用户应用的客户端-服务器流量从不离开蜂窝网络。

<Figure src="ch07/fig7-28.webp" caption="图 7.28　5G 网络的主要组成" />

#### 4G/5G RAN：物理无线电信道

4G 与 5G RAN 实现 7.3.1 节研究过的 OFDMA 信道共享。在 4G 网络中，最小子信道带宽为 15 kHz，单个符号在单个微时隙中的传输时间为 66 微秒。5G 网络还定义了更大的子信道带宽（30、60、120、240、480、960 kHz）以及相应更短的微时隙长度。

回忆 7.3.1 节：**资源单元**（RE）是单个 OFDMA 子载波频率上的一个时间微时隙。4G 与 5G 网络都把相邻（在频率与时间上）的 RE 捆绑为**资源块**（RB）。资源块是 4G 与 5G 网络中发送设备或基站所使用的信道资源的最小单位。在 4G 网络中，一个 RB 把 84 个符号捆绑在一起（位于 12 个相邻子载波上、7 个连续时间微时隙中），如图 7.29 所示；这是 4G 网络中 RE 到 RB 的唯一捆绑方式。5G 网络中有多种把 RE 捆绑为 RB 的不同方式。

图 7.29 还说明了信道与 RB 之间的关系，展示了一个 10 MHz 宽的信道，它由 50 个时间上并行的 RB 组成，每个 RB 使用 50 个不同频率子信道之一。4G 网络的标准信道带宽为 1.4、3、5、10、15 与 20 MHz；5G 纳入了 4G 的全部信道定义，并另外定义了最宽达 100 MHz 的信道。

<Figure src="ch07/fig7-29.webp" caption="图 7.29　4G 资源块" />

4G/5G 网络中还有最后一个更高层次的带宽聚合！**频段**（band）是一个或多个信道的聚合，每个信道又由若干不同子载波（子信道）组成，如图 7.30 所示。3GPP 定义了各种 5G 频段 [3GPP TS 38.101-1 2024]。回忆 7.2.1 节：这些频段内许可频谱分配给蜂窝网络提供商，是由各国政府（通常通过拍卖）完成的。各国在这些频段中向运营商提供的频谱量各不相同。网络运营商一旦获得分配到一个频段，如何把该频段划分为信道、把信道划分为子载波，就由该运营商自行决定。

<Figure src="ch07/fig7-30.webp" caption="图 7.30　频段、信道与子载波" />

#### 4G/5G RAN 无线电：物理与逻辑控制／数据信道

上面讨论聚焦于物理无线电信道资源——无线电频率、时间微时隙与 RB 结构。每个 RB 还有一个**方向**：**下行**方向是从基站到用户设备，**上行**方向是从用户设备到基站。正如第 6 章在有线（如电缆）边缘网络中所见，下行流量通常显著多于上行流量，4G/5G 网络中下行与上行流量之比约为 10:1 [Sauter 2021; Mitra 2024]。每个网络运营商可以通过确定每个方向分配的 OFDMA 时隙比例，来设定下行与上行信道资源之比，这一过程称为**时分双工**（TDD）。也可以按频率对资源分组，把一段信道频率专门分配给上行或下行传输，这一过程称为**频分双工**（FDD）。

在给定 RAN 中上下行 RB 的频率与时隙分配之后，RB 在下行方向被划分为三组、在上行方向被划分为三组。这些组称为**下行物理信道**与**上行物理信道**，每个物理信道中的 RB 用于同一目的。其中三个信道在下行方向：

- **物理下行共享信道**（PDSCH）。该信道承载所有下行用户平面数据，以及基站向所有用户设备发送的控制平面消息。
- **物理下行控制信道**（PDCCH）。该信道用于告知用户设备：它们将在下行方向的哪些 RB 中接收数据，以及在哪些 RB 中可以在上行方向发送数据。
- **物理广播信道**（PBCH）。该信道承载基站广播的信息，用户设备需要这些信息来发现并加入蜂窝网络，见 7.3.4 节。

另三个信道在上行方向：

- **物理上行共享信道**（PUSCH）。该信道是 PDSCH 的上行对应物，承载所有上行用户平面数据，以及用户设备向基站发送的控制平面消息。
- **物理随机接入信道**（PRACH）。当设备首次加入网络时，用它向基站请求连接。顾名思义，设备以随机接入方式访问该信道。
- **物理上行控制信道**（PUCCH）。设备用该信道请求基站为其分配 PUSCH 中的 RB，以便将来用这些 RB 向基站发送数据。PUCCH 还承载测量数据，以及用于可靠数据传输的链路层 ACK/NAK。

上下行方向还定义了多种**逻辑信道**，它们随后被映射到物理上下行信道上。同一逻辑信道上流动的所有信息在语义上相关，细节见 [Sauter 2021; electronicsnotes 2024]。有了这些 5G 逻辑与物理上下行信道的定义、图 7.30 中频段与信道的概念，以及 7.2 节对无线电信道特性的讨论，就很容易看出"信道"一词在不同语境下含义大不相同，它是无线网络中用得最多（也许是用得最滥）的词之一！

#### 5G RAN：无线链路层

前面学过了 WiFi 链路层协议栈，现在来看 5G RAN 中的链路层协议栈。

图 7.31 展示了 5G RAN 协议栈，并展开显示了 5G 链路层中各个子层。注意与 WiFi 一样，设备与基站中的链路层都有用户平面与控制平面。用户平面的职责是把链路层帧从设备的应用送到基站（反之亦然）；控制平面的职责是控制和配置 RAN 的无线资源，为用户平面帧传输提供控制功能（例如 ARQ 与服务质量），并提供设备移动性（7.5.3 节）、网络附着（7.3.4 节）与功率控制（7.3.6 节）等附加服务。由于链路层控制平面动作通常涉及设备与基站中控制功能之间的报文交换，图 7.31 在无线链路两侧各子层的控制模块之间画了虚线逻辑连接。基站在用户设备之间发送的控制消息，经 5G 物理控制信道之一在链路层帧中承载。

图 7.31 显示 5G RAN 链路层被划分为若干子层：

- **无线资源控制**（Radio Resource Control，RRC）是控制平面功能，负责 (i) 建立、维护与释放链路层逻辑信道；(ii) 管理每设备的链路层连接状态（7.3.4、7.3.6 节）；(iii) 管理设备移动性的某些方面（7.5 节）；(iv) 执行信道质量测量与上报（7.3.5 节）。RRC 通过配置本地链路层与物理层状态、用 RRC 协议 [3GPP TS 38.331 2024] 在基站与用户设备之间发送控制消息来完成其工作。
- **服务数据适配协议**（Service Data Adaptation Protocol，SDAP）是链路层用户平面中最高的子层。当需要为分组流提供服务质量（QoS）保证时，SDAP 分配 QoS 流标识并把流映射到下层无线资源上。
- **分组数据汇聚协议**（Packet Data Convergence Protocol，PDCP）负责 IP 首部压缩，以及（可选的）加密与密码学报文完整性检查。
- **无线链路控制**（Radio Link Control，RLC）负责分段／重组，以及使用带序号、CRC 与 ACK/NACK 报文的简单 ARQ（自动重传请求）协议实现可靠帧传输，如第 3 章所学。
- **介质访问控制**（MAC）子层负责调度基站与用户设备之间链路层用户平面与控制平面帧的传输。如本节前面所学，这些帧中的数据被切分为更小的块，随后映射到 OFDMA 资源块上传输。我们将在 7.3.5 节讨论 MAC 调度。

<Figure src="ch07/fig7-31.webp" caption="图 7.31　用户设备与基站处的 5G RAN 协议栈" />

图 7.26 的 WiFi 链路层帧相对简单，而 5G RAN 帧要复杂得多，这在很大程度上归因于多个链路子层。一个 5G 链路层帧包含一个 IP 数据报或一个 RRC 控制平面消息，并加上 SDAP、PDCP、RLC 与 MAC 首部字段。每个子层都加入自己的首部字段，通常包括一个用户／控制消息比特、一个序号或标识符、一个载荷字段，以及完成该子层功能所需的其他字段。与其费力详述这些字段，不如把有兴趣的读者直接引向各 3GPP 链路子层协议文档的第 6 节 [3GPP RRC TS 38.331 2024; 3GPP SDAP TS 38.300 2024; 3GPP PDCP TS 38.323 2024; 3GPP RLC TS 38.322 2024; 3GPP MAC TS 38.321 2024]。

图 7.32 给出了 5G 基站链路层控制与分组处理流水线的视图，再次强调了控制平面与用户平面的分离，并注意 RRC 的中心控制作用。

<Figure src="ch07/fig7-32.webp" caption="图 7.32　5G 基站 RAN 控制与分组处理流水线" />

在早先的 2G、3G 与 4G 网络中，RAN 蜂窝基站被实现为一个一体化单元——本质上是一台实现该代标准功能的、单一厂商的专用"盒子"。从 5G 开始，出现了把 RAN 功能"**解绑**"（disaggregate）为多个功能单元、通过标准化接口相互协作的趋势。这种解绑式体系结构使多个厂商可以提供相互竞争的 5G 基站部件实现，降低了准入门槛，增加了竞争与创新——这与我们在第 5 章发现的 SDN 发展的一个关键动因相似。

图 7.33 展示了 5G 基站在功能上拆分为**无线单元**（Radio Unit，RU）、**分布式单元**（Distributed Unit，DU）与**集中单元**（Central Unit，CU），以及各单元内执行的 RAN 功能。这些功能单元位于 RAN 中的何处——基站内、边缘云中还是中心云中——是一个实现决策，常由通信时延与实时通信需求驱动。虽然 RU、DU、CU 是 3GPP 5G 规范的一部分 [3GPP TS 38.300; 3GPP TS 38.401]，但 O-RAN 联盟把这种解绑又推进一步，规定了这些单元之间的接口 [O-RAN Architecture 2024; Polese 2023]。

<Figure src="ch07/fig7-33.webp" caption="图 7.33　解绑：5G 基站在功能上拆分为三个&quot;单元&quot;" />

#### 实现 5G RAN 控制平面

把 5G 基站解绑为 RU、DU、CU 功能单元，只是 5G 中两种解绑之一。第二种解绑出现在 5G 控制平面中。特别地，由于 RRC 控制平面与用户平面是分离的（其分离方式与因特网控制平面和数据平面分离很相似），因此可以用现代 SDN 式的方式实现标准化的 RRC 功能。

图 7.34 展示了 RAN 控制平面的一种 SDN 式实现。把图 7.33 所暗示的一体化 RRC 实现与图 7.34 的 SDN RRC 实现加以比较是很有教益的。特别地，只要图 7.34 中重构后的实现实现了图 7.33 中所有面向移动核心与用户平面的功能接口，那么对 5G 网络的其他组件来说，两种实现无从区分。

如图 7.34 所示，一个 **SD-RAN** 控制器通常有以下主要组件：

- **控制平面代理**（control-plane proxy），在 RAN 与 5G 核心控制平面之间实现符合 3GPP 的接口。具体地说，RAN 的控制平面代理必须实现到图 7.28 所示每个核心网功能的、定义良好的服务化接口（详见 7.4 节）。
- **实时智能控制器**（RIC），在此处的作用类似于图 5.14 中的 SDN 控制器。RIC 本身有三个主要组件：下层通信层，把命令传送给数据平面 RAN 组件；RAN 范围的状态管理层，RIC 的控制决策需要关于每个用户设备的信道状态、连接状态与身份信息、QoS 要求等的最新信息，这些信息保存在本地 **RAN 节点信息库**（R-NIB）中；以及面向一组应用层控制进程的接口。
- **RIC 控制进程**，就负载均衡、设备切换、QoS 供给等做出 RAN 控制决策。这些进程在 OpenRAN 行话中称为 **xApp**，可以访问 R-NIB 中的信息，并作为独立软件进程实现在 RIC 本身之外，如图 7.34 所示。一组开源 xApp 见 [O-RAN xApp 2024]。OpenRAN [O-RAN Architecture 2024] 是最著名的 SD-RAN 实例之一。OpenRAN 之所以"开放"，是因为 SD-RAN 各组件之间有定义良好的标准化接口，使 SD-RAN 不同组件的多厂商实现可以互操作。

<Figure src="ch07/fig7-34.webp" caption="图 7.34　SD-RAN：软件定义的 RAN 控制平面" />

关于 5G RAN 软件化的深入讨论，见 [Peterson 2024]。

### 7.3.4　发现：附着到无线网络

讲完蜂窝 RAN 与 WiFi 局域网的细节，现在把注意力转向任何边缘网络都需要的一项能力——无论它是有线以太网局域网、5G RAN 还是 WiFi WLAN：设备检测网络基础设施的存在并"附着"到该网络的能力。这个过程称为**网络关联**（network association）。

#### 信标

基站（无论 5G 网络还是 WiFi 网络中的）都会周期性发送**信标**（beacon）报文，宣告接入网的存在，以及关于其特性的信息，例如名称、传输能力（如传输速率）与无线电信道的物理层参数。想附着到某网络的设备会**被动扫描**各种可能的无线信道，寻找这类信标报文。

无线网络标准并不规定设备用何种算法来选择关联哪个已通告的网络——这个选择留给设备（或用户），或留给无线设备中固件与软件的设计者。通常，设备可能选择与它最近一次关联过的网络关联，可能从一份有序列表中选择，也可能选择加入信号最强的网络。在公共 5G 网络中，设备几乎总是优先关联到为其 SIM 卡发卡、且与其有付费服务计划的提供商所运营的 5G 网络。

#### 附着到 WiFi 网络

在扫描可用网络并选定要关联的 AP 之后，WiFi 设备向该 AP 发送一个 802.11 **关联请求**帧；AP 回送一个**关联响应**帧，如图 7.35 所示。如 8.8 节将讨论的（图 7.35 未画出），设备还会在收到信标之后、在关联之前或之后，用 WPA（WiFi 保护接入）安全机制向网络鉴别自己。

一旦与某个 WiFi AP 关联，设备就想加入该 AP 所属的子网（4.3.3 节 IP 编址意义上的子网）。因此设备通常经该 AP 向子网发送一个 DHCP 发现报文（见图 4.21），以获取该子网上的一个 IP 地址。一旦取得地址，世界其余部分就把该设备简单地看作该子网中又一台拥有 IP 地址的设备。

#### 附着到 5G 网络

设备附着到 5G 网络以获得自己无冲突的控制与数据信道的过程，比附着到 WiFi 网络要复杂一些。特别地，5G 设备不是只寻找一条包含加入接入网所需全部信息的信标报文，而是经过一个多步过程来获取所需信息。图 7.36 说明了这个过程：

1. 每台基站广播设备决定是否加入网络所需的多项信息。设备首先定位该网络的**主同步信号**（PSS），并用它把自己的时钟与基站的时钟同步；然后定位**辅同步信号**（SSS），它提供一个初始网络标识符。PSS 与 SSS 由每台 5G 基站在每个 5G 信道的中心 127 个子载波上每 5 毫秒广播一次。接着，设备获取该信道的**主信息块**（MIB），其中含子载波间隔信息，以及该小区是否开放关联。PSS、SSS 与 MIB 合起来构成**系统信号块**（SSB）。有了这些信息，设备就能定位并接收最多 20 个**系统信息块**（SIB），它们刻画该 5G 网络及其运行。其中最重要的是 SIB1，它每 80 毫秒发送一次，包含：运营该信道的运营商的**移动国家码**（MCC）与**移动网络码**（MNC）；基站标识符；可接受的最低接收电平（信道质量）。
1. 现在假设设备决定要关联这个 5G 网络。然而基站甚至还不知道该设备的存在，设备也尚未分配到任何可用于与基站通信的上行 RB。因此，设备用该小区的上行随机接入信道，向基站发送一个**无线资源控制**（RRC）连接建立请求（用意上类似 802.11 的关联请求帧）。
1. 第 3 步，基站用一个 RRC 连接建立响应消息（用意上类似 802.11 的关联响应帧）回应设备的连接建立请求。

此时，用户设备与基站已能在 RAN 中彼此交换控制消息。但设备**仍未**加入 5G 网络（！），因为它还没有向网络标识或鉴别自己，也还没有 IP 地址。我们将在讲 5G 核心（7.4 节）与鉴别（8.8 节）时看到设备如何完成加入 5G 网络的过程。

### 7.3.5　RAN/WLAN 上的传输调度

MAC 层最重要的功能之一，是调度下行方向上从基站到用户设备的数据发送顺序，以及上行反方向的发送顺序。这是 **MAC 调度器**的角色，在密集部署场景（即 4G/5G 网络与 WiFi 6/7 的 OFDMA 部署）中尤为重要——那里在某一时刻可能有数十或数百个用户有数据要发。因此这里聚焦于基站中存在一个集中式 MAC 调度器的场景。纯随机接入环境中的分布式调度也是一个有趣话题（见例如 [Liang 2010]），但这里不涉及。

回忆我们此前在 4.2.5 节研究过有线环境中的链路层调度。那里我们看到，链路层的总体性能（例如按吞吐量衡量、对所有流经该链路的流量汇总）本质上与帧的发送顺序**无关**，因为无论具体选择发送哪些帧，每秒发送的帧数都是固定的。然而在无线环境中，情况绝非如此！如 7.2 节所学，基站对物理上靠近、视距清晰的设备（通过使用更高比特率的调制方案）能以比对远处、受多径效应影响的设备更高的速率发送。因此，WLAN 与 RAN 的吞吐量取决于调度了哪些设备作为发送方与接收方。MIMO 空间复用与空间分集为向给定接收方发送单流或多流提供了额外的自由度；波束成形提供了另一种机会——同时向不同的一组接收方发送。而且，信道特性当然在不断变化。于是，**无线链路层的总体聚合性能在很大程度上取决于 MAC 调度选择**！

由于 3GPP 与 WiFi 标准都不规定（甚至不描述）MAC 调度算法，调度算法的选择完全掌握在网络运营商手中。调度因此是能把一个网络提供商与另一个区分开的"秘方"的一部分。确实，许多无线硬件／软件厂商与无线网络提供商都宣称，其精巧的 MAC 调度途径使他们区别于竞争对手。

MAC 调度有四个关键考虑：

- **信道质量感知**。调度器在做调度决策时是否考虑基站与设备之间无线电信道质量的估计／测量？由于与基站之间无线电信道质量高的设备能以更高速率收发数据，网络可以通过优先向与基站之间信道质量高的设备发送，获得更高的聚合吞吐量。
- **设备间公平性**。调度器是否在设备之间提供一定程度的公平（例如大致相等的吞吐量）？如果是，"公平"指什么？例如，只向信道质量最高的设备发送的调度策略可能取得高吞吐量，但不提供设备间的吞吐量公平。如果要提供公平，"代价"可能是（相对于不考虑公平时可达的最大吞吐量）聚合吞吐量有所下降。
- **业务类别的优先级**。调度器是否区分控制平面流量与用户平面流量（例如给前者更高优先级，或为这两类之一或两者保证固定的最小信道资源量）？调度器是否区分有实时约束的流量（如控制应用、交互式语音与视频）与非实时流量（如网页浏览）？我们此前在 4.2.5 节关于优先级调度的讨论在这里适用。
- **服务质量（QoS）感知**。调度器是否以这样的方式做调度决策，从而为网络中的设备提供服务质量（性能）保证？

多年来人们写了成千上万篇研究论文，提出的 MAC 调度算法几乎一样多。这里只描述几个有代表性的算法，采用 [Capozzi 2012] 的记号。MAC 调度算法的综述见 [Capozzi 2012; Haque 2023]。

图 7.37 展示了四种不同的 MAC 调度算法，显示基站中排队等待向六个下行设备发送的数据（即链路层帧）。这里聚焦于调度从基站到其关联设备的下行传输；不过讨论也适用于上行信道，因为基站同样调度上行信道，并告知设备可用的上行信道资源及使用时机。在 OFDMA 下行信道下，调度器的决策决定在当前调度时刻与下一时刻之间，哪个设备排队中的帧将在哪些资源块（RB）中发送。在 4G/5G 系统中，调度决策每 1 毫秒做一次；在 WiFi 6 中，调度决策之间的时间可以更短 [Qualcomm 2021]。

#### 轮询（RR）调度

回忆 4.2.5 节在有线环境中对 RR 调度的讨论。在无线环境中，RR 为每个设备在下一轮传输中分配**相同数量**的 RB。RR 是信道不感知、QoS 不感知的。RR 按轮次是公平的，因为每个设备分到相同数量的 RB；但不一定是吞吐量公平的，因为不同设备可能经历不同信道条件，从而获得不同吞吐量。

#### 最大吞吐量（MT）调度

在 MT 调度中（图 7.37(b)），基站把 RB 分配给"对该 RB 测得信道质量最高且有待发数据"的用户设备。信道质量可以用许多不同方式确定。在 5G 网络中，基站在资源块的已知位置上周期性广播**参考信号**符号；设备根据对这些参考信号的测量，周期性地上报一个 4 比特的**信道质量指示**（CQI）。

在 MT 调度中，每个调度时刻 $t$，基站计算

$d_{i}^{k}(t)$：设备 $i$ 在时刻 $t$ 使用第 $k$ 个 RB 的期望吞吐量

它由各设备 $i$ 上报的 CQI 计算得出，CQI 又决定所用的调制技术（见例如 [3GPP 38.214 2024] 表 5.2.2.1-1），进而决定资源块 $k$ 中每个发送符号的比特数。

MT 调度器随后在所有 RB $k$ 上找出报告质量最高的设备 $i$：

$$
\max _{i, k} {d_{i}^{k}(t)}
$$

并把 RB $k$ 分配给设备 $i$。这个过程重复进行，直到所有 RB 分配完毕。注意 MT 调度是信道感知的，但不公平。确实，在最不公平的情形下，若数据足够多，信道质量最高的那台设备可能被分配全部可用 RB！

#### 盲式等吞吐（BET）调度

BET 调度算法（图 7.37(c)）明确以提供公平为目标，为所有用户设备提供相等的平均吞吐量。在 BET 中，调度器维护对设备平均吞吐量的估计。设 $r_{i}(t)$ 是设备 $i$ 在时间段 $t$ 内实测达到的吞吐量，则设备 $i$ 在时刻 $t$ 吞吐量的指数加权滑动平均（EWMA）$R_{i}(t)$ 为

$$
R_{i}(t) = \beta r_{i}(t) + (1 - \beta) R_{i}(t - 1)
$$

其中参数 $\beta$（$0 < \beta < 1$）决定 $R_{i}(\cdot)$ 较新取值在计算平均吞吐量时的相对重要性；$\beta$ 越大，近期取值越重要。你可能还记得，我们在 3.5.3 节学习 TCP 如何估计往返时间时遇到过这个 EWMA 公式。BET 简单地把 RB 分配给"在基站中排队等待发送的数据、且吞吐量最小"的设备。这个过程重复进行，直到所有 RB 分配完毕。BET 调度是显式吞吐量公平的、QoS 不感知的，并且可以说在某种程度上是信道感知的，因为它使用了实际达到的每设备吞吐量（这取决于信道质量）。

#### 比例公平（PF）调度

PF 调度力图在最大化性能（吞吐量）与提供设备间公平之间取得平衡。设 $d_{i}^{k}(t)$ 与 $R_{i}(t)$ 如上定义。每个调度时刻 $t$，PF 调度器找出使下式最大的设备 $i$ 与资源块 $k$：

$$
\max _{i, k} {d_{i}^{k} \frac{t}{R_{i}}(t - 1)}
$$

然后把 RB $k$ 分配给设备 $i$。PF 背后的直觉很清楚——由于 $d_{i}^{k}(t)$ 在分子中，吞吐量越大，被最大化的表达式值越高；同样由于 $R_{i}(t - 1)$ 在分母中，平均吞吐量低的用户设备也会提高被最大化表达式的值，从而有利于那些经历过低吞吐量的设备。这个过程重复进行，直到所有 RB 分配完毕。注意 PF 调度是信道感知的，并力图提供一定程度的公平。

以上讨论只是触及 WLAN 与 RAN 调度的皮毛。其他调度准则、通过硬性或软性资源预留提供服务质量保证 [Prasad 2023]、优先级调度、实时流量调度，以及虚拟化调度 [Peterson 2024]，都是这一领域中另外的重要话题。

### 7.3.6　能耗考虑：唤醒／睡眠

能量是无线移动设备中的宝贵资源，因此许多无线网络提供显式的电源管理能力，使设备把其侦听、发送、接收功能及其他电路的"开启"时间降到最低。为此，设备通常在睡眠与唤醒状态之间交替（就像课堂上打瞌睡的学生！）——有活干时醒来，没活干时睡觉。测量表明，LTE 电台在发送或接收（或等待接收）时可能消耗 1 000 到 3 500 mW，而断电时不到 15 mW——约为开启状态能耗的百分之一 [Huang 2012]。测量还表明，在运行流行应用的 4G 与 5G 设备中，20% 到 50% 以上的能耗用于通信 [Xu 2020]。因此，与通信相关的能耗在移动设备整体能耗管理中起核心作用。

可以识别出通过电台睡眠／唤醒周期进行能量管理的两种主要途径：

- 在**协调式睡眠／唤醒**（coordinated sleep/wake）途径中，设备与基站之间的协议协调设备的睡眠／唤醒周期，双方都知道设备的睡眠／唤醒状态，以及设备下次预定醒来的时间。有了这些知识，基站可以把到达的、目的地为该睡眠设备的数据报排队，等设备醒来后再把这些数据报发送给它。WiFi 与 5G 网络都采用协调式睡眠／唤醒途径。
- 在**非协调的"唤醒即发"**（uncoordinated, wake-and-send）途径中，设备只在有数据要发时才醒来。例如 IoT 设备可能如此：偶尔的传感器读数要经基站发送给日志服务器。醒来发送之后，设备可能等待基站回送给它的报文，然后回到睡眠，直到下一次需要发送传感器读数。蓝牙（7.6.1 节）、LoRaWAN（7.6.3 节）与 4G LTE 窄带 IoT（NB-IoT）网络采用非协调的"唤醒即发"途径。

#### IEEE 802.11 网络中的协调式睡眠／唤醒

802.11 网络自诞生起就具备电源管理能力。WiFi 设备把 802.11 帧首部中的**功率管理**比特（见图 7.26）置 1，向接入点表明自己将进入睡眠。由于 AP 从该比特知道设备要睡眠，它会把到达的、目的地为该睡眠设备的帧缓存起来，直到该设备醒来。WiFi 设备醒来时，会扫描 AP 的信标帧，其中含**业务指示图**（TIM），指明哪些设备在 AP 处有缓存帧等待发送。若该设备没有缓存帧，它可以回去继续睡；否则设备向 AP 发送轮询请求报文，请 AP 发送缓存帧。

802.11 还增加了若干较新的电源管理能力。WiFi 6 引入了**目标唤醒时间**（TWT），允许设备与 AP 协商其睡眠周期长度。这在设备只是偶尔上报传感器值的 IoT 场景中很有价值。TWT 的最大值为 4 年 5 个月 16 天 13 小时 37 分 39.49 秒——一段非常长的睡眠！专门为 IoT 应用设计的 IEEE 802.11ah 标准（见 7.6.3 节）继承了 IEEE 802.11 的省电能力，并增加了缩小首部等增强措施以进一步节能。关于 WiFi 现代节能机制有一篇透彻而可读的综述 [Guerin 2023]。

#### 5G 网络中的协调式睡眠／唤醒

与 WiFi 一样，当用户设备没有要发送或接收的东西时，其电台没有理由一直"开着"。因此 5G 网络中的用户设备与其 WiFi 对应物一样，也可以经历睡眠／唤醒周期。5G 设备的睡眠／唤醒周期有两种不同形式，大致对应于**浅睡眠**（也许相当于打个小盹）与**深睡眠**。

图 7.38 展示了浅睡眠周期的结构，在 5G 中称为**连接态下的非连续接收**（DRX）。这里浅睡眠有两个阶段：短 DRX 周期与长 DRX 周期。顾名思义，两个阶段只在睡眠时长上不同，在时延（设备收到已在基站到达、目的地为该设备的数据报之前的延迟）与"开启电台、检查是否有待收下行传输、再关闭电台"所耗能量之间做权衡。

在图 7.38 的例子中，用户设备在 $t_{0}$ 收到基站的一次传输并启动活动定时器。到 $t_{1}$，由于设备自 $t_{0}$ 以来既未收到任何传输、也没有要发的传输，活动定时器到期，设备进入短 DRX 睡眠周期。每个短 DRX 周期结束时，设备醒来，检查基站是否在通告有待发给它的传输，或自己是否有传输要发。这个例子中，由于在若干个短睡眠周期内该设备都没有活动，设备在 $t_{2}$ 进入长 DRX 睡眠周期；它在每个更长睡眠周期结束时再次醒来检查有无进出传输。在 $t_{3}$，一个分组到达基站要发给该设备，由于设备在睡眠而被缓存。在 $t_{4}$ 结束的那个长睡眠周期末尾，设备醒来，发现基站在通告有发给它的传输，进入活动状态，最终在 $t_{5}$ 收到基站的传输，并重启其非活动定时器。这个例子中，由于设备睡眠，到达分组经历的时延增加量等于 $t_{5} - t_{3}$。

除了图 7.38 所示的 DRX 周期，还有更长、更深的用户设备睡眠状态。在更长时间不活动之后，设备可以进入**空闲**（Idle）态或**非活动**（Inactive）态，此时它必须采取额外步骤在 RAN 中重建其活动存在，然后才能收发用户数据。更多细节见 [Hailu 2019; Developedia 2021; Sauter 2021]。

<Figure src="ch07/fig7-38.webp" caption="图 7.38　用户设备的浅睡眠周期，含短 DRX 与长 DRX 周期" />

#### LoRaWAN 中的非协调"唤醒即发"

LoRa（见 7.6.3 节）[Sematech 2019a, 2019b; Sinha 2017] 是一种低功耗、低比特率的无线网络技术，面向相对简单的 IoT 设备，其典型任务是把传感器测量数据上报给附近的网关（通常在设备几公里范围内）。最简单的一类 LoRa 设备称为 **Class A** 设备，它用非协调的"唤醒即发"方式使用电台：有数据要发的设备直接醒来，不与网关节点做任何协调（甚至不知道是否有网关存在）就发送数据，可选地等待来自网关的下行数据，然后回到睡眠。这里设备节能是一等考虑，设备通常处于睡眠状态，只是偶尔被设备自己发起的唤醒打断以发送数据。

图 7.39 展示了 LoRa 的"唤醒即发"行为。在 $t_{0}$，LoRa IoT 设备醒来，向 LoRa 网关发送一个 LoRa 帧（例如含一次传感器测量）。设备随后寻找来自网关的报文，没收到，于是在 $t_{1}$ 回到睡眠。在 $t_{2}$，网关有报文要发给该 IoT 设备，但必须等到设备下一次联系（$t_{3}$ 之后）才能发送；网关的报文在 $t_{4}$ 被收到，设备在 $t_{5}$ 回到睡眠。

<Figure src="ch07/fig7-39.webp" caption="图 7.39　LoRa 的&quot;唤醒即发&quot;" />

与 LoRa Class A 一样，低功耗蓝牙（BLE）与 4G LTE 窄带 IoT（NB-IoT）网络也支持由 IoT 设备发起的"唤醒即发"传输。不过在这些情形下，设备醒来后必须先联系控制节点或基站，先被分配到信道发送时隙，然后才能发送数据。细节见 [Sauter 2021]。

## 7.4　无线核心网

7.3 节学习了无线接入网，现在从无线边缘走进无线核心。5G 核心提供较高层的控制平面与管理平面服务（例如管理用户设备身份、接入安全、移动性等），以及把数据报在 5G RAN 中的设备与更大因特网之间转发的数据平面服务。

本节完全聚焦 5G 网络，而不再同时讲 5G 与 WiFi。确实，这里没有理由讨论 WiFi 网络的核心控制与管理，因为传统 IP 网络对有以太网与 WiFi 使用同一套管理与控制平面机制。企业把 WiFi（或任何无线边缘网络）只看作其网络中的又一种链路层技术。

有人可能会问：为什么核心网在移动蜂窝网络中是如此核心的体系结构组件，而在传统 IP 网络中不是？答案无疑在于 5G 植根于移动蜂窝电话。1G 与 2G 蜂窝网络本质上只是电话网；3G 网络仍主要是电话网，分组数据只是作为附加服务嫁接上去。这些早期蜂窝网络支持管理用户身份（例如通过 SIM 卡）、设备在提供商网络内移动、在不同提供商网络间漫游，以及服务的计费、账单、支付与结算等服务。当时已部署的因特网并不支持这些服务。4G 与 5G 网络如今已成为"全 IP"网络，并采纳了传统 IP 网络中首创的许多服务。然而，对身份、移动性、漫游与服务计费等服务的原生支持——这些服务主要在 5G 核心中实现——在传统因特网 ISP 中并未实现，至今仍是 4G/5G 网络与传统 IP 网络之间的重要差别。

本节 7.4.1 节概述 5G 核心及其服务；7.4.2 节聚焦用户平面功能与隧道的广泛使用；7.4.3 节讨论用户身份及其在注册与会话建立中的作用。移动性如此重要，我们将在 7.5 节单独讨论。

### 7.4.1　5G 核心与网元功能

图 7.40（改编自 [3GPP 23.501 2024]）展示了若干关键的 5G 核心组件。5G 核心采用**服务化体系结构**（Service-Based Architecture，SBA），核心中的体系结构元素以**网元功能**（Network Function，NF）及其提供的服务来定义。虽然 5G 规范并不规定这些功能如何实现，但服务化的描述自然会映射为实现在逻辑集中式数据中心中的微服务（正如本章各图所暗示的那样）。这一途径与 4G 及更早的蜂窝网络体系结构显著不同——后者定义的是通过协议交互的传统网络"实体"，通常由独立的单一功能设备（"盒子"）实现。也许正反映了与 4G 的这种断裂，5G 的服务元素与 4G 对应物相比有全新的名称与缩写，这偶尔会让学习蜂窝网络的学生头疼——他们可能被蜂窝网络世界里的名称与缩写淹没。

5G 核心中的许多创新——特别是从"盒子"到"服务"的演进、基于 SDN 实现服务的机会，以及控制平面与用户平面的清晰分离——都映射了我们在第 5 章学过的因特网控制平面的早期演进。

<Figure src="ch07/fig7-40.webp" caption="图 7.40　5G 核心：关键网元功能" />

#### 5G 网元功能

如果要选出 5G 核心中"最重要的三个"网元功能，以下三个会是主要候选：

- **用户平面功能**（User Plane Function，UPF）负责 RAN 与更大因特网之间流量的数据平面转发。作为数据平面中唯一的 5G 网元功能，它显然起核心作用。如 7.4.2 节将看到的，UPF 被组织为一个隧道式中继，在基站与更大因特网之间转发用户 IP 数据报。设备发往更大因特网的每个数据报（以及反方向的每个数据报）都要经过该设备的 UPF。
- **接入与移动性管理功能**（Access, Mobility Management Function，AMF）在授权并建立设备对 5G 网络服务的接入、以及管理设备移动性（7.5 节讨论）方面起关键作用。AMF 可以说是 5G 控制平面中最核心的网元功能。我们将会看到，AMF 与许多其他网元功能协作实现其服务。例如，AMF 与**鉴别服务器功能**（AUSF）交互，对想加入 5G 网络的设备进行鉴别。AMF 还是唯一直接与设备交换控制消息的控制平面网元功能（经图 7.40 所示的 N1 接口），也是仅有的两个直接与基站交换控制消息的网元功能之一（经 N2 接口）。像 N1 这样带编号的接口在 3GPP 行话中称为**参考点**，定义一个 5G 核心功能与另一个核心功能（或设备、基站）之间的交互。[3GPP 23.501 2024] 标准化了 60 多个这样的参考点。
- **会话管理功能**（Session Management Function，SMF）管理每个设备的会话，包括 IP 地址分配与指派（例如 NAT 与类 DHCP 服务），以及为基于策略的接入控制、计费、经 UPF 建立设备数据平面转发等功能安装每设备状态。

网络、用户与应用的数据及状态信息在网元功能集合中也占显著位置。设备配置、服务与鉴别信息由**统一数据管理**（Unified Data Management，UDM）网元功能管理。UDM 可以把数据存在其功能实现内部，也可以外部存放在**统一数据存储库**（Unified Data Repository，UDR）中。当一个网元功能选择把数据外部存放在 UDR 并远程访问、更新这些信息时，就可以实现**无状态事务**（用意上类似 HTTP 中的无状态客户端／服务器交互），这自然带来云环境中可扩展、有韧性的网元功能实现。其他网元功能与第三方应用也可以向 UDR 与**非结构化数据存储功能**（UDSF）存取数据。

7.3.3 节学到，用户应用代码可以运行在 5G 核心或基站的服务器上，与设备通信以实现应用服务，这种能力称为**本地疏导**。**网络开放功能**（NEF）与**应用功能**（AF）把这些本地疏导应用所需的特定网络数据与网元功能服务开放给它们，反之亦然。

有时一个运营商 5G 网络中运行的网元功能需要与另一运营商 5G 网络中的对应功能交互。例如，当你的智能手机想加入一个并非由你付费订购的提供商（称为你的"归属"网络）运营的网络时，你想加入的网络中的 AUSF 会与你归属网络中的对等 AUSF 交互，以执行鉴别并确定你可用的服务集合。这两个网络中的鉴别功能会通过各自的**安全边缘保护代理**（SEPP）网元功能安全通信。

最后，还需要让网元功能注册其服务、并发现可能数量庞大的其他网元功能的能力。**网络存储库功能**（NRF）提供这种自动注册与发现服务，免去了复杂的人工配置。**策略控制功能**（PCF）为用于移动性管理、每设备服务质量与漫游的控制策略规则提供控制、管理与集中存储库服务。5G 引入的一个重要新概念是**网络切片**（network slicing），它涉及 RAN 与核心资源的虚拟化，以及定义多个共享网络底层物理资源的逻辑网络的能力——这与我们在 6.5 节学到的"多个虚拟专用网（VPN）可以在传统 IP 网络的同一套物理网络资源上运行"很相似。**网络切片选择功能**（NSSF）是在网络切片中起核心作用的网元功能，网络切片这一话题超出本书范围。

我们将看到，一个网元功能通常与其他网元功能交互来实现其服务。网元功能可以用几种不同的交互风格通信，标准并不强制或推荐某一种。NF 服务可以用我们第 2 章学过的传统请求／响应客户端-服务器模型访问，而这又可以通过 HTTP 之类的协议或数据中心环境中的远程过程调用实现。另一种客户端-服务器交互形式是**订阅／通知**模型（分布式系统文献中也称发布／订阅模型）：客户端注册对某服务的兴趣，服务结果可用时服务器通知客户端（即把结果"推"给已订阅的客户端）。回忆第 5 章学过，发布／订阅模型是 Google Orion SDN 平台的核心组织原则。

### 7.4.2　用户平面功能

上面学到，用户平面功能负责控制 RAN 与更大因特网之间流量的数据平面转发。由于 5G 数据平面是全 IP 网络，它在许多方面的运行与我们在第 4、5 章已见过的完全相同。不过 5G 控制平面把数据平面配置为支持两项传统 IP 网络并不总具备的关键服务：**服务质量**（QoS）支持与**隧道**。5G 的 QoS 支持是超出本书范围的高级话题，讨论见 [Sauter 2021]。本小节讨论隧道，以及 5G 数据平面中实现隧道的协议栈。

回忆第 4、6 章：隧道在两个 IP 设备之间提供一条虚拟链路的抽象。在 5G 场景中，为每台设备在其基站与其 UPF 实例之间建立一条隧道，如图 7.41 所示。有了隧道，基站与 UPF 之间回传网络中那一整片路由器和链路，对该设备而言就被抽象为一条虚拟链路。

在 7.3 节详细学过 RAN 协议栈之后，现在聚焦基站与 5G 核心中 UPF 处的数据平面协议栈。如 7.4.3 节所述，当设备加入网络时，SMF 会在基站与该设备的 UPF 之间建立一条隧道。当 UPF 从外部因特网收到一个目的地为其数据平面中某台设备的数据报时，它用 **GPRS 隧道协议**（GTP）[3GPP TS 29.281 2022] 把该数据报封装进一个 UDP 报文段；该 UDP 数据报随后成为一个新 IP 数据报的载荷，这个新 IP 数据报像任何其他寻址到基站的 IP 数据报一样，经回传网络从 UPF 转发到基站。在接收侧，基站解封装来自 UPF 的隧道 UDP 数据报，取出其中封装的、目的地为设备的数据报，并经 RAN 把该 IP 数据报转发给设备。与混合 IPv4/v6 网络中隧道（4.3 节）的用法一样，你应当仔细查看图 7.41 中"数据报套数据报"里的那些地址。

<Figure src="ch07/fig7-41.webp" caption="图 7.41　带隧道的 5G 协议栈" />

隧道协议的细节相当直接，见 [3GPP TS 29.281 2022]。因此这里不深入那些细节，而考虑一个更根本的问题：为什么首先要用隧道？第 4 章学过，隧道使 IPv4 与 IPv6 网络可以互操作。但在纯 5G 网络中运行，把数据报套进数据报又有什么好处？答案在于**设备移动性**，即设备在蜂窝提供商网络中移动时改变其所附着的基站（7.4 节）。

再考虑图 7.41 的例子。若没有隧道，回传网络中的所有路由器都需要维护关于设备位置（即设备当前附着到哪台基站）的最新信息，才能把数据报转发给该设备。确实，路由器需要为该提供商网络中**所有**设备维护这类信息！有了隧道，只有隧道端点（即 UPF）需要知道设备附着到哪台基站；回传路由器只需知道如何向基站转发与路由数据报。因此在设备附着到 5G 网络的整个期间，UPF 充当把数据报从设备转发到更大因特网（以及反方向）的**锚点**，无论设备在某一时刻恰好附着到哪台基站。

### 7.4.3　用户身份、注册与会话建立

7.3.4 节学过设备如何发现 5G 网络的存在、如何初始附着到基站。回忆在那次初始附着之后，虽然设备与基站能交换控制消息，设备其实还没有真正加入 5G 网络——它尚未与 5G 核心交换控制消息，因而例如还不能经 UPF 收发数据平面数据报。我们从设备如何向网络标识自己开始，讨论设备如何完整加入 5G 网络。

#### 身份：SIM 卡

多数手机用户都知道，4G/5G 设备需要一张物理 **SIM**（用户身份模块）卡，或较新的纯软件 **eSIM**，才能附着到 4G/5G 网络。你的 SIM 向全球所有蜂窝网络提供商唯一标识你本人与你的"归属"网络。在蜂窝网络世界里，你的 SIM 就是你的全球网络身份！

SIM 中包含的信息因提供商而异，但一般包括：

- **IMSI**：国际移动用户身份（International Mobile Subscriber Identity）。一个 IMSI 有三部分：3 位（十进制）的**移动国家码**（MCC）、2 或 3 位的**移动网络码**（MNC），以及**移动用户识别号**（MSIN）。MCC 与 MNC 合起来定义该 SIM 的**归属网络**，即把 SIM 卡提供给你、与你签订订购计划的蜂窝提供商。MSIN 在归属网络内唯一标识该 SIM。你的 SIM 还带有你的蜂窝电话号码，以及你附着到归属网络时能访问的一组蜂窝服务。当你处于归属网络不覆盖的区域时，你可能附着到另一提供商的网络，此时称你在**拜访网络**上**漫游**。你在拜访网络上可用的服务集合可能不同，取决于你与归属网络的订购计划，以及归属网络与拜访网络之间的计费／结算机制。也可能有些网络你就是无法加入，令人十分沮丧。
- SIM 上还存储**密码学密钥与 PIN**。密码学密钥用于设备加入 5G 网络时的鉴别，如下文与第 8 章所述。
- **本地区域身份**（Local Area Identity）信息列出当前与最近拜访过的网络。本地身份用于标识设备在寻求蜂窝网络服务时可能首先尝试的网络。
- SIM 卡上还可能存储通讯录与短信。

#### 加入 5G 网络：注册与会话建立

当设备想加入 5G 网络时，要做两组重要动作。第一是**注册**（registration）：设备向网络标识自己并随后鉴别自己，网络也反向鉴别自己。第二是 **PDU 会话建立**（PDU Session establishment）：为设备分配一个 IP 地址，并在设备与某个 UPF 之间创建一条数据平面路径。"PDU"是"协议数据单元"（Protocol Data Unit）的缩写——3GPP 对"分组"的行话。完成这些步骤之后，设备就完整地附着到网络，可以开工了（在移动中通信）！

注册与会话建立都由 5G 核心中的网元功能完成，其中 AMF 在这一过程中起核心作用。AMF 是唯一直接与基站和设备通信的网元功能，它在 5G 核心内协调鉴别（与 AUSF）与会话建立（与 SMF）。

下面简要考察注册与会话建立涉及的步骤，如图 7.42 所示。

<Figure src="ch07/fig7-42.webp" caption="图 7.42　设备注册与会话建立：设备、基站与核心网元功能之间的交互" />

- **注册**。7.3.4 节学过，设备与基站交换连接建立请求／响应消息，在它们之间建立一条 RAN 信令信道。这次交换之后，基站为该设备选择一个 AMF 实例，并向该 AMF 发送该设备的注册请求。AMF 随后联系设备，请求并接收设备身份信息。如图 7.42 所示，这些信息随后被交给鉴别功能，由后者与设备执行**双向鉴别**；5G 鉴别的讨论推迟到第 8 章详细展开。注意若设备加入的网络不是其归属网络，拜访网络中的本地鉴别功能将作为设备归属网络中鉴别功能的代理，而由后者实际执行鉴别。鉴别成功后，AMF 在本地 UDM 中登记设备的身份与订购服务信息，并向设备返回注册接受消息。
- **会话建立**。设备向 AMF 发送 PDU 会话建立请求，启动建立其数据平面的过程；AMF 随后选择一个 SMF，负责在设备附着网络期间建立并管理设备的数据平面。SMF 经用户数据管理功能核实设备所请求的会话参数是否被允许后，选择一个 UPF 实例，并在设备基站与该 UPF 之间建立设备的隧道。SMF 随后经 AMF 与基站把隧道、IPv4 地址信息以及附加会话信息返回给设备。最后一步是基站与设备交互，配置设备的 RAN 数据平面。完成之后，设备就准备好向因特网发送数据报了！

以上只说明了设备、基站与各网元功能在注册与会话建立中最重要的交互。要指出，策略控制功能与计费功能也参与会话建立，且若需要 IPv6 还需额外的配置步骤。关于该过程的完整讨论，见 [3GPP TS 23.502 2024] 以及图 4.2.2.2.2-1 与 4.3.2.2.1 周围那段（足足 34 页密集的）论述。

## 7.5　移动性

7.2 节讲了无线链路特性与无线网络物理层，7.3 节讲了无线接入网，7.4 节讲了无线核心网，现在把注意力转向无线网络最独特、最有趣的方面之一——支持设备移动性的需要。确实，这个话题如此重要，我们用整整一节来讨论它。7.5.1 节先讨论支持移动设备所带来的挑战以及应对的总体途径。WiFi 天然支持接入点附近的移动，但我们将看到 WiFi（7.5.2 节）只对附近 WiFi WLAN 之间的移动提供有限支持。相比之下，蜂窝网络由于植根于移动电话世界，自最早的日子起就把移动性作为一等"必备"服务"烘焙"进体系结构。7.5.3 节讨论 5G 网络中对移动性的广泛支持。7.5.4 节以对 IETF 过去在非蜂窝 IP 网络内部与之间支持网络层移动性所做努力的评述作结，并探讨这类移动因特网服务为何至今未被部署。

### 7.5.1　移动性原理

#### 什么是"移动性"？

先仔细考虑我们所说的"移动性"到底指什么。假设一台设备在移动中保持"开机"并通信，考虑它在不中断通信（例如维持正在进行的 TCP 连接、且无需显式加入任何新网络）的情况下能移动多"远"。借用域间与域内选路的区分，可以根据设备能否在同一提供商网络内的接入网（如 802.11 WLAN 或 5G RAN）内部及之间、以及多个提供商网络内部及之间移动而不中断正在进行的通信，识别出三种不同的移动性场景。

<Figure src="ch07/fig7-43.webp" caption="图 7.43　设备保持连通性时的各种移动程度" />

- **仅在单一接入网内移动**。在光谱的一端，即图 7.43 的场景 (a)，移动设备只在附着于某个给定接入网时保持通信连通性。在这个场景中，设备在接入网之间移动时必须先断开与一个接入网中基站的连接，再连接到另一个接入网中的新基站。例如，一名学生可能从无线教室网络断开并关掉笔记本电脑或智能手机，走到食堂并在吃饭时连接那里的无线接入网，然后从食堂网络断开并关机，走到图书馆，在学习时连接图书馆的无线网络。此时设备依次关联（加入）每个遇到的无线接入网，随后解除关联（离开）。这种受限的设备移动性完全可以用我们已在 7.3、7.4 节学过的网络机制处理。
- **在单一提供商网络内多个接入网之间移动**。我们对设备移动性的真正兴趣始于情形 (b)：设备在某提供商网络的多个接入网之间移动，同时继续收发 IP 数据报，并维持更高层（如 TCP）连接。这时网络需要提供**切换**（handover）——当设备在 WLAN 或 RAN 之间移动时，把向其转发数据报的责任从一台基站转移到另一台基站。当切换发生在属于单一网络提供商的接入网之间时，该提供商网络自行编排切换。
- **在多个网络提供商之间移动**。当移动设备在多个提供商网络之间漫游时（如图 7.43 场景 (c)），各提供商必须协调切换，以确保正在进行的通信不中断。这种提供商之间的切换显著增加了过程复杂度。

由于场景 (c) 更复杂、且随着蜂窝提供商扩大地理覆盖而较少发生，这里聚焦情形 (b)。关于场景 (c) 的讨论见本书早期版本第 7 章。

#### 移动性：挑战与途径

任何在单一提供商网络的接入网之间支持设备移动性（图 7.43 情形 (b)）的途径，都必须考虑三个根本问题：

- **设备移动性只在链路层支持，还是网络层也参与？** 如果只在链路层支持移动性，设备或许能在无线接入（链路层）网之间移动，但这可能把设备在不中断通信下的移动范围限制在当前子网（4.3 节编址意义上的子网）之内。这是因为在仅有链路层移动性支持时，来自更大因特网、目的地为该设备的入数据报将始终被转发到该子网以交付给设备。我们将在 7.5.2 节看到，这正是企业 WiFi 网络采取的途径。
- 反之，如果要在提供商的**整个**网络中支持设备移动性，就需要网络层（和／或更高层）支持。例如，核心网需要知道移动设备当前附着到哪个具体接入网，以便来自更大因特网的入数据报能被转发到该子网以交付给设备。我们将在 7.5.3 节看到，这正是 5G（以及 3G、4G）蜂窝网络采取的途径。
- **切换为何被发起，由谁发起？** 当设备把接入点从一台基站换到另一台基站时，这个改变最初为何发生？如 7.2 节所见，设备移动时，它与基站之间的无线电信号质量（以及由此决定的分组吞吐量与延迟）会变化，因此设备可能为改善性能而更换接入网。不过网络自身也可能为在接入网之间做负载均衡而选择把设备从一接入网移到另一接入网。WiFi 与 5G 标准并不规定基站用以判定是否执行切换、或选择哪个目标基站的具体算法，这个决定留给网络运营商，并且仍是活跃的研究领域 [Haghrah 2023]。
- 无线设备通常还会测量范围内所有基站的信号质量，并把该信息回报给它当前附着的基站。7.3.5 节学过，在 5G 网络中基站周期性广播参考信号符号，设备根据对这些参考信号的测量周期性上报 4 比特的信道质量指示（CQI）。WiFi 设备测量从各 AP 收到的信号强度，并为每个 AP 返回一个**接收信号强度指示**（RSSI）。这些测量与上报值随后可用于判定是否应把设备切换到另一台基站。设备或网络还可以（例如用机器学习）预测未来的设备移动与无线电信号强度，并主动执行切换，而不只依赖当前测量。执行切换的决定可能主要由设备发起并控制，也可能由网络基站中的控制平面发起并控制。
- **切换如何完成？** 当一台与某基站关联的设备被切换到另一台基站时，必须完成两项重要任务。第一，一台基站中 WLAN 或 RAN 控制平面内关于设备的状态（例如设备的鉴别状态、设备被允许的服务）必须转移到相邻基站。没有这个转移，设备就必须从旧基站解除关联、再与新基站关联。第二，为确保往返移动设备的数据报双向流动不中断，当设备有了新的网络附着点时，必须修改路由器与交换机中的转发表，以重定向往返该设备的数据报。

下面两小节研究机构 WiFi 网络（7.5.2 节）与 5G 蜂窝网络（7.5.3 节）如何应对这些移动性考虑。

### 7.5.2　WiFi 网络中的移动性

IEEE 802.11 WiFi 标准对移动性采取的是明确的**仅链路层**途径，这也许并不奇怪，因为 802.11 是链路层标准。因此，WiFi 移动性只在同一子网（4.3 节编址意义上的子网）内的接入点之间得到支持。

我们在 7.3.2 节（图 7.22）学过，称为基本服务集（BSS）的传统 WiFi 网络含一个 AP 与一个或多个附着的无线设备。图 7.44 展示了**扩展服务集**（Extended Service Set，ESS）的概念，它由多个 BSS（如图中 BSS 2 与 BSS 3）及其一组接入点（图中 AP2 与 AP3）组成。假设 ESS 中每个 AP 使用相同的 SSID，那么从设备角度与从网络层角度看，一个 ESS 在逻辑上都只是一条 WLAN，因为 ESS 中的设备与 AP 处于同一三层子网。确实，在图 7.44 中在 BSS 2 与 BSS 3 之间移动的设备，从网络层角度看甚至不算移动——因为它从未离开自己的子网！IEEE 802.11 标准引入了**快速基本服务集转换**（Fast Basic Service Set Transition，FT），以加速设备在 ESS 内 AP 之间移动时的 802.1X 鉴别，并允许 AP 向设备建议 ESS 内其他可供附着的 AP。

<Figure src="ch07/fig7-44.webp" caption="图 7.44　WiFi：ESS 内的切换" />

除这些 802.11 标准能力之外，大型 WiFi 设备厂商还提供专有解决方案来支持移动性，例如管理 ESS 内两个 AP 之间的设备切换 [Cisco 802.11r 2016]。

### 7.5.3　5G 网络中的移动性

802.11 的移动性完全发生在链路层，而蜂窝 5G 网络中的移动性是一项网络范围的工作，涉及 RAN 与 5G 核心网两者。5G 对设备移动性的广泛支持无疑反映了它植根于移动蜂窝电话世界。最早几代蜂窝网络就提供了呼叫切换，使用户在提供商网络中逐小区移动、以及在从一个提供商网络到另一个提供商网络移动时语音服务不中断。由于移动性在最早期的蜂窝网络体系结构中就被"烘焙"进去，后来各代蜂窝网络加入移动数据服务也就相当自然了。

本小节聚焦 5G 网络中的切换过程。我们将会看到，切换在 RAN 与 5G 核心控制平面内被仔细编排，还涉及设备 RAN 与 5G 核心数据平面的重配置，使它成为一项真正的网络范围活动。

#### 5G 切换

考虑一台活跃的 5G 设备，它当前与某个 RAN 中的一台基站（切换的"源"基站）关联，将被切换到另一个 RAN 中的第二台基站（"目标"基站）。假设该设备是"活跃"的，即它与更大因特网中的某台远程主机有正在进行的 TCP 连接，并有一条经隧道通往其核心中 UPF 的活跃数据平面连接（见 7.4.2 节）。切换之后，设备将与目标基站关联，源基站将释放它一直维护的设备状态，往返设备的数据平面隧道现在终止于第二个 RAN（为简化假设另一端仍为同一个 UPF），并且 5G 核心中所有设备状态都将反映"设备现在位于新加入的基站"这一事实。需要做的改变真多！

图 7.45（改编自 [3GPP TS 23.502 2024] 图 4.9.1.2.2-1 与 [3GPP TS 38.300 2024] 图 9.2.3.2.1-1）说明了切换过程。5G 切换始于 RAN，然后在核心中完成。图 7.45 中大部分切换交互都在控制平面中，但 UPF 与用户所附着基站之间的数据平面隧道也会在此过程中改变。可以识别出 5G 切换的三个不同阶段：

- **做出切换决定**。切换始于 RAN：设备测量它能听到的各基站无线电信道的质量，然后把这些测量报告给源基站。若源基站认为切换可取，它向目标基站发送**切换请求**消息；目标基站随后决定是否接受该切换，并把决定（图 7.45 的例子中是肯定确认）返回给源基站。
- **在基站之间转移设备**。源基站、目标基站与设备随后共同把设备的 RAN 连接从源基站转移到目标基站。这个过程始于源基站发送两条消息：一条给设备的**重配置**消息，一条给目标基站的**转移状态**消息，把设备状态转移给目标基站。设备与目标基站随后可以建立新的 RAN 连接。当设备向目标基站发送**重配置完成**消息、且目标与源基站完成最后一次握手时，过程完成。注意在这个过程中，基站与 UPF 之间隧道的端点保持不变；不过源基站不再经源 RAN 向设备交付数据报，而是开始把目的地为设备的数据报转发给目标基站。目标基站会缓存这些数据报以便稍后交付给设备，从而确保在切换过程中没有目的地为设备的入数据报丢失。
- **在核心中更新设备状态与 UPF 隧道**。切换活动现在转移到核心。目标基站现在完全掌管设备的 RAN 连接，它经 AMF 向 SMF 发信号，表明自己是被切换设备的新基站。SMF 随后向 UPF 发信号，把设备的隧道改为终止于目标基站。UPF 随后向源基站发送一个**数据结束标记**（data-end marker），源基站由此知道设备隧道端点已切换，并通知目标基站。此时目标基站可以把切换期间从源基站转发来的缓存数据报交付给设备。此外，数据报现在将直接从设备的 UPF 流向目标基站。经过一些清理握手之后，切换过程就完成了！

<Figure src="ch07/fig7-45.webp" caption="图 7.45　设备切换：RAN 与核心的动作" />

上面描述看似相当复杂，其实只考虑了最简单的切换场景！一个未涉及的常见场景是：设备为省电而关闭了电台。回忆 7.3 节：在长时间不活动之后，存在比图 7.38 中 DRX 睡眠周期更长的睡眠期。在这些长睡眠期间，设备先进入**空闲**（Idle）态，然后进入**非活动**（Inactive）态。在空闲态，设备必须采取额外步骤在 RAN 中重建其活动存在，然后才能收发用户数据；在非活动态，RAN 与核心中都需要额外的切换步骤。特别地，若设备在空闲或非活动状态下在基站之间移动，5G 核心甚至可能不知道该设备位于哪个 RAN 中。可以用**跟踪区更新**（tracking area update）过程让核心知道设备所在的大致区域，随后核心可以用**寻呼**（paging）过程精确定位设备的 RAN。这些话题超出本书讨论范围，讨论见 [Alsaeedy 2019]。

当设备从一个提供商的移动蜂窝网络 RAN 切换到另一个提供商网络的 RAN 时，会发生更复杂的切换。此时设备所附着的蜂窝提供商发生变化，需要提供商之间的信令；细节见 [3GPP TS 138.300 2024]。

### 7.5.4　因特网移动性

今天传统（非蜂窝）因特网没有任何广泛部署的基础设施来为"移动中"的用户提供我们在 5G 蜂窝网络中所见的那类服务。然而这并不是因为缺少提供这类服务的技术方案！确实，**移动 IP**（Mobile IP）体系结构与协议 [RFC 5944] 早在 25 年前就已在因特网 RFC 中标准化。有兴趣的读者可参阅本书早期版本与 [Perkins 1998] 对移动 IP 的深入论述；研究也在继续，出现了更新、更安全、更一般化的因特网移动性方案 [Venkataramani 2014]。

既然移动 IP 已有技术方案，那么也许是缺少有说服力的商业与用例 [Arkko 2012]，以及蜂窝网络中替代移动性方案的及时、"先动者"式开发与部署，削弱了移动 IP 的部署。回忆 25 年前，3G 蜂窝网络已经提供了移动语音服务（移动用户的"杀手级应用"）的解决方案，并开始了全球移动数据服务的起步。这些服务背后是与归属网络提供商的付费订购模式，以及允许用户从归属网络漫游到拜访网络的提供商间商业协议与支付。传统因特网缺少这样支持漫游的商业基础设施。

今天，移动因特网连通性通过**双技术方案**提供——当我们真正移动、"在路上"时（即图 7.43 移动性光谱的中部与最右端）通过蜂窝网络提供移动服务，当我们静止或在本地移动时（即光谱的中部与最左端）通过 802.11 网络或有线网络提供因特网服务。也许这个我们已经用了 25 年的双技术方案将继续存在到未来。

然而一个无可争辩的事实是：15 年前，通过固定（有线）宽带技术接入因特网的用户数与通过无线技术接入的用户数大致相当；此后两者都在增长，而如今联网的无线用户已是有线用户的五倍。有句话说，顾客"用脚投票"。这也许特别贴切地描述了高度移动的因特网用户所做的选择。

## 7.6　蓝牙、卫星与 IoT 无线网络

前三节主要聚焦 WiFi 与 5G 网络，但它们并不是唯一广泛部署的无线网络类型！本节因此简要介绍另外三类无线网络——蓝牙、卫星与 IoT 无线网络。我们将会看到，由于这些网络提供的服务比 WiFi 与 5G 更专门化，它们的体系结构与协议也有有趣的不同。

### 7.6.1　蓝牙网络

蓝牙网络已迅速成为日常生活的一部分。你可能用过蓝牙网络作为"电缆替代"技术，把计算机与无线键盘、鼠标或其他外设互联；也可能用蓝牙把无线耳机、音箱、手表或健康监测手环连到智能手机，或把智能手机连到汽车音响系统。所有这些情形中，蓝牙都在短距离（几十米或更短）、低功率、低成本下工作。因此蓝牙网络有时被称为**无线个人区域网**（WPAN），或者因其范围有限而称为**微微网**（piconet）。

蓝牙网络虽然按设计小巧相对简单，却打包了我们在前面学过的许多链路级网络技术，包括时分与频分多路复用（6.3.1 节）、随机退避（6.3.2 节）、轮询（6.3.3 节）、差错检测与纠正（6.2 节），以及可靠数据传输与流量控制（第 3 章）。而这还只考虑了蓝牙的链路层！

蓝牙网络工作在免许可的 2.4 GHz 工业、科学与医疗（ISM）射频频段，与微波炉、车库门开启器、无绳电话等家用设备共用。因此蓝牙网络在设计时就明确考虑了噪声与干扰。蓝牙无线信道以 TDM 与 FDM 相结合的方式运行：79 个频率信道，每个信道上 625 微秒的时隙。在每个时隙中，发送方在 79 个信道之一上发送；随后发送方按预定方式在相邻时隙间改变所用信道（频率），如图 7.46 所示。

<Figure src="ch07/fig7-46.webp" caption="图 7.46　蓝牙的跳频随时间变化" />

这种信道跳变形式称为**跳频扩频**（FHSS），其作用是：ISM 频段中工作在某一频率的其他设备所造成的干扰，只会影响蓝牙通信的少数时隙。此外，那些干扰显著（表现为低信噪比）的时隙可以从跳频图案中自适应地剔除。多个蓝牙网络只要使用不同的跳频图案，就可以在同一物理空间共存。蓝牙数据率可达 2 到 3 Mbit/s。

蓝牙网络是**自组织网络**，不需要任何网络基础设施（即基站）。多数使用场景中，蓝牙通信只发生在两台设备之间，例如无线耳机与智能手机之间。但蓝牙标准也允许设备自行组织成网络，因此需要多路访问协议。蓝牙设备自行组织成一个最多八个活跃设备的**微微网**（piconet），如图 7.47 所示。其中一个设备被指定为集中控制器，其余设备充当"外围"角色的客户端。集中控制器节点真正统治着这个微微网——它的时钟决定微微网中的时间（例如决定 TDM 时隙边界），它决定逐时隙的跳频序列，它控制客户端设备进入微微网，它控制外围设备的发送功率（100 mW、2.5 mW 或 1 mW），并且（用轮询方式）在允许某个外围设备入网后授予其发送权限。蓝牙中通信只发生在中心节点与外围节点之间；外围节点之间没有直接通信。

<Figure src="ch07/fig7-47.webp" caption="图 7.47　一个蓝牙微微网" />

由于蓝牙自组织网络必须自组织，值得研究它们如何自举其网络结构。当集中控制器节点想组建一个蓝牙网络时，它必须首先确定范围内还有哪些其他蓝牙设备——这就是**邻居发现**问题。集中控制器通过广播一系列 32 个查询（inquiry）报文来做这件事，每个报文使用不同的频率信道，并把该发送序列重复最多 128 次。客户端设备在自己选定的频率上侦听，希望在这个频率上听到集中控制器的某个查询报文。一旦听到查询报文，它就在 0 到 0.3 秒之间随机退避一段时间（以避免与其他响应节点冲突，令人想起 WiFi 与以太网的二进制退避），然后向集中控制器回送一个含其设备 ID 的报文。

随着蓝牙集中控制器发现范围内的潜在客户端，它随后可以邀请它希望的那些客户端加入其微微网。这第二个阶段称为**蓝牙寻呼**（paging，不要与 5G 网络中的寻呼混淆），令人想起 802.11 客户端与基站关联的过程。集中控制器通过再次发送 32 个相同的寻呼邀请报文来启动寻呼过程，这次每个报文都寻址到某个具体客户端，但仍使用不同频率，因为客户端尚不知道跳频图案。一旦客户端用一个 ACK 报文回应寻呼邀请，集中控制器就向该客户端发送跳频信息、时钟同步信息与一个活跃成员地址；最后它用跳频图案轮询该客户端，以确保客户端已接入网络。

由于蓝牙是为特定、有限的一组服务设计的（不像因特网与 5G 网络），快速看一下其协议栈（图 7.48）很有教益。最引人注目的也许是：蓝牙协议栈既没有网络层，也没有传统的运输层！缺少网络层也许并不奇怪，因为蓝牙网络一般是单跳的，只有"控制器到外围"或"外围到控制器"的传输，因此不必操心多跳转发与选路。基本蓝牙机制的多跳扩展确实存在于蓝牙散射网（Scatternet）以及更近的低功耗网状（Low Energy Mesh）规范中，但这些部署极为有限 [Todtenberg 2019]。因特网的许多端到端运输层服务——包括可靠数据传输、流量控制、分段、面向连接与无连接服务，以及供上层应用使用的 API——在蓝牙的**逻辑链路控制与适配协议**（L2CAP）层中提供。L2CAP 还提供一项为连接的传输预留周期性时隙的服务，这对带宽需求已知、定时固定的多媒体应用很有用。

<Figure src="ch07/fig7-48.webp" caption="图 7.48　蓝牙协议栈" />

今天许多最有用、最重要的智能手机应用都是基于位置的移动应用，包括 Foursquare、Yelp、Uber、Pokémon Go 与 Waze。这些软件应用都使用一个 API，直接从智能手机取得当前地理位置。你是否想过智能手机如何获得地理位置？今天，这是通过组合两个系统完成的：全球定位系统（GPS）与 WiFi 定位系统（WPS）。

GPS 由 30 多颗卫星组成的星座广播卫星位置与定时信息，各 GPS 接收机据此估计自己的地理位置。该系统由美国政府创建、维护，并向任何拥有 GPS 接收机的人免费开放。卫星上装有非常稳定的原子钟，彼此之间以及与地面时钟同步；卫星还极其精确地知道自己的位置。每颗 GPS 卫星持续广播一个含其当前时间与位置的无线电信号。若 GPS 接收机从至少四颗卫星获得这些信息，它就能解三边测量（trilateration）方程来估计自己的位置。

然而，若 GPS 无法与至少四颗卫星保持视距，或受到其他高频通信系统的干扰，它就不能总提供准确的地理位置。城市环境中尤其如此——高楼常常遮挡 GPS 信号。这正是 WiFi 定位系统出手相救之处。WiFi 定位系统利用 WiFi 接入点数据库，这些数据库由 Google、Apple、Microsoft 等多家因特网公司各自独立维护。每个数据库含有数百万个 WiFi 接入点的信息，包括每个接入点的 SSID 与其地理位置的估计值。要理解 WiFi 定位系统如何使用这样的数据库，考虑一台 Android 智能手机与 Google 位置服务。智能手机从附近每个接入点接收并测量信标信号（见 7.3.4 节）的强度，这些信号含接入点的 SSID。因此智能手机可以不断向（云端的）Google 位置服务发送报文，其中含附近接入点的 SSID 及相应信号强度；若有 GPS 位置（经上述卫星广播信号取得），也一并发送。Google 用信号强度信息估计智能手机与各 WiFi 接入点之间的距离，再利用这些估计距离解三边测量方程，估计智能手机的地理位置。最后，把这个基于 WiFi 的估计与基于 GPS 卫星的估计合并成一个综合估计，回送给智能手机，供基于位置的移动应用使用。

但你可能仍想知道 Google（以及 Apple、Microsoft 等）如何获得并维护接入点数据库，尤其是接入点的地理位置？回忆对某个给定接入点，附近每台 Android 智能手机都会向 Google 位置服务发送从该接入点收到的信号强度，以及智能手机自己估计的位置。既然一天之内可能有数千台智能手机路过该接入点，Google 的位置服务就有大量数据可用于（同样通过解三边测量方程）估计该接入点的位置。于是，接入点帮助智能手机确定位置，而智能手机反过来又帮助接入点确定它们的位置！

### 7.6.2　卫星网络

过去 10 年，卫星通信世界发生了剧烈变化。直到 10 年前，已部署的卫星应用主要使用**地球静止轨道**（GEO）卫星。一颗地球静止卫星位于赤道上方约 35 000 公里处，并随地球一起转动，从而相对地球上的观察者始终停留在天空中同一位置。地球静止卫星已使用 60 多年，应用包括广播电视、遥感（例如气象、大气或地表遥感），以及在没有地面因特网覆盖的地区提供因特网连通性 [Hughes 2025]。

然而过去 10 年，人们对另一类卫星网络——**低地球轨道**（LEO）卫星——的兴趣急剧增长。虽然应用仍是那些（特别是遥感与因特网连通性），但 LEO 卫星通常比 GEO 卫星更小、更便宜，且位置离地球近得多。LEO 卫星位于地表上方 500 到 1 200 公里之间，因此往返时延比 GEO 卫星（约 800 毫秒）短得多（约 30 毫秒）。截至 2022 年 11 月，有史以来总共只发射过 6 800 颗活跃卫星；但在短短五年间（2019–2024），仅 Starlink 一家就发射了数量相当（6 281 颗）的 LEO 卫星 [space.com 2024]。今天，所有已发射卫星中远超 90% 是 LEO 卫星。显然，近来人们对 LEO 卫星网络有着巨大的兴趣！

#### LEO 卫星网络体系结构

图 7.49 展示了 LEO 卫星网络的主要组成部分：

- **LEO 卫星**。图 7.49 顶部是运行中的 LEO 卫星网络，常称为卫星**星座**（constellation）。Starlink 报告其星座中有 6 750 多颗卫星；2025 年初 Oneweb 星座中约有 650 颗 LEO 卫星。由于其高度相对较低，LEO 卫星不是地球静止的，而是相对下方地球不断运动，相对地面以 27 000 公里/小时的速度飞行 [Bhattacherjee 2019]。我们将在下面看到，这些高度移动的网络元素把"网络移动性"这一整个话题带向了一个全新方向！
- **卫星链路**。卫星无线收发机在下方的地球上的覆盖区域称为其**足迹**（footprint）。在下行方向，卫星的传输是广播性质的，足迹内所有站点都能收到；在上行方向，足迹内各地面站发往卫星的传输是单播的——一个经典的多路访问信道！典型 LEO 卫星的足迹直径为 15 英里。一个地面站只会在卫星链路波束的足迹中停留约 10 分钟，直到卫星运动使它移出该地面站的视野。你可以在 https://satellitemap.space/ 查看 Starlink 与 Oneweb 星座当前不断变化的足迹（包括你所在地的详情）。卫星之间也可以直接用光学**星间链路**（ISL）相连，尽管这类基础设施链路在实践中尚未广泛使用。
- **地面站**。在地球表面或近地表是收发卫星链路数据报的地面站。这些地面站可能只连到卫星，也可能同时连到卫星与地面因特网——后者情况下地面站充当卫星网络与地面因特网之间的网关。LEO 地面站常有小型碟形或平板天线用于卫星通信。不过，目前某些（Apple）手机已可通过卫星使用低带宽 SOS 紧急短信服务，而通过 LEO 卫星提供更多类 5G 数据服务正在研究之中。

<Figure src="ch07/fig7-49.webp" caption="图 7.49　LEO 卫星网络的组成" />

#### 移动性

LEO 卫星以 27 000 公里/小时在天空中飞驰，而地面站本身也可能在卡车、船只或飞机上移动，因此 LEO 星座是移动性极强的无线网络！不过与 WiFi 和 5G 网络不同，这里"移动性"的主要来源是 LEO 网络基础设施（卫星），而不是用户设备。由于一个地面站只与某颗卫星保持约 10 分钟的附着，**地面站在轨道卫星之间的切换**是常见而重要的事件——一颗卫星移出地面站范围，而其他卫星仍在范围内。近期测量表明，卫星切换远不如 5G 切换成熟，切换期间疑有丢包 [Kassem 2022]。此外，与 5G 网络不同，LEO 卫星网络没有类似蜂窝世界 3GPP 的标准化组织，因此卫星网络实现仍是专有的。

#### 空中的链路，还是空中的网络？

图 7.50 展示了构建卫星网络的两种可能途径。"弯管"（bent pipe）体系结构（图 7.50(a)）把每颗卫星当作一条链路，每条链路两端各有一个地面站。因此端到端路径由一系列单跳卫星链路组成，每一跳之后分组都要从天空回到地面。图 7.50(b) 展示了"空中网络"途径：星间链路（ISL）直接连接卫星，一个分组可以在返回地面之前穿越卫星之间的多跳。注意由于卫星相对地面、相对彼此都非静止，空中网络中的 ISL 链路是动态变化的，这使 LEO 星座中的选路成为一个富有挑战的问题。关于 LEO 星座网络的近期介绍与综述，见 [Bhattacherjee 2019; Al Homssi 2022; Kassem 2022]。

### 7.6.3　物联网（IoT）网络

**物联网**（IoT）[Manyika 2013] 讲的是把设备（往往很小、能量受限）与计算连接起来，以感知、监视、上报并控制物理世界中的现象。多个领域的无数 IoT 应用比比皆是，包括但不限于：(i) 制造业，监测压力、振动、温度、湿度、开关状态与仪表液位等物理特性，并常常随之采取动作；(ii) 物流与供应链，监测并跟踪资产与运输条件；(iii) 农业与环境，监测降雨、温度、风、湿度、动物跟踪／健康与土壤状况，并据此调配资源；(iv) 智慧城市，测量声音、空气、水、天气、照明、交通与人群，监视运输系统与服务，并据此启用／停用服务；(v) 个人健康监测与照护。有人把 IoT 的影响形容得如此普遍、如此深刻，以至于构成第四次工业革命，即"工业 4.0" [Schwab 2016]。到本十年末，已部署的联网 IoT 设备数量将超过 PC、笔记本电脑、平板电脑与手机总和的**三倍以上** [Statista IoT 2025]，IoT 有望很快成为一个 3 000 亿美元的市场 [Schwab 2016]。

有这么多需求各异的应用、这么大的潜在市场，难怪有许多相互竞争的技术争相为 IoT 提供联网服务。我们这里的目标只是概述这些 IoT 无线网络技术（其中若干我们在本章前面已经学过），并提供进一步阅读的线索。

图 7.51（改编自 [Ahmad 2019]）对 IoT 联网技术作了三方面刻画，说明某项具体技术在多大程度上强调覆盖范围、能耗和／或高数据率。图 7.51 中每种技术都强调这三者中的两个，但没有一种三者兼强。这提示 IoT 联网不会出现"赢家通吃"的结果，实践中更可能根据场景采用不同方案。

<Figure src="ch07/fig7-51.webp" caption="图 7.51　IoT 通信技术及其侧重" />

- **强调低能耗与低数据率**。IEEE 802.11ah、低功耗蓝牙（BLE）与 Zigbee 是三种面向短距离覆盖的无线 IoT 技术。IEEE 802.11ah 是 WiFi 的一个"口味"，继承了 WiFi 的大部分体系结构，包括 BSS 结构、信道的概念，以及一个精简的 802.11 帧格式。IEEE 802.11ah 提供数百 kbit/s 到约 5–10 Mbit/s 的数据率；工作在 900 MHz 免许可频段，配合中继，实践中覆盖可达一公里。低功耗蓝牙（BLE）[Sauter 2021] 是对原蓝牙标准的重大扩展，以支持 IoT 设备。我们在 7.6.1 节学过蓝牙网络，并在 7.3.6 节学到 BLE（像 LoRa Class A 与 4G LTE 窄带 IoT 一样）支持由 IoT 设备发起的"唤醒即发"传输。Zigbee [Gomez 2010] 于 1990 年代末推出，是最早的 IoT 联网技术之一，构建在面向低速率无线个人区域网的 IEEE 802.15.4 标准的物理层与 MAC 层之上。
- **强调低能耗与更广覆盖**。LoRaWAN [Jouhari 2023]（Long Range Wide Area Network，远距离广域网）由国际电信联盟（ITU）标准化。我们在 7.3.6 节讲过 LoRaWAN 面向 Class A 设备的节能机制 [Semtech 2019a]，Class B 设备的运行见 [Semtech 2019b]。LoRaWAN 是一个网络范围（而非链路层）的标准，有服务器、网关与 IoT 设备，在 902–928 MHz 免许可频段上每信道数据率从 0.3 kbit/s 到 50 kbit/s。LoRaWAN 网络采用"星中之星"拓扑覆盖广域，每个边缘星形网络中有一个 LoRaWAN 网关作为协调中心节点。4G 窄带物联网（NB-IoT）[Vaezi 2022] 是 3GPP 的 4G 标准，自然含有 4G RAN 的许多体系结构特征，包括基站、用户设备、下行 OFDM 与上行单载波 FDMA——这些我们都在 7.3 节学过。NB-IoT 也支持我们在 7.6.1 节遇到的、由 IoT 设备发起的"唤醒即发"传输。由于信道带宽只有 200 kHz，LTE NB-IoT 的数据率被限制在约 250 kbit/s。
- **强调更广覆盖与更高数据率**。机器型长期演进（LTE-M）是 3GPP 面向 IoT 应用的第二个、功能更完整的 LTE 标准。它支持设备在基站之间移动，信道带宽是 LTE NB-IoT 的 5 倍。与 3GPP 合作制定移动蜂窝网络标准愿景的国际电信联盟（ITU）指出，对 5G 而言，"尽管最初的标准化与商用主要聚焦增强移动宽带，5G 预期将越来越多地使能新的商业模式与无数新用例，特别是大规模机器类通信与超可靠低时延通信"。后两大类通信应用包含 IoT。因此，尽管 5G 标准与部署迄今主要聚焦移动宽带，在 5G 标准内支持 IoT 的工作正在大力推进 [Vaezi 2022; 3GPP TS 38.300 2024]。

## 7.7　小结

无线移动网络最初彻底改变了电话，如今在计算机网络世界中也正产生日益深刻的影响。联网的无线用户已是有线用户的五倍以上，加上随时随地、无拘无束地接入全球网络基础设施，无线网络正提供近乎无处不在的无线因特网连通性，并促成了一组令人兴奋的新移动、位置相关服务。鉴于无线与移动网络的重要性，我们用整整一章（本章）讨论这个主题。

本章从无线与移动网络导论开始，随后自底向上研究其原理与实践。尽管我们强烈偏好自顶向下的教学方法，但我们认为尽早掌握底层无线电信道是理解无线网络几乎其他所有方面的前提。因此 7.2 节从研究无线电信道的独特特性开始深入研究，随后学习比特如何被编码为符号、符号又如何被调制、发送并在该信道上接收。7.3 节转向无线接入网，涵盖共享无线信道、网络发现与设备附着、帧传输调度与节能等技术；在 7.3 节全篇我们用 WiFi 与 5G 网络说明所学原理如何付诸实践。7.4 节讲了移动核心网——蜂窝网络的关键体系结构组件，为全球身份、移动性与服务订购提供支持，而这些服务在传统有线因特网中通常没有。移动性是无线网络如此独特的特征，我们用整整一节（7.5 节）讨论它。本章主要聚焦 5G 与 WiFi 网络，但 7.6 节也简要介绍了另外三种重要的无线网络体系结构——蓝牙、卫星与 IoT 无线网络。

尽管我们用整整一章研究无线与移动网络，要充分探索这个令人兴奋且快速扩张的领域仍需要一整本书（甚至更多）！这个主题本身足以开一门完整的课——本书作者之一确实开了这样一门课 [Kurose 2025]。我们鼓励读者查阅本章提到的众多资源，更深入地钻研这个领域。

今天的因特网大概是有史以来人类建造的最庞大的工程系统：数亿台互联的计算机、通信链路和交换机；数十亿通过笔记本电脑、平板电脑和智能手机上网的用户；还有形形色色的新型联网"物"——游戏机、监控系统、手表、眼镜、恒温器、机器人、汽车，甚至尿布。面对如此庞大、组件如此繁多、用途如此多样的因特网，我们还有希望理解它的工作原理吗？是否存在一些指导性的原理和结构，可以作为理解这样一个惊人庞大而复杂系统的基础？如果有，学习计算机网络是否可能既有趣又好玩？幸运的是，这些问题的答案都是响亮的"是"！本书的目标正是为你提供一个关于计算机网络这一动态领域的现代导论，给你理解今天的网络——以及明天的网络——所需的原理与实践洞见。

本章对计算机网络与因特网作一个全景式概览，目的是描绘一幅宏观图景，为全书设定语境，做到"见森林而不只见树木"。这一导论性章节将涉及大量内容、讨论网络的许多组成部分，同时不迷失大局。

本章的组织方式如下：在介绍一些基本术语和概念之后，先考察构成网络的基本硬件与软件组件——从网络边缘开始，看端系统和运行在其中的网络应用；然后探索计算机网络的核心，考察传输数据的链路与交换机，以及把端系统连接到网络核心的接入网与物理媒体；我们会认识到因特网是"网络的网络"，并了解这些网络如何互连。

完成对网络边缘与核心的概览之后，本章后半部分将采取更宏观、更抽象的视角：考察计算机网络中数据的时延、丢包与吞吐量，并给出端到端吞吐量和时延的简单定量模型（这些模型考虑传输时延、传播时延和排队时延）；随后介绍计算机网络中的若干关键体系结构原理，即协议分层与服务模型；还会了解到计算机网络易受多种攻击，概览其中一些攻击并思考如何使网络更安全；最后以一段简短的计算机网络发展史收束全章。

## 1.1　什么是因特网

本书以公共因特网这一具体的计算机网络作为讨论计算机网络及其协议的主要载体。但"因特网"究竟是什么？回答这个问题有两条路径：一条是描述因特网的**具体构成**，即构成因特网的基本硬件与软件组件；另一条是把因特网描述为一种**为分布式应用提供服务的网络基础设施**。先看具体构成，结合图 1.1 展开讨论。

### 1.1.1　具体构成描述

因特网是一个把全世界数十亿计算设备互连起来的计算机网络。不久之前，这些计算设备主要还是传统的台式机、Linux 工作站，以及存储和传输网页、电子邮件等信息的所谓服务器。但如今越来越多用户通过智能手机和平板电脑上网——今天全球约三分之二的人口是活跃的移动因特网用户 [Statista Users 2024]。此外，电视机、游戏机、恒温器、家庭安防系统、家电、手表、眼镜、汽车、交通控制系统等非传统的联网"物"也正接入因特网。面对这么多接入因特网的非传统设备，"计算机网络"这个词本身都开始显得有些过时了。用因特网的术语说，所有这些设备都称为**主机**（host）或**端系统**（end system）。据估计，2025 年接入因特网的设备约有 190 亿台，到 2030 年将达到 290 亿台 [Statista Connections 2025]。

<Figure src="ch01/fig1-01.webp" caption="图 1.1　因特网的若干组成部分" />

端系统由**通信链路**（communication link）和**分组交换机**（packet switch）构成的网络连接在一起。1.2 节将会看到，通信链路有多种类型，由不同类型的物理媒体构成，包括同轴电缆、铜线、光纤和无线电频谱。不同链路能以不同速率传输数据，链路的传输速率以比特/秒计量。

当一个端系统要向另一个端系统发送数据时，发送端系统把数据**分段**，并为每一段加上首部字节。由此形成的信息包在计算机网络术语中称为**分组**（packet），它们随后通过网络送往目的端系统，在那里被重新组装成原始数据。

**分组交换机**从它的一条入通信链路上接收到达的分组，并从它的一条出通信链路上转发该分组。分组交换机形态各异，但当今因特网中最突出的两类是**路由器**（router）和**链路层交换机**（link-layer switch）。两类交换机都把分组朝着最终目的地转发：链路层交换机通常用于接入网，路由器通常用于网络核心。一个分组从发送端系统到接收端系统所经过的通信链路与分组交换机序列，称为该分组在网络中的**路径**（route 或 path）。

分组交换网（传输分组）在许多方面类似于运输车辆的高速公路、道路和立交桥网络。设想一家工厂要把一大批货物运到数千公里外的目的仓库：在工厂，货物被分装并装上卡车车队；每辆卡车随后独立地经由高速公路、道路和立交桥驶向目的仓库；在目的仓库，货物被卸下并与同批运到的其余货物归并。于是，分组类似于卡车，通信链路类似于高速公路和道路，分组交换机类似于立交桥，端系统类似于建筑物。正如卡车在运输网中选择一条路径，分组也在计算机网络中选择一条路径。

端系统通过**因特网服务提供商**（Internet Service Provider, ISP）接入因特网，包括居民区 ISP（如本地有线电视或电话公司）、公司 ISP、大学 ISP、在机场、酒店、咖啡馆等公共场所提供 WiFi 接入的 ISP，以及为智能手机等设备提供移动接入的蜂窝数据 ISP。每个 ISP 本身就是一个由分组交换机和通信链路构成的网络。ISP 为端系统提供多种类型的网络接入，包括电缆调制解调器或 DSL 这样的居民宽带接入、高速局域网接入以及移动无线接入。ISP 也为内容提供商提供因特网接入，把服务器直接连到因特网上。

因特网的核心就是把端系统彼此连接起来，因此为端系统提供接入的 ISP 之间也必须互连。这些较低层 ISP 通过网络和国际的上层 ISP 互连，而这些上层 ISP 又彼此直接相连。一个上层 ISP 由高速路由器和高速光纤链路互连而成。每个 ISP 网络，无论上层还是低层，都独立管理、运行 IP 协议（见下文），并遵循某些命名与编址约定。1.3 节将更仔细地考察 ISP 及其互连。

端系统、分组交换机以及因特网的其他组成部分都运行**协议**（protocol），这些协议控制因特网中信息的发送与接收。传输控制协议（TCP）和网际协议（IP）是因特网中最重要的两个协议。IP 协议规定了在路由器与端系统之间发送和接收的分组的格式。因特网的主要协议统称为 TCP/IP。本章就开始接触协议——但这只是开始，本书的大部分内容都与网络协议有关！

鉴于协议对因特网的重要性，所有人都必须对"每个协议做什么"达成一致，这样人们才能构建可互操作的系统与产品。这正是**标准**的用武之地。因特网标准由**因特网工程任务组**（Internet Engineering Task Force, IETF）制定 [IETF 2025]。IETF 的标准文档称为**请求评论**（request for comments, RFC）。RFC 最初只是一般意义上的"征求意见"（名字由此而来），用以解决因特网前身所面临的网络与协议设计问题 [Allman 2011]。RFC 往往相当技术化且详尽，它们定义了 TCP、IP、HTTP（用于 Web）、SMTP（用于电子邮件）等协议。目前 RFC 已有近 9000 份。其他机构也为网络组件（尤其是网络链路）制定标准，例如 IEEE 802 局域网标准委员会 [IEEE 802 2025] 就规定了以太网和无线 WiFi 标准。

### 1.1.2　服务描述

上面的讨论指出了构成因特网的许多部件。但我们还可以从完全不同的角度来描述因特网——把它描述为**一种为应用提供服务的基础设施**。除了电子邮件、网页浏览这类传统应用之外，因特网应用还包括移动智能手机与平板应用：即时消息、带实时路况的地图、音乐流媒体、影视流媒体、在线社交媒体、视频会议、多人游戏、基于位置的推荐系统等。这些应用被称为**分布式应用**（distributed application），因为它们涉及多个彼此交换数据的端系统。重要的是，因特网应用运行在**端系统**上——它们不在网络核心的分组交换机中运行。虽然分组交换机为端系统之间的数据交换提供了便利，但它们并不关心作为数据源或数据宿的应用。

再进一步体会"为应用提供服务的基础设施"这一说法。设想你对一个分布式因特网应用有了一个激动人心的新想法——它可能极大地造福人类，也可能只是让你名利双收。你该如何把这个想法变成真正的因特网应用？由于应用运行在端系统上，你需要编写运行在端系统上的程序，比如用 Java、C 或 Python 编写。又因为你在开发分布式因特网应用，运行在不同端系统上的程序需要互相发送数据。于是就来到一个核心问题——正是这个问题引出了把因特网描述为"应用平台"的另一种视角：运行在一个端系统上的程序，如何指示因特网把数据交付给运行在另一个端系统上的程序？

连到因特网上的端系统提供**套接字接口**（socket interface），它规定了运行在一个端系统上的程序如何请求因特网基础设施，把数据交付给运行在另一个端系统上的特定目的程序。这个因特网套接字接口是一组规则，发送程序必须遵守它们，因特网才能把数据交付给目的程序。第 2 章将详细讨论套接字接口，这里先用一个本书中会反复使用的简单类比。

假设 Alice 要用邮政服务给 Bob 寄一封信。Alice 当然不能只写好信（数据）就把它扔出窗外；邮政服务要求她把信装进信封，在信封中央写上 Bob 的全名、地址和邮编，封好信封，在右上角贴邮票，最后把信封投入邮政局的邮筒。可见邮政服务有它自己的"邮政服务接口"，也就是 Alice 必须遵守的一组规则，邮政服务才会把她的信投递给 Bob。与此类似，因特网也有一个套接字接口，发送数据的程序必须遵守它，因特网才会把数据交付给接收数据的程序。

当然，邮政服务向顾客提供的服务不止一种：特快专递、回执、平信等等。与此类似，因特网也向应用提供多种服务。开发因特网应用时，你也必须为你的应用选择因特网的一种服务。因特网的这些服务将在第 2 章描述。

我们刚刚给出了因特网的两种描述：一种着眼于它的硬件与软件组件，另一种着眼于它为分布式应用提供服务的基础设施。但你可能仍然困惑：因特网到底是什么？什么是分组交换和 TCP/IP？什么是路由器？因特网中有哪些通信链路？什么是分布式应用？恒温器或体重秤怎么能连到因特网上？如果你现在感到有点应接不暇，别担心——本书的目的正是把你带入因特网的具体构成，以及支配它"如何工作、为何如此工作"的原理。这些重要术语和问题将在随后各节与各章中逐一解释。

### 1.1.3　什么是协议

对因特网已有了一点感觉之后，再来看计算机网络中另一个重要的术语：**协议**。什么是协议？协议做什么？

#### 一个人类类比

理解计算机网络协议最容易的办法，也许是先看一些人类的类比，因为我们人类无时无刻不在执行协议。想想你想向别人询问时间时会怎么做。图 1.2 给出了一个典型的交互过程。人类协议（至少是良好礼貌）要求先送出一句问候（图 1.2 中的第一个"Hi"），以此发起与他人的通信。对"Hi"的典型回应是回一句"Hi"。隐含地，人们随后把对方友善的"Hi"回应视为"可以继续"的信号，于是提出询问时间。而对最初"Hi"的另一种回应（比如"别烦我！""我不会说英语"，或者某些不便付印的话）则可能表示不愿或无法通信；此时人类协议就是不问时间。有时一个问题完全得不到回应，那通常就放弃向这个人问时间了。

注意，在人类协议中，我们发送**特定的报文**，并在收到回应报文或其他事件（例如在给定时间内没有回应）时采取**特定的动作**。显然，收发的报文、以及在这些报文被发送或接收时（或其他事件发生时）所采取的动作，在人类协议中起着核心作用。如果人们运行不同的协议（例如一个人有礼貌而另一个没有，或一个人理解"时间"的概念而另一个不理解），协议就无法互操作，也就无法完成任何有用的事情。网络中也一样——需要两个（或更多）运行相同协议的通信实体，才能完成一项任务。

再看第二个人类类比。假设你在一堂大学课上（比如计算机网络课！），老师正絮絮叨叨地讲协议，而你一头雾水。老师停下来问："有什么问题吗？"（这是一条发送给所有醒着的学生并被他们接收的报文。）你举手（向老师发送一条隐含的报文）。老师微笑着示意你，说"请讲……"（一条鼓励你提问的报文——老师喜欢被提问），于是你提出问题（把你的报文发送给老师）。老师听到你的问题（接收到你的问题报文）并作答（向你发送一条回应）。我们再次看到，报文的发送与接收、以及在这些报文被发送和接收时所采取的一组约定动作，是这个问答协议的核心。

#### 网络协议

网络协议与人类协议相似，区别在于交换报文并采取动作的实体是某个设备（例如计算机、智能手机、平板电脑、路由器或其他具备联网能力的设备）的硬件或软件组件。因特网中所有涉及两个或多个远程通信实体的活动，都由协议支配。例如，两台物理相连的计算机中由硬件实现的协议，控制着两块网卡之间"线缆"上比特的流动；端系统中的拥塞控制协议控制着发送方与接收方之间分组的发送速率；路由器中的协议决定一个分组从源到目的的路径。协议在因特网中无处不在，因此本书的很大篇幅都在讲计算机网络协议。

举一个你大概已经熟悉的计算机网络协议的例子：当你向 Web 服务器发出请求，也就是在浏览器中输入一个网页的 URL 时，会发生什么？图 1.2 的右半部分描绘了这一场景。首先，你的计算机会向 Web 服务器发送一条连接请求报文，并等待回应。Web 服务器最终收到你的连接请求报文，并返回一条连接响应报文。你的计算机得知现在可以请求 Web 文档了，于是用一条 GET 报文发送它想从该服务器获取的网页名称。最后，Web 服务器把该网页（文件）返回给你的计算机。

从上面的人类与网络例子可以看出，报文的交换、以及在这些报文被发送和接收时所采取的动作，是协议的关键定义要素：

::: info 定义

**协议**定义了在两个或多个通信实体之间交换的报文的**格式**和**次序**，以及发送和/或接收一条报文或其他事件时所采取的**动作**。

:::

因特网乃至一般意义上的计算机网络都大量使用协议，不同的协议用于完成不同的通信任务。随着阅读本书，你会了解到有些协议简单直接，有些则复杂而富有思想深度。掌握计算机网络这一领域，等价于理解网络协议的"是什么、为什么、怎么做"。

## 1.2　网络边缘

上一节对因特网和网络协议作了高层概览，现在深入一些考察因特网的组成部分。本节从**网络边缘**开始，看看我们最熟悉的那些组件——日常使用的计算机、智能手机等设备；下一节再从网络边缘走向**网络核心**，考察计算机网络中的交换与路由。

回忆上一节：在计算机网络术语中，接入因特网的计算机等设备常被称为**端系统**（end system）。之所以叫端系统，是因为它们位于因特网的边缘，如图 1.3 所示。因特网的端系统包括台式计算机（如台式 PC、Mac 和 Linux 机器）、服务器（如 Web 服务器和邮件服务器）以及移动设备（如笔记本电脑、智能手机和平板电脑）。此外，越来越多的非传统"物"正作为端系统接入因特网。

<Figure src="ch01/fig1-03.webp" caption="图 1.3　端系统之间的交互" />

端系统也称为**主机**（host），因为它们承载（即运行）应用程序，例如 Web 浏览器程序、Web 服务器程序、电子邮件客户端程序或电子邮件服务器程序。本书中"主机"与"端系统"两个术语可以互换使用，即 主机 = 端系统。主机有时又进一步分为**客户**（client）与**服务器**（server）两类。粗略地说，客户往往是台式机、笔记本电脑、智能手机等，而服务器往往是更强大的机器，用于存储和分发网页、流式传输视频、中转电子邮件等。今天，我们获得搜索结果、电子邮件、网页、视频和移动应用内容所依托的服务器，大多位于大型**数据中心**（data center）中。例如截至 2024 年底，Google 在四大洲拥有 33 个数据中心 [Google data centers 2024]，合计容纳数百万台服务器。图 1.3 中画出了其中两个数据中心。

<AsideCard title="案例回放 · 数据中心与云计算">

谷歌、微软、亚马逊、阿里巴巴等因特网公司建造了庞大的数据中心，每个数据中心容纳数万到数十万台主机。这些数据中心不仅连到因特网（如图 1.1 所示），其内部还包含复杂的计算机网络，把数据中心内的主机互连起来。数据中心是我们日常使用的因特网应用背后的引擎。

概括地说，数据中心有三重用途（这里以亚马逊为例具体说明）：第一，为用户提供亚马逊电子商务页面，例如产品介绍页和购买信息页；第二，作为大规模并行计算基础设施，承担亚马逊特有的数据处理任务；第三，向其他公司提供**云计算**服务。事实上，当今计算领域的一大趋势，就是公司利用亚马逊这样的云服务商来满足自己几乎全部的 IT 需求。例如，Airbnb 等许多基于因特网的公司并不自建自管数据中心，而是把整套基于 Web 的服务运行在亚马逊云（即 Amazon Web Services，AWS）上。

数据中心里的"工蜂"是主机。它们提供内容（如网页和视频）、存储电子邮件与文档，并协同完成大规模分布式计算。数据中心中的主机称为**刀片**（blade），外形像比萨盒，一般是包含 CPU、内存和磁盘存储的商用主机。主机堆叠在机架中，每个机架通常有 20～40 个刀片；机架之间再用精巧且不断演进的数据中心网络设计互连。数据中心网络将在第 6 章详述。

### 1.2.1　接入网

考察了"网络边缘"的应用与端系统之后，接下来看**接入网**（access network）——把端系统物理连接到其路径上第一个路由器（也称"边缘路由器"）的网络，这个路由器是从该端系统通往任何其他远程端系统的必经之路。图 1.4 用粗阴影线画出了几种典型的接入网，并标出了它们各自的使用场景（家庭、企业、广域移动无线）。

<Figure src="ch01/fig1-04.webp" caption="图 1.4　接入网" />

#### 家庭接入：DSL、电缆、FTTH、固定无线与 LEO 卫星

截至 2023 年，欧美已有超过 80% 的家庭接入因特网 [OECD 2024]，不过世界各地以及不同人群之间仍存在"数字鸿沟" [globaldigitalinclusion 2025]。鉴于家庭接入网如此普及，我们先从家庭如何连入因特网谈起。今天最主流的三种宽带居民接入是**数字用户线**（DSL）、**电缆**和**光纤到户**（FTTH）。

家庭通常从提供本地电话接入的同一家本地电话公司（telco）获得 DSL 因特网接入；因此使用 DSL 时，用户的电话公司同时也是其 ISP。如图 1.5 所示，每个用户的 DSL 调制解调器利用现有的电话线与位于电话公司本地中心局（CO）的**数字用户线接入复用器**（DSLAM）交换数据。家中的 DSL 调制解调器把数字数据转换为高频音调，通过电话线传送到 CO；来自许多家庭的那些模拟信号在 DSLAM 处被转换回数字格式。

<Figure src="ch01/fig1-05.webp" caption="图 1.5　DSL 因特网接入" />

居民电话线同时承载数据和传统电话信号，二者被编码在不同的频段上：

- 高速**下行**信道，位于 50 kHz～1 MHz 频段；
- 中速**上行**信道，位于 4 kHz～50 kHz 频段；
- 普通双向电话信道，位于 0～4 kHz 频段。

这种做法使一条 DSL 链路看起来像是三条独立的链路，于是一通电话和一次因特网连接可以同时共享这条 DSL 链路。（这种**频分复用**技术将在 1.3.1 节描述。）在用户侧，一个分路器把到达家中的数据和电话信号分开，并把数据信号送给 DSL 调制解调器；在电话公司侧，CO 中的 DSLAM 把数据与电话信号分开，并把数据送入因特网。成百上千个家庭连接到同一个 DSLAM。

最新的 DSL 标准 [ITU DSL 2019] 在短距离上可提供最高 1 Gbps 的下行速率和最高 500 Mbps 的上行速率。由于上下行速率不同，这种接入被称为**非对称**的。实际达到的上下行速率可能低于上述数值，因为当提供分级服务（不同速率、不同价格）时，DSL 提供商会刻意限制居民速率；最高速率还受家庭与 CO 之间距离、双绞线线径以及电气干扰程度的限制。工程师设计 DSL 时明确针对家庭到 CO 的短距离；一般说来，若住宅距 CO 超过 5～10 英里，就只能改用其他接入方式。

DSL 利用电话公司现有的本地电话基础设施，而**电缆**因特网接入则利用有线电视公司现有的有线电视基础设施。家庭从提供有线电视的同一家公司获得电缆因特网接入。如图 1.6 所示，光纤把电缆头端连接到社区级的节点，再从这些节点用传统的同轴电缆接到各个家庭和公寓。每个社区节点通常支持 500～5000 户家庭。由于该系统同时使用光纤和同轴电缆，常被称为**混合光纤同轴**（HFC）。

<Figure src="ch01/fig1-06.webp" caption="图 1.6　混合光纤同轴接入网" />

电缆因特网接入需要专门的调制解调器，称为**电缆调制解调器**（cable modem）。与 DSL 调制解调器一样，电缆调制解调器通常是一个外置设备，通过以太网端口与家用 PC 相连。在电缆头端，**电缆调制解调器端接系统**（CMTS）的作用类似于 DSL 网络中的 DSLAM——把许多下游家庭中电缆调制解调器送来的模拟信号转换回数字格式。电缆调制解调器把 HFC 网络划分为下行和上行两个信道。与 DSL 一样，这种接入通常是非对称的，下行信道通常分配更高的传输速率。DOCSIS 2.0 与 3.0 标准分别规定了下行 40 Mbps 和 1.2 Gbps、上行 30 Mbps 和 100 Mbps 的比特率。与 DSL 网络一样，由于签约速率较低或媒体损伤，实际可达到的最高速率未必能实现。

电缆因特网接入的一个重要特点是：它是一种**共享广播媒体**。具体地说，头端发出的每个分组都沿下行链路传到每一户，而每户发出的每个分组都沿上行信道传到头端。因此，如果若干用户同时在下行信道上下载视频文件，每个用户实际获得视频文件的速率将明显低于电缆下行总速率；反之，若只有少数活跃用户且都在浏览网页，每个用户倒可能以完整的电缆下行速率获得网页，因为用户很少恰好在同一时刻请求网页。由于上行信道也是共享的，就需要一种分布式多址访问协议来协调各用户的发送、避免碰撞。（碰撞问题将在第 6 章较详细地讨论。）

尽管 DSL 与电缆网络目前占美国居民宽带接入的多数，一种能提供更高速度的新兴技术——**光纤到户**（FTTH）——正在兴起 [Fiber Broadband 2025]。顾名思义，FTTH 的概念很简单：把一条光纤通路从 CO 直接铺到家庭。FTTH 有潜力提供每秒吉比特量级的因特网接入速率。

从 CO 到各家庭的光分配有若干相互竞争的技术。最简单的光分配网络称为**直接光纤**，即从 CO 到每户各出一条光纤。更常见的是，从中心局引出的每条光纤实际上由许多家庭共享，直到光纤接近家庭时才分成各个用户专用的光纤。实现这种分光的有两种相互竞争的光分配网络架构：**有源光网络**（AON）与**无源光网络**（PON）。AON 实质上就是交换式以太网，将在第 6 章讨论。

这里简要讨论 PON，Verizon 的 FiOS 服务就采用了它。图 1.7 展示了采用 PON 分配架构的 FTTH。每户有一个**光网络终端**（ONT），通过专用光纤连接到社区分光器；分光器把若干户（通常少于 100 户）合并到一条共享光纤上，这条光纤再连到电话公司 CO 中的**光线路终端**（OLT）。OLT 完成光信号与电信号的转换，并通过一台电话公司路由器连到因特网。在用户家中，用户把家用路由器（通常是无线路由器）接到 ONT，并通过该路由器上网。在 PON 架构中，从 OLT 发往分光器的所有分组都在分光器处被复制（类似电缆头端）。

<Figure src="ch01/fig1-07.webp" caption="图 1.7　FTTH 因特网接入" />

**固定无线因特网**（FWI）也已成为一种流行的接入技术。FWI 不仅能提供高速居民接入，而且无需从电话公司 CO 到用户家庭铺设昂贵且易出故障的线缆。使用 5G 固定无线时，借助波束成形技术，数据从运营商基站无线传送到家中的调制解调器；无线路由器与调制解调器相连（二者可能合为一体），这与无线路由器连接电缆或 DSL 调制解调器的方式相似。

除 DSL、电缆、FTTH 和 FWI 之外，**低地球轨道**（LEO）卫星也越来越多地用于宽带接入，尤其是在农村和偏远地区。SpaceX 的 Starlink 等公司部署了庞大的卫星星座，提供高速接入，其信号传播时延远低于地球同步卫星。

#### 以太网与 WiFi

在企业与大学校园，以及越来越多的家庭环境中，使用**局域网**（LAN）把端系统连接到边缘路由器。局域网技术种类繁多，但在企业、大学和家庭网络中，**以太网**是迄今最主流的接入技术。如图 1.8 所示，以太网用户用双绞铜线连接到**以太网交换机**（该技术将在第 6 章详述），以太网交换机（或由若干这类交换机互连而成的网络）再接入更大的因特网。使用以太网接入时，用户到以太网交换机通常有 100 Mbps 到数十 Gbps 的速率，而服务器可能有 1 Gbps 或 10 Gbps 的接入速率。

<Figure src="ch01/fig1-08.webp" caption="图 1.8　以太网因特网接入" />

不过，人们越来越多地用笔记本电脑、智能手机、平板电脑和其他"物"以无线方式接入因特网。在无线局域网场景中，无线用户与**接入点**（access point）之间收发分组，接入点连入企业网络（很可能使用有线以太网），企业网络再连到有线因特网。无线局域网用户通常必须位于接入点几十米范围内。基于 IEEE 802.11 技术的无线局域网接入——更通俗的名称是 WiFi——如今几乎无处不在：大学、办公室、咖啡馆、机场、家庭，甚至飞机上。第 7 章将详细讨论，802.11 目前提供的共享传输速率可超过 100 Mbps。

尽管以太网与 WiFi 接入网最初部署在企业（公司、大学）环境中，如今它们也是家庭网络的常见组成部分。许多家庭把宽带居民接入（即电缆调制解调器或 DSL）与这些廉价的无线局域网技术结合起来，构建功能强大的家庭网络。图 1.9 展示了一个典型的家庭网络：其中包括一台可移动的笔记本电脑、若干联网家电以及一台有线 PC；一个**基站**（即无线接入点），与无线 PC 及家中其他无线设备通信；还有一台**家用路由器**，把无线接入点以及任何其他有线家用设备连到因特网。这个网络让家庭成员都能宽带上网，其中一人还可以从厨房走到后院、再走到卧室而不掉线。

<Figure src="ch01/fig1-09.webp" caption="图 1.9　一个典型的家庭网络" />

#### 广域无线接入：4G 与 5G

iPhone 和 Android 设备等移动设备，被用来在移动中发消息、在社交网络上分享照片和视频、移动支付、看电影、听流媒体音乐、开视频会议等等。这些设备采用与蜂窝电话相同的无线基础设施，通过蜂窝网络运营商运营的基站收发分组。与 WiFi 不同，用户只需位于基站几十公里（而不是几十米）范围内。

电信公司已在所谓**第四代**（4G）无线上投入巨资，其实际下载速度可达 60 Mbps。但速度更高的广域接入技术——**第五代**（5G）广域无线网络——已在部署之中。第 7 章将讲述无线网络与移动性的基本原理，以及 WiFi、4G 和 5G 技术（还有更多内容！）。

### 1.2.2　物理媒体

上一小节概览了因特网中一些最重要的网络接入技术，并在描述这些技术时指出了所用的物理媒体：例如 HFC 使用光纤与同轴电缆的组合，DSL 和以太网使用铜线，移动接入网使用无线电频谱。本小节简要介绍这些以及其他因特网中常用的传输媒体。

为了说明什么是物理媒体，不妨回想一个比特短暂的一生。考虑一个比特从一个端系统出发，经过一系列链路和路由器，到达另一个端系统。这个可怜的比特被踢来踢去、被传输了许许多多次！源端系统先发送该比特，不久后这一串中的第一台路由器收到它；第一台路由器再发送该比特，不久后第二台路由器收到它；如此继续。因此，我们的比特在从源到目的的旅途中，经过了一系列**发送器-接收器对**。对每一对发送器-接收器，该比特都是通过在某种物理媒体上传播电磁波或光脉冲来发送的。

物理媒体可以有许多形态，而且沿路径的每一对发送器-接收器所用的媒体不必相同。物理媒体的例子包括双绞铜线、同轴电缆、多模光纤、陆地无线电频谱和卫星无线电频谱。物理媒体分为两类：**导引型媒体**（guided media）与**非导引型媒体**（unguided media）。在导引型媒体中，波沿固体媒体被导引传播，例如光纤、双绞铜线或同轴电缆；在非导引型媒体中，波在大气层和外层空间中传播，例如无线局域网或数字卫星信道。

在介绍各种媒体的特性之前，先说几句它们的成本。物理链路（铜线、光纤等）本身的实际成本，与其他网络成本相比往往微不足道；特别是安装物理链路的人工成本，可能比材料成本高出几个数量级。正因如此，许多建筑商在楼宇的每个房间都预铺双绞线、光纤和同轴电缆——即便起初只用一种媒体，不久的将来很可能用到另一种，这样就省下了日后重新布线的钱。

#### 双绞铜线

最便宜、最常用的导引型传输媒体是**双绞铜线**。一百多年来，电话网一直在使用它；事实上，从电话听筒到本地电话交换机的有线连接中，99% 以上都使用双绞铜线。我们大多数人在家里（或父母、祖父母家里！）和工作环境中都见过双绞线。双绞线由两根约 1 mm 粗的绝缘铜线组成，按规则螺旋状排列；两根线绞合在一起，是为了减小邻近线对带来的电气干扰。通常把若干线对捆在一起、外面包上保护屏蔽层，构成一根电缆。一对导线构成一条通信链路。**非屏蔽双绞线**（UTP）常用于建筑物内的计算机网络，即局域网。今天使用双绞线的局域网数据速率从 10 Mbps 到 10 Gbps 不等，可达到的速率取决于线径以及收发两端的距离。

20 世纪 80 年代光纤技术出现时，许多人因双绞线比特率相对较低而贬低它，有人甚至认为光纤技术会完全取代双绞线。但双绞线并没有那么轻易认输：现代双绞线技术（例如 6a 类线）在百米距离上可达到 10 Gbps 的数据速率。最终，双绞线成为高速局域网组网的主流方案。

如前所述，双绞线也常用于居民因特网接入：拨号调制解调器技术可在双绞线上提供最高 56 kbps 的接入速率；DSL 技术则使居民用户能在双绞线上以数十 Mbps 的速率接入因特网（前提是用户住得离 ISP 中心局较近）。

#### 同轴电缆

与双绞线一样，同轴电缆也由两根铜导体构成，但这两根导体是同心的而非平行的。凭借这种结构以及特殊的绝缘与屏蔽，同轴电缆可以达到很高的数据传输速率。同轴电缆在有线电视系统中相当普遍。如前所述，有线电视系统近来与电缆调制解调器结合，为居民用户提供数百 Mbps 的因特网接入。在有线电视和电缆因特网接入中，发送器把数字信号搬移到特定频段，由此得到的模拟信号从发送器送往一个或多个接收器。同轴电缆可以用作**导引型共享媒体**：若干端系统可以直接接到电缆上，每个端系统都能收到其他端系统发送的内容。

#### 光纤

光纤是一种细而柔软的媒体，传导光脉冲，每个脉冲表示一个比特。单根光纤可以支撑极高的比特率，可达每秒数十甚至数百吉比特。光纤不受电磁干扰影响，在 100 公里范围内信号衰减极低，而且很难被窃听。这些特性使光纤成为长途导引型传输媒体的首选，尤其是洲际链路。美国及其他许多地区的长途电话网如今已完全使用光纤，光纤在因特网骨干中也十分普遍。然而，光器件（如发送器、接收器和交换机）成本高昂，阻碍了光纤在短途传输中的部署，例如局域网内或居民接入网进户段。**光载波**（OC）标准的链路速率从 51.8 Mbps 到 39.8 Gbps，这些规范常写作 OC-$n$，其中链路速率等于 $n \times 51.8$ Mbps。今天在用的标准包括 OC-1、OC-3、OC-12、OC-24、OC-48、OC-96、OC-192、OC-768。

#### 陆地无线电信道

无线电信道在电磁频谱中承载信号。它是一种有吸引力的媒体：无需铺设任何物理线缆，可以穿墙，能为移动用户提供连通性，并且有潜力把信号传送到很远的地方。无线电信道的特性在很大程度上取决于传播环境和信号需要传输的距离。环境因素决定了**路径损耗**与**阴影衰落**（信号在长距离传播以及绕过/穿过障碍物时强度下降）、**多径衰落**（信号被干扰物反射所致）以及**干扰**（来自其他传输和电磁信号）。

陆地无线电信道大致可分为三类：工作在极短距离（例如一两米）上的；工作在局部区域、通常覆盖十米到数百米的；以及工作在广域、覆盖数十公里的。无线耳机、键盘和医疗设备等个人设备工作在短距离上；1.2.1 节描述的无线局域网技术使用局域无线电信道；蜂窝接入技术使用广域无线电信道。第 7 章将详细讨论无线电信道。

#### 卫星无线电信道

通信卫星连接两个或多个地面微波收发器，即**地面站**。卫星在一个频段上接收传输，用转发器（见下文）再生信号，再在另一个频段上发送信号。通信中使用两类卫星：**地球同步卫星**与**低地球轨道**（LEO）卫星。

地球同步卫星永久停留在距地球表面约 36 000 公里轨道上的同一位置上方。这个从地面站经卫星再回到地面站的巨大距离带来了约 280 毫秒的可观信号传播时延。尽管如此，能以数百 Mbps 速率工作的卫星链路，仍常用于无法获得 DSL 或电缆接入的地区。地球同步卫星也是全球定位系统（GPS）的核心组成部分，许多基于位置的因特网应用都依赖 GPS。

LEO 卫星离地球近得多，不会永久停留在某一地点的上空。它们绕地球旋转（就像月球那样），彼此之间以及与地面站之间都可以通信。与地球同步卫星相比，它们的往返传播时延低得多，约为 10 毫秒。为对某一区域提供连续覆盖，需要在轨道上部署许多卫星。目前有许多低空通信系统正在研发中。LEO 卫星技术正越来越多地用于因特网接入，尤其是在难以用地面通信基础设施覆盖的偏远地区。

### 1.3.1　分组交换

在网络应用中，端系统彼此交换**报文**（message）。报文可以包含应用设计者想要的任何内容：可以执行某种控制功能（例如图 1.2 握手例子中的"Hi"报文），也可以包含数据，例如一封电子邮件、一幅 JPEG 图像或一个 MP3 音频文件。为了从源端系统向目的端系统发送一个报文，源把长报文划分为较小的数据块，称为**分组**（packet）。在源与目的之间，每个分组都经过通信链路和分组交换机（主要有两类：路由器和链路层交换机）传输。分组在每条通信链路上都以等于该链路全部传输速率的速率传输。因此，若源端系统或分组交换机要在一个传输速率为 $R$ 比特/秒的链路上发送一个 $L$ 比特的分组，则该分组的传输时间为 $\frac{L}{R}$ 秒。

#### 存储转发传输

多数分组交换机在链路的输入端采用**存储转发传输**（store-and-forward transmission）。所谓存储转发，是指分组交换机必须接收到整个分组之后，才能开始把该分组的第一个比特发送到出链路上。为深入理解存储转发，考虑一个由一台路由器连接两个端系统的简单网络，如图 1.11 所示。路由器通常有多条相连链路，因为它的职责就是把从入链路到达的分组交换到某条出链路；在这个简单例子中，路由器的任务很简单：把一个分组从一条（输入）链路转移到唯一另一条相连的链路。

<Figure src="ch01/fig1-11.webp" caption="图 1.11　存储转发分组交换" />

在这个例子中，源有三个分组要发往目的地，每个分组 $L$ 比特。在图 1.11 所示的时刻，源已经发出了分组 1 的一部分，分组 1 的前端已经到达路由器。由于路由器采用存储转发，此刻它还不能发送已收到的那些比特，而必须先缓存（即"存储"）该分组的比特；只有收到该分组的全部比特之后，它才能开始把分组发送（即"转发"）到出链路上。

为体会存储转发，计算从源开始发送该分组到目的地收到整个分组所经历的时间。（这里忽略传播时延，即比特以接近光速在导线上传播所需的时间，1.4 节将讨论它。）源在时刻 0 开始发送；在时刻 $\frac{L}{R}$，源已发完整个分组，且整个分组已被路由器接收并存储（因为没有传播时延）。在时刻 $\frac{L}{R}$，路由器刚收完整个分组，于是可以开始把分组发送到通往目的地的出链路上；在时刻 $2 \frac{L}{R}$，路由器已发完整个分组，目的地也收到了整个分组。因此总时延为 $2 \frac{L}{R}$。如果交换机一收到比特就转发（而不必先收完整个分组），那么总时延就只有 $\frac{L}{R}$，因为比特不会在路由器处被耽搁。但正如 1.4 节将要讨论的，路由器需要先接收、存储并处理完整个分组才能转发。

现在计算从源开始发送第一个分组到目的地收到全部三个分组所经历的时间。如前所述，在时刻 $\frac{L}{R}$，路由器开始转发第一个分组；同样在时刻 $\frac{L}{R}$，源也开始发送第二个分组，因为它刚刚发完第一个分组。于是在时刻 $2 \frac{L}{R}$，目的地已收到第一个分组，路由器已收到第二个分组。类似地，在时刻 $3 \frac{L}{R}$，目的地已收到前两个分组，路由器已收到第三个分组。最后，在时刻 $4 \frac{L}{R}$，目的地收到了全部三个分组！

现在考虑一般情形：从源经 $N$ 条速率均为 $R$ 的链路向目的地发送一个分组（因而源与目的之间有 $N - 1$ 台路由器）。套用上面的推理，端到端时延为

$$
d_{\text{端到端}} = N \frac{L}{R} \tag{1.1}
$$

你可以试着自己推导：经 $N$ 条链路发送 $P$ 个分组的时延是多少？

#### 排队时延与丢包

每台分组交换机都连接着多条链路。对每条相连的链路，分组交换机都有一个**输出缓冲区**（output buffer，也称输出队列），用于存储路由器即将发送到该链路的分组。输出缓冲区在分组交换中起着关键作用：如果到达的分组需要发送到某条链路，却发现该链路正在发送另一个分组，这个到达的分组就必须在输出缓冲区中等待。因此，除了存储转发时延之外，分组还要承受**输出缓冲区排队时延**。这些时延是可变的，取决于网络的拥塞程度。由于缓冲空间有限，到达的分组可能发现缓冲区已被其他等待发送的分组完全占满；此时就会发生**丢包**——要么到达的分组被丢弃，要么某个已排队的分组被丢弃。

图 1.12 展示了一个简单的分组交换网。与图 1.11 一样，分组用三维板块表示，板块的宽度代表分组中的比特数；图中所有分组宽度相同，因而长度相同。假设主机 A 和 B 正向主机 E 发送分组：A 和 B 先把分组经 100 Mbps 以太网链路送到第一台路由器，路由器再把这些分组导向 15 Mbps 的链路。如果在某个短时间间隔内，到达路由器的分组速率（折算为比特/秒）超过了 15 Mbps，路由器处就会发生拥塞——分组在该链路的输出缓冲区中排队，等待被发送到链路上。例如，若 A 和 B 同时各背靠背发送五个分组，其中大多数分组都要在队列中等待一段时间。这种情形其实与许多日常场景完全类似——比如我们在银行柜台前排队，或在收费站前排队。1.4 节将更详细地考察排队时延。

#### 转发表与路由协议

前面说过，路由器把从某条相连通信链路到达的分组转发到另一条相连通信链路上。但路由器如何确定应该把分组转发到哪条链路？在不同类型的计算机网络中，分组转发实际上有不同的实现方式。这里简要介绍因特网中的做法。

在因特网中，每个端系统都有一个地址，称为 **IP 地址**。当源端系统要向目的端系统发送分组时，源把目的地的 IP 地址放入分组首部。与邮政地址一样，这个地址具有层次结构。当分组到达网络中的某台路由器时，路由器检查该分组目的地址的一部分，并把分组转发给相邻的一台路由器。更具体地说，每台路由器都有一张**转发表**（forwarding table），把目的地址（或目的地址的一部分）映射到该路由器的出链路。分组到达路由器时，路由器检查地址并用该目的地址在转发表中查找合适的出链路，然后把分组导向该出链路。

这个端到端路由过程类似于一位不用地图、而宁愿问路的司机。假设 Joe 要从费城开车去佛罗里达州奥兰多的湖滨大道 156 号。Joe 先开到附近的加油站，问怎么去佛罗里达州奥兰多的湖滨大道 156 号。加油站店员提取出地址中"佛罗里达"这一部分，告诉 Joe 他需要上 95 号州际公路南行，入口就在加油站旁边；还告诉他，进了佛罗里达之后再问别人。Joe 沿 95 号公路南行到佛罗里达的杰克逊维尔，在那里又问了一位加油站店员。店员提取出地址中"奥兰多"这一部分，告诉 Joe 继续沿 95 号公路到代托纳比奇，然后再问别人。到了代托纳比奇，又一位加油站店员同样提取"奥兰多"部分，告诉 Joe 直接走 4 号公路去奥兰多。Joe 沿 4 号公路在奥兰多出口下高速，再找一位加油站店员，这次店员提取出"湖滨大道"部分，告诉他走哪条路能到湖滨大道。到了湖滨大道，Joe 问一个骑自行车的孩子怎么到目的地，孩子提取出"156 号"部分，指了指那栋房子。Joe 终于到达了最终目的地。在这个类比中，加油站店员和骑车的孩子就相当于路由器。

我们刚刚了解到，路由器用分组的目的地址来索引转发表，从而确定合适的出链路。但这句话又引出另一个问题：转发表是怎么设置出来的？是在每台路由器上手工配置，还是因特网采用了更自动化的办法？这个问题将在第 5 章深入研究。这里先吊吊胃口：因特网有若干特殊的**路由协议**（routing protocol），用于自动设置转发表。例如，路由协议可以确定从每台路由器到每个目的地的最短路径，并用这些最短路径结果来配置各路由器的转发表。

### 1.3.2　电路交换

通过网络中的链路和交换机移动数据有两种基本方式：**电路交换**（circuit switching）与**分组交换**（packet switching）。上一小节讨论了分组交换网，现在转向电路交换网。

在电路交换网中，端系统之间通信会话期间所需沿路径的资源（缓冲区、链路传输速率）是**预留**给该会话的；而在分组交换网中，这些资源并不预留——会话的报文按需使用资源，因而可能不得不等待（即排队）才能使用某条通信链路。打个简单的比方：两家餐厅，一家需要预订，另一家既不要求也不接受预订。对需要预订的餐厅，我们得在出门前费事打个电话；但到了餐厅，原则上就可以立即入座点菜。对不要求预订的餐厅，我们不必费心订位；但到了餐厅，可能得等一会儿才有座位。

传统电话网就是电路交换网的例子。考虑一个人要通过电话网向另一个人发送信息（语音或传真）时会发生什么。在发送方能够发送信息之前，网络必须在发送方与接收方之间建立一条**连接**。这是一条名副其实的连接，发送方与接收方之间路径上的交换机要为该连接维护连接状态。用电话业的术语说，这条连接称为**电路**（circuit）。网络建立电路时，还会在该连接的持续期内，在网络各链路中预留一个恒定的传输速率（相当于每条链路传输容量的一部分）。由于已经为这条发送方到接收方的连接预留了给定的传输速率，发送方就能以有保证的恒定速率向接收方传送数据。

图 1.13 展示了一个电路交换网。图中四台电路交换机由四条链路互连，每条链路有四条电路，因此每条链路可支持四个同时的连接。各主机（例如 PC 和工作站）分别直接连到其中一台交换机上。当两台主机要通信时，网络在两者之间建立一条专用的端到端连接。因此，为使主机 A 与主机 B 通信，网络必须先在两条链路上各预留一条电路。在这个例子中，这条专用端到端连接使用第一条链路上的第二条电路和第二条链路上的第四条电路。

<Figure src="ch01/fig1-13.webp" caption="图 1.13　由四台交换机和四条链路构成的简单电路交换网" />

由于每条链路有四条电路，对端到端连接所用的每条链路而言，该连接在连接持续期内获得该链路总传输容量的四分之一。于是，例如若相邻交换机之间每条链路的传输速率是 1 Mbps，则每条端到端电路交换连接获得 250 kbps 的专用传输速率。

相比之下，考虑一台主机要通过因特网这样的分组交换网向另一台主机发送分组。与电路交换一样，分组也经一系列通信链路传输；但与电路交换不同的是，分组被送入网络时**不预留任何链路资源**。如果某条链路因为此刻还有其他分组要传输而发生拥塞，该分组就不得不在该传输链路发送侧的缓冲区中等待，从而承受时延。因特网尽最大努力及时交付分组，但不作任何保证。

#### 电路交换网中的多路复用

一条链路中的电路，用**频分复用**（FDM）或**时分复用**（TDM）来实现。使用 FDM 时，链路的频谱被划分给建立在该链路上的各个连接：具体地说，链路在连接持续期内为每个连接专门分配一个频段。在电话网中，这个频段通常宽 4 kHz（即 4000 赫兹或每秒 4000 个周期）。这个频段的宽度顺理成章地称为**带宽**（bandwidth）。调频广播电台也用 FDM 共享 88 MHz 到 108 MHz 之间的频谱，每个电台分配一个特定频段。

对 TDM 链路，时间被划分为固定时长的**帧**，每帧又被划分为固定数目的**时隙**。当网络在某条链路上建立一条连接时，网络在每一帧中为该连接专门分配一个时隙；这些时隙专供该连接使用，每帧中有一个时隙可用来传输该连接的数据。

图 1.14 说明了支持最多四条电路的一条特定网络链路上的 FDM 与 TDM。对 FDM，频域被划分为四个频段，每个带宽 4 kHz；对 TDM，时域被划分为帧，每帧四个时隙，每条电路在循环的 TDM 帧中被分配同一个专用时隙。对 TDM，一条电路的传输速率等于帧速率乘以每时隙的比特数。例如，若链路每秒传输 8000 帧、每时隙 8 比特，则每条电路的传输速率为 64 kbps。

<Figure src="ch01/fig1-14.webp" caption="图 1.14　FDM 下每条电路连续获得一部分带宽；TDM 下每条电路在短暂的间隔（即时隙）内周期性地获得全部带宽" />

分组交换的支持者一直认为电路交换是浪费的，因为专用电路在静默期处于空闲状态。例如，在通话中一个人不说话时，空闲的网络资源（连接路径上各链路的频段或时隙）不能被其他正在进行的连接使用。再看一个资源利用不足的例子：一位放射科医生使用电路交换网远程访问一系列 X 光片——他建立连接、请求一幅图像、端详图像，然后再请求下一幅。在医生端详图像期间，分配给该连接的网络资源被闲置（即被浪费）了。分组交换的支持者还乐于指出：建立端到端电路并预留端到端传输容量很复杂，需要复杂的信令软件来协调端到端路径上各交换机的动作。

在结束电路交换的讨论之前，做一个数值例题，进一步加深理解。

::: example 示例

考虑在一个电路交换网上把 640 000 比特的文件从主机 A 发送到主机 B 需要多长时间。假设网络中所有链路都采用 24 个时隙的 TDM，比特率为 1.536 Mbps；并假设主机 A 开始发送文件之前，建立端到端电路需要 500 毫秒。发送该文件需要多长时间？

每条电路的传输速率为 $1.536 \frac{\text{Mbps}}{24} = 64$ kbps，因此发送该文件需要 $640 \, 000 \frac{\text{比特}}{64} \text{kbps} = 10$ 秒。再加上电路建立时间，共需 10.5 秒。注意，**传输时间与链路数目无关**：无论端到端电路经过一条链路还是一百条链路，传输时间都是 10 秒。（实际的端到端时延还包括传播时延，见 1.4 节。）

:::

#### 分组交换与电路交换的比较

描述了电路交换与分组交换之后，来比较二者。分组交换的批评者常常认为，分组交换不适合实时服务（例如电话和视频会议），因为它的端到端时延可变且不可预测（主要源于可变且不可预测的排队时延）。分组交换的支持者则认为：(1) 它比电路交换能更好地共享传输容量；(2) 它比电路交换更简单、更高效、成本更低。关于分组交换与电路交换之争的有趣讨论见 [Molinero-Fernandez 2002]。一般说来，不喜欢为订餐位费事的人，会更喜欢分组交换而不是电路交换。

分组交换为什么更高效？看一个简单例子。假设用户共享一条 1 Mbps 的链路，每个用户在活动期与静默期之间交替：活动期以 100 kbps 的恒定速率产生数据，静默期不产生数据；又假设某用户只有 10% 的时间是活动的（其余 90% 的时间在悠闲地喝咖啡）。采用电路交换时，必须始终为每个用户预留 100 kbps。例如采用电路交换的 TDM，若把 1 秒的帧划分为 10 个各 100 毫秒的时隙，则每个用户每帧分配一个时隙。

于是，这条电路交换链路只能支持 $1 \frac{\text{Mbps}}{100} \text{kbps} = 10$ 个同时用户。采用分组交换时，某特定用户处于活动状态的概率为 0.1（即 10%）。如果有 35 个用户，则同时有 11 个或更多用户活动的概率约为 0.0004。（习题 P8 给出了该概率的推导。）当同时活动的用户不超过 10 个时（这种情况发生的概率为 0.9996），数据的总到达速率不超过链路的输出速率 1 Mbps，于是用户的报文分组基本上无时延地流过链路，与电路交换的情形一样。当同时活动的用户超过 10 个时，分组的总到达速率超过链路的输出能力，输出队列开始增长（一直增长到总输入速率回落到 1 Mbps 以下，此时队列长度才开始减少）。由于本例中同时活动用户超过 10 个的概率微乎其微，分组交换提供的性能与电路交换基本相同，却能支持三倍以上的用户数。

再看第二个简单例子。假设有 10 个用户，其中一个突然产生 1000 个 1000 比特的分组，而其他用户保持静默、不产生分组。在每帧 10 个时隙、每时隙 1000 比特的 TDM 电路交换下，该活动用户每帧只能使用自己的一个时隙来传数据，其余九个时隙空着；要等 10 秒，该用户的一百万比特数据才能全部发完。而在分组交换下，由于没有其他用户的分组需要与该用户的分组复用，该活动用户可以以 1 Mbps 的完整链路速率连续发送，其全部数据将在 1 秒内发完。

上述例子说明了分组交换性能优于电路交换的两种情形，也凸显了二者在"如何共享链路传输速率"上的关键差别：电路交换不管需求如何都**预先分配**链路的使用权，已分配但不需要的链路时间被白白浪费；分组交换则**按需分配**链路使用权，链路传输容量只在那些确有分组需要在该链路上传输的用户之间，以分组为单位共享。

尽管分组交换与电路交换在当今电信网中都十分普遍，但趋势无疑是朝着分组交换方向发展。甚至今天许多电路交换电话网也在缓慢向分组交换迁移，尤其是电话网常常在通话的昂贵洲际段使用分组交换。

### 1.3.3　网络的网络

前面看到，端系统（PC、智能手机、Web 服务器、邮件服务器等）通过**接入 ISP** 连入因特网。接入 ISP 可以提供有线或无线连接，使用 DSL、电缆、FTTH、Wi-Fi 和蜂窝等一整套接入技术。注意，接入 ISP 不必是电话公司或有线电视公司，它也可以是一所大学（为学生、教职工提供因特网接入），或一家公司（为员工提供接入）。但是，把终端用户和内容提供商连到接入 ISP，只是"连接构成因特网的数十亿端系统"这一难题的一小部分。要解完这道题，接入 ISP 之间必须互连——办法就是构建一个**网络的网络**（network of networks）。理解这个短语，是理解因特网的关键。

多年来，构成因特网的"网络的网络"已演化为一个非常复杂的结构。这种演化在很大程度上由经济与国家政策驱动，而不是出于性能考虑。为理解今天因特网的网络结构，我们逐步构建一系列网络结构，每一个新结构都是对今天这个复杂因特网的更好近似。记住总体目标：把各接入 ISP 互连起来，使所有端系统都能互相发送分组。一种朴素的做法是让每个接入 ISP 与其他所有接入 ISP 直接相连。这种网状设计对接入 ISP 来说当然太昂贵了，因为它要求每个接入 ISP 都与全世界几十万个其他接入 ISP 各有一条单独的通信链路。

我们的第一个网络结构——**网络结构 1**——用单个**全球传输 ISP** 互连所有接入 ISP。我们（想象中）的全球传输 ISP 是一个由路由器和通信链路构成的网络，它不仅覆盖全球，而且在几十万个接入 ISP 附近至少各有一台路由器。当然，全球 ISP 要建设如此庞大的网络，代价极其高昂。为了盈利，它自然会向每个接入 ISP 收取连通性费用，其定价反映（但不必正比于）该接入 ISP 与全球 ISP 交换的流量。由于接入 ISP 向全球传输 ISP 付费，接入 ISP 被称为**客户**，全球传输 ISP 被称为**提供商**。

现在，如果某家公司建设并运营一个盈利的全球传输 ISP，那么其他公司自然也会建设自己的全球传输 ISP 与原公司竞争。这就导致**网络结构 2**：由几十万个接入 ISP 和多个全球传输 ISP 构成。接入 ISP 当然更喜欢网络结构 2 而不是网络结构 1，因为它们现在可以根据价格和服务，在相互竞争的全球传输提供商之间做选择。不过要注意，这些全球传输 ISP 之间也必须互连；否则，连到某个全球传输提供商上的接入 ISP 就无法与连到其他全球传输提供商上的接入 ISP 通信。

刚描述的网络结构 2 是一个两层层次结构：全球传输提供商位于顶层，接入 ISP 位于底层。这假定全球传输 ISP 不仅能靠近每一个接入 ISP，而且认为这样做在经济上可取。现实中，虽然有些 ISP 确实拥有可观的全球覆盖、并与许多接入 ISP 直接相连，但没有哪家 ISP 在世界上每一座城市都有存在点。于是，在任一地区，可能存在一个**区域 ISP**（regional ISP），该地区的接入 ISP 都连到它上面；每个区域 ISP 再连到**第一层 ISP**（tier-1 ISP）。第一层 ISP 类似于我们（想象中）的全球传输 ISP，但真实存在的第一层 ISP 并没有在世界上每座城市都有存在点。这样的第一层 ISP 大约有十几家，包括 Level 3 Communications、AT&T、Sprint 和 NTT。有趣的是，并没有哪个组织正式认定"第一层"身份；俗话说得好——如果你还得问自己是不是某个圈子的成员，那你多半不是。

回到这个网络的网络：不仅存在多个相互竞争的第一层 ISP，一个区域内也可能有多个相互竞争的区域 ISP。在这样的层次结构中，每个接入 ISP 向它所连的区域 ISP 付费，每个区域 ISP 向它所连的第一层 ISP 付费（接入 ISP 也可以直接连到第一层 ISP，此时它向第一层 ISP 付费）。于是，层次结构的每一层都存在客户-提供商关系。注意，第一层 ISP 不向任何人付费，因为它们位于层次结构的顶端。更复杂的是，在某些地区，可能还有一个更大的区域 ISP（可能覆盖整个国家），该地区较小的区域 ISP 连到它上面，这个更大的区域 ISP 再连到第一层 ISP。例如在中国，每个城市都有接入 ISP，它们连到省级 ISP，省级 ISP 再连到国家级 ISP，国家级 ISP 最终连到第一层 ISP [Tian 2012]。我们把这种多级层次结构称为**网络结构 3**，它仍然只是对今天因特网的一个粗略近似。

要构建一个更接近今天因特网的网络，必须在层次化的网络结构 3 上加入**存在点**（PoP）、**多宿**（multi-homing）、**对等**（peering）和**因特网交换点**（IXP）。PoP 存在于层次结构的所有层级（接入 ISP 这一底层除外）。PoP 就是提供商网络中的一组（位于同一地点的）路由器，客户 ISP 可以在那里接入提供商 ISP。客户网络要连到提供商的 PoP，可以向第三方电信提供商租用一条高速链路，把它自己的一台路由器直接连到 PoP 中的一台路由器上。任何 ISP（第一层 ISP 除外）都可以选择**多宿**，即连到两个或更多提供商 ISP 上。例如，一个接入 ISP 可以与两个区域 ISP 多宿，也可以同时与两个区域 ISP 和一个第一层 ISP 多宿；同样，一个区域 ISP 可以与多个第一层 ISP 多宿。ISP 多宿之后，即使其中一个提供商发生故障，它仍能继续在因特网中收发分组。

如我们刚刚所学，客户 ISP 向提供商 ISP 付费以获得全球因特网互连。客户 ISP 向提供商 ISP 支付的金额，反映它与该提供商交换的流量。为降低这些费用，层次结构中同一层级的两个邻近 ISP 可以**对等**，即把它们的网络直接连接起来，使两者之间的所有流量都经过这条直连链路，而不经过上游中间商。两个 ISP 对等时，通常**不结算费用**（settlement-free），即双方互不付费。如前所述，第一层 ISP 之间也互相对等，且不结算费用。关于对等与客户-提供商关系的通俗讨论，见 [Van der Berg 2008]。沿着同样的思路，第三方公司可以建立**因特网交换点**（IXP），即多个 ISP 可以在此对等的会合点。IXP 通常设在一栋独立建筑中，配有自己的一套交换机 [Ager 2012]。今天因特网中有 600 多个 IXP [PeeringDB 2025]。我们把由接入 ISP、区域 ISP、第一层 ISP、PoP、多宿、对等和 IXP 构成的这个生态系统称为**网络结构 4**。

最后终于来到**网络结构 5**，它描述了今天的因特网。如图 1.15 所示，网络结构 5 在网络结构 4 的基础上增加了**内容提供商网络**（content-provider network）。谷歌目前是这类内容提供商网络的领先例子之一。谷歌在北美、欧洲、亚洲和南美分布着 20 多个主要数据中心 [Google datacenters 2024]，每个数据中心有数万到数十万台服务器；此外还有较小的数据中心，各有几百台服务器，这些小数据中心往往就设在 IXP 内。谷歌的所有数据中心都通过其专用的 TCP/IP 网络互连，该网络覆盖全球，却与公共因特网相分离。重要的是，谷歌专用网络只承载进出谷歌服务器的流量。图 1.15 展示了截至 2024 年谷歌的全球云网络 [Google Cloud 2025]。

<Figure src="ch01/fig1-15.webp" caption="图 1.15　谷歌云站点与网络" />

如图 1.16 所示，谷歌专用网络试图"绕过"因特网的上层，办法是与较低层 ISP 对等（不结算费用），或与其直接相连，或在 IXP 处与其相连 [Labovitz 2010]。然而，由于许多接入 ISP 仍只能通过穿越第一层网络才能到达，谷歌网络也连到第一层 ISP，并为与它们交换的流量付费。通过建立自己的网络，内容提供商不仅减少了向上层 ISP 支付的费用，还能更好地控制其服务最终如何交付给终端用户。截至 2020 年，云服务商 Amazon、Google、IBM 和 Microsoft 合计能够在不经过第一层 ISP 的情况下到达 76% 的因特网 [Arnold 2020]。

总之，今天的因特网——一个网络的网络——是复杂的，由十几家第一层 ISP 和几十万家较低层 ISP 构成。这些 ISP 的覆盖范围各不相同：有的跨越多个大洲和大洋，有的只限于狭小的地理区域。较低层 ISP 连到较高层 ISP，较高层 ISP 之间互连。用户和内容提供商是较低层 ISP 的客户，较低层 ISP 又是较高层 ISP 的客户。近年来，大型内容提供商也建立了自己的网络，并尽可能直接连入较低层 ISP。

## 1.4　分组交换网中的时延、丢包与吞吐量

1.1 节说过，因特网可以看作一种为运行在端系统上的分布式应用提供服务的基础设施。理想情况下，我们希望因特网服务能在任意两个端系统之间，以任意大的数据量、瞬时且无任何丢失地传送数据。可惜这是个崇高的目标，现实中无法实现。计算机网络必然限制端系统之间的**吞吐量**（每秒可传送的数据量），在端系统之间引入**时延**，并且确实可能**丢失分组**。一方面，现实物理规律带来时延与丢包、限制吞吐量，这确实令人遗憾；另一方面，正因为计算机网络有这些问题，围绕"如何应对这些问题"才产生了大量引人入胜的课题——多到足以支撑一门计算机网络课程，也足以激励成千上万篇博士论文！本节开始考察并定量描述计算机网络中的时延、丢包与吞吐量。

### 1.4.1　分组交换网中的时延概述

回忆一下，一个分组从源主机出发，经过一系列路由器，最终到达目的主机。当分组沿这条路径从一个节点（主机或路由器）行进到下一个节点时，它在这条路径上的每个节点都要承受几种不同类型的时延。其中最重要的有**节点处理时延**、**排队时延**、**传输时延**和**传播时延**，它们累加起来构成总的**节点时延**。许多因特网应用——如搜索、网页浏览、电子邮件、地图、即时消息和 IP 电话——的性能都深受网络时延的影响。要深入理解分组交换与计算机网络，就必须理解这些时延的性质与重要性。

<Figure src="ch01/fig1-17.webp" caption="图 1.17　路由器 A 处的节点时延" />

#### 时延的类型

结合图 1.17 来考察这些时延。作为端到端路由的一部分，一个分组从上游节点经路由器 A 发往路由器 B，我们要刻画路由器 A 处的节点时延。注意路由器 A 有一条通往路由器 B 的出链路，这条链路前面有一个**队列**（也称缓冲区）。当分组从上游节点到达路由器 A 时，A 检查该分组的首部以确定合适的出链路，然后把分组导向该链路——本例中就是通往 B 的那条。一个分组只有在链路上当前没有其他分组正在传输、且队列中没有其他分组排在它前面时，才能在该链路上传输；如果链路正忙，或者已有其他分组在排队等待该链路，新到达的分组就加入队列。

**处理时延。** 检查分组首部并确定把分组导向何处所需的时间，是处理时延的一部分。处理时延还可能包括其他因素，例如检查从上游节点传到路由器 A 的过程中是否出现比特级差错所需的时间。高速路由器中的处理时延通常在微秒或更小的量级。经过这一节点处理后，路由器把分组导向通往 B 的链路之前的队列。（第 4 章将研究路由器如何工作的细节。）

**排队时延。** 在队列中，分组等待被发送到链路上，因而经历排队时延。某个特定分组的排队时延长短，取决于队列中在它之前到达、正在等待传输的分组数目。如果队列为空且当前没有其他分组在传输，则该分组的排队时延为零；反之，如果流量很大、许多分组都在等待传输，排队时延就会很长。稍后会看到，一个到达分组可能遇到的分组数目，是到达队列的流量的强度与性质的函数。实践中排队时延的量级可从微秒到毫秒。

**传输时延。** 假设分组按先到先服务的方式传输（分组交换网中通常如此），则我们的分组只有在它之前到达的所有分组都传输完毕之后才能被传输。记分组长度为 $L$ 比特，路由器 A 到 B 的链路传输速率为 $R$ 比特/秒。例如对 10 Mbps 以太网链路，$R = 10$ Mbps；对 100 Mbps 以太网链路，$R = 100$ Mbps。传输时延为 $\frac{L}{R}$，即把该分组的全部比特推入（即传输到）链路所需的时间。实践中传输时延的量级通常也是微秒到毫秒。

**传播时延。** 一个比特被推入链路之后，还需要传播到路由器 B。从链路起点传播到路由器 B 所需的时间就是传播时延。比特以链路的传播速度传播，该速度取决于链路的物理媒体（即光纤、双绞铜线等），在 $2 \times 10^{8}$ 米/秒到 $3 \times 10^{8}$ 米/秒之间，等于或略小于光速。传播时延等于两台路由器之间的距离除以传播速度，即 $\frac{d}{s}$，其中 $d$ 是路由器 A 与 B 之间的距离，$s$ 是链路的传播速度。一旦分组的最后一个比特传播到节点 B，该比特及其前面的所有比特都存储在路由器 B 中，整个流程继续，由 B 执行转发。在广域网中，传播时延的量级为毫秒。

#### 传输时延与传播时延的比较

初学计算机网络的人有时难以理解传输时延与传播时延的区别。这个区别很细微，却很重要。**传输时延**是路由器把分组推出所需的时间，它是分组长度与链路传输速率的函数，与两台路由器之间的距离毫无关系；**传播时延**则是一个比特从一台路由器传播到下一台路由器所需的时间，它是两台路由器之间距离的函数，与分组长度和链路传输速率毫无关系。

一个类比有助于澄清传输时延与传播时延的概念。考虑一条每隔 100 公里设一个收费站的公路，如图 1.18 所示。可以把收费站之间的路段看作链路，把收费站看作路由器。假设汽车在公路上以 100 公里/小时的速度行驶（即汽车离开收费站时瞬时加速到 100 公里/小时，并在两个收费站之间保持该速度）。再假设 10 辆汽车组成一个车队、以固定次序前后相随行驶：可以把每辆汽车看作一个比特，把整个车队看作一个分组。还假设每个收费站服务（即"传输"）一辆汽车的速率是每 12 秒一辆，而且时值深夜，公路上只有这个车队的车。最后假设车队的头一辆车到达收费站时，要在入口处等到其余九辆车都到达并在它后面排好队（也就是说，整个车队必须先"存储"在收费站，然后才能开始转发）。收费站把整个车队推上公路所需的时间为 $10 \frac{\text{辆}}{5 \text{辆/分钟}} = 2$ 分钟，这个时间相当于路由器中的**传输时延**。一辆汽车从一个收费站出口行驶到下一个收费站所需的时间为 $100 \frac{\text{公里}}{100 \text{公里/小时}} = 1$ 小时，这个时间相当于**传播时延**。因此，从车队在某个收费站前完成"存储"到车队在下一个收费站前完成"存储"，所需时间是传输时延与传播时延之和——本例中为 62 分钟。

<Figure src="ch01/fig1-18.webp" caption="图 1.18　车队类比" />

再深入一点。如果收费站服务一个车队的时间大于汽车在两个收费站之间行驶的时间，会怎样？例如假设汽车以 1000 公里/小时行驶，而收费站每分钟服务一辆汽车，则两个收费站之间的行驶时延是 6 分钟，而服务一个车队需要 10 分钟。此时，车队的前几辆车会在车队的后几辆车尚未离开第一个收费站时，就到达第二个收费站。这种情况在分组交换网中同样会出现——一个分组的前几个比特可能已经到达某台路由器，而该分组其余许多比特还在前一台路由器处等待传输。

如果一幅图胜过千言，那么一个动画必定胜过万语。本书网站提供了一个交互式动画，很好地说明并对比了传输时延与传播时延，强烈建议读者去看一看。[Smith 2009] 也对传播、排队和传输时延作了非常通俗的讨论。

若用 $d_{\text{proc}}$、$d_{\text{queue}}$、$d_{\text{trans}}$、$d_{\text{prop}}$ 分别表示处理、排队、传输和传播时延，则总节点时延为

$$
d_{\text{nodal}} = d_{\text{proc}} + d_{\text{queue}} + d_{\text{trans}} + d_{\text{prop}} \tag{1.2}
$$

各项时延的贡献可能差别很大。例如，对连接同一所大学校园内两台路由器的链路，$d_{\text{prop}}$ 可以忽略不计（例如几微秒）；而对由地球同步卫星链路互连的两台路由器，$d_{\text{prop}}$ 达数百毫秒，可能成为 $d_{\text{nodal}}$ 中的主导项。类似地，$d_{\text{trans}}$ 可以从可忽略到相当可观：对 10 Mbps 及更高传输速率（例如局域网）通常可以忽略；但对通过低速拨号调制解调器链路发送的大型因特网分组，则可能达数百毫秒。处理时延 $d_{\text{proc}}$ 往往可以忽略，但它强烈影响路由器的最大吞吐量，即路由器转发分组的最大速率。

### 1.4.2　排队时延与丢包

节点时延中最复杂、最有意思的分量是排队时延 $d_{\text{queue}}$。事实上，排队时延在计算机网络中如此重要、如此有趣，以至于围绕它已写出数千篇论文和许多专著 [Bertsekas 1991; Kleinrock 1975; Kleinrock 1976]。这里只作高层次、直观的讨论；更好奇的读者不妨翻阅其中一些著作（甚至将来就此写一篇博士论文！）。

与另外三种时延（$d_{\text{proc}}$、$d_{\text{trans}}$、$d_{\text{prop}}$）不同，排队时延是逐分组变化的。例如，若有 10 个分组同时到达一个空队列，则第一个被传输的分组不承受排队时延，而最后一个被传输的分组将承受相当大的排队时延（它要等其余九个分组传输完）。因此，刻画排队时延时通常使用统计量，例如平均排队时延、排队时延的方差、以及排队时延超过某个给定值的概率。

排队时延何时大、何时可忽略？答案取决于分组到达队列的速率、链路的传输速率以及到达流量的性质——即流量是周期性到达还是成批到达。为获得一些洞见，设 $a$ 表示分组到达队列的平均速率（单位为分组/秒），$R$ 为传输速率（即比特被推出队列的速率，单位为比特/秒）；为简单起见，假设所有分组都由 $L$ 比特组成。于是比特到达队列的平均速率为 $L a$ 比特/秒。最后，假设队列非常大，能容纳几乎无限多的比特。

比值 $L \frac{a}{R}$ 称为**流量强度**（traffic intensity），它在估计排队时延程度时往往起重要作用。若 $L \frac{a}{R} > 1$，则比特到达队列的平均速率超过比特从队列传输出去的速率。在这种不幸的情形下，队列将无界增长，排队时延趋于无穷！因此，流量工程的一条金科玉律是：**设计系统时，务必使流量强度不大于 1**。

现在考虑 $L \frac{a}{R} \le 1$ 的情形。此时，到达流量的性质会影响排队时延。例如，若分组周期性到达——即每 $\frac{L}{R}$ 秒到达一个分组——则每个分组都到达空队列，不产生排队时延。反之，若分组成批到达（但仍是周期性的），则可能有相当大的平均排队时延。例如，假设每 $(\frac{L}{R}) \times N$ 秒同时到达 $N$ 个分组，则第一个被传输的分组没有排队时延，第二个的排队时延为 $\frac{L}{R}$ 秒；一般地，第 $n$ 个被传输的分组排队时延为 $(n - 1) \frac{L}{R}$ 秒。这个例子中的平均排队时延，留作练习由读者计算。

上面两个周期性到达的例子有点学究气。通常，到达队列的过程是随机的：到达不遵循任何模式，分组之间的间隔是随机的时间量。在这种更现实的情形下，$L \frac{a}{R}$ 通常不足以完全刻画排队时延的统计特性，但它仍有助于直观理解排队时延的程度。特别是：若流量强度接近零，分组到达稀疏，到达的分组不太可能在队列中遇到别的分组，因而平均排队时延接近零；反之，当流量强度接近 1 时，由于分组到达速率本身的波动，会出现到达速率超过传输能力的时间段，这些时段内队列就会形成，而当到达速率低于传输能力时队列长度又会缩短。尽管如此，随着流量强度趋近 1，平均队列长度越来越大。平均排队时延随流量强度的定性依赖关系如图 1.19 所示。

<Figure src="ch01/fig1-19.webp" caption="图 1.19　平均排队时延与流量强度的关系" />

图 1.19 的一个重要之处在于：当流量强度趋近 1 时，平均排队时延急剧上升。流量强度只增加很小的百分比，时延却会以大得多的百分比增加。你也许在公路上体验过这种现象：如果你经常走一条通常拥堵的路，这条路的流量强度就接近 1；一旦某个事件使车流比平时略多一些，你经历的时延就可能大得惊人。

为了真正体会排队时延是怎么回事，建议再去看看教材网站上的队列交互式动画。如果把分组到达速率设得足够高、使流量强度超过 1，你会看到队列随时间慢慢堆积起来。

#### 丢包

上面的讨论假定了队列能容纳无限多个分组。现实中，链路之前的队列容量是有限的，尽管排队容量在很大程度上取决于路由器的设计与成本。由于队列容量有限，当时流量强度趋近 1 时，分组时延并不会真的趋于无穷；相反，一个分组可能到达时发现队列已满。由于无处存放，路由器将丢弃该分组，即该分组被**丢失**。这种队列溢出同样可以在交互式动画中看到——当流量强度大于 1 时。

从端系统的角度看，分组丢失表现为：一个分组被送入网络核心，却始终没有从网络的目的端出来。丢失分组的比例随流量强度增加而增大。因此，一个节点的性能往往不仅用时延衡量，还用**丢包概率**衡量。后续章节将会讨论，丢失的分组可以在端到端的基础上重传，以确保所有数据最终都从源传送到目的地。

### 1.4.3　端到端时延

到目前为止，我们的讨论集中在节点时延，即单台路由器处的时延。现在考虑从源到目的的总时延。为此，假设源主机与目的主机之间有 $N - 1$ 台路由器；再假设此刻网络无拥塞（因而排队时延可以忽略），每台路由器以及源主机的处理时延为 $d_{\text{proc}}$，从每台路由器和源主机出去的传输速率为 $R$ 比特/秒，每条链路上的传播时延为 $d_{\text{prop}}$。各节点时延累加，得到端到端时延

$$
d_{\text{end-end}} = N(d_{\text{proc}} + d_{\text{trans}} + d_{\text{prop}}) \tag{1.3}
$$

其中仍有 $d_{\text{trans}} = \frac{L}{R}$，$L$ 为分组长度。注意，上式是式 (1.1) 的推广，后者没有考虑处理时延与传播时延。至于各节点时延不一致、以及每个节点存在平均排队时延的情形，留给读者自行推广。

#### Traceroute

要亲身体会计算机网络中的端到端时延，可以使用 **Traceroute** 程序。Traceroute 是一个简单程序，可以在任何因特网主机上运行。用户指定一个目的主机名后，源主机中的程序向该目的地发送多个特殊分组。这些分组在通往目的地的途中经过一系列路由器；当某台路由器收到这种特殊分组时，就向源回送一条短消息，其中包含该路由器的名称和地址。

更具体地说，源向网络中发送一系列特殊分组，每个分组都寻址到最终目的地。第一个分组标记为 1，第二个标记为 2，依此类推。当源与目的之间的某台路由器收到这种特殊分组时，就把标记减 1，然后继续转发；但如果某台路由器把标记减到 0，它就不再向目的地转发该分组，而是向源回送一条消息。当目的主机收到标记为 1 的分组时，也向源回送一条消息（源收到该主机的消息后就不再发送这些特殊分组）。源记录从发出分组到收到相应返回消息之间经过的时间，同时记录返回消息的路由器（或目的主机）的名称与地址。这样，源就能重建分组从源到目的所走的路径，并能确定到沿途各路由器的往返时延。Traceroute 实际上把上述实验重复三次，因此源共向目的地发送 $3 N$ 个分组，其中 $N - 1$ 是源与目的之间的路由器数目。RFC 1393 详细描述了 Traceroute。

#### 端系统时延、应用时延及其他时延

除了处理、传输和传播时延之外，端系统中还可能有其他可观的时延。例如，一个端系统要向共享媒体发送分组（如 WiFi 或电缆调制解调器场景），它可能作为与其他端系统共享媒体的协议的一部分，有意延迟自己的发送——这类协议将在第 6 章详细讨论。另一个重要的时延是**媒体分组化时延**（packetization delay），它存在于 Zoom、Google Hangouts 这类视频会议应用中：在视频会议中，发送侧必须先用编码后的数字化视频和语音把一个分组填满，然后才能把该分组交给因特网。

### 1.4.4　计算机网络中的吞吐量

除了时延和丢包，计算机网络的另一个关键性能度量是**端到端吞吐量**。为定义吞吐量，考虑通过一个计算机网络把一个大文件从主机 A 传送到主机 B（例如把一个很大的视频片段从一台计算机传到另一台）。任一时刻的**瞬时吞吐量**，是主机 B 接收该文件的速率（比特/秒）。（许多应用会在用户界面中显示下载时的瞬时吞吐量——你也许见过！你也可以用 speedtest 应用 [Speedtest 2025] 测一测自己与因特网上各处服务器之间的端到端时延和下载吞吐量。）若文件由 $F$ 比特组成，主机 B 用 $T$ 秒接收完所有 $F$ 比特，则该文件传送的**平均吞吐量**为 $\frac{F}{T}$ 比特/秒。对某些应用（如 IP 电话），希望时延低、且瞬时吞吐量始终高于某个门限（例如某些 IP 电话应用要求高于 24 kbps，某些实时视频应用要求高于 256 kbps）；对另一些应用（包括文件传送类），时延不关键，但希望吞吐量尽可能高。

为深入理解吞吐量这一重要概念，看几个例子。图 1.20(a) 展示了两个端系统——一台服务器和一台客户机——由两条通信链路和一台路由器相连。考虑从服务器向客户机传送文件的吞吐量。设 $R_{s}$ 表示服务器与路由器之间链路的速率，$R_{c}$ 表示路由器与客户机之间链路的速率。假设整个网络中正在发送的比特只有从服务器到客户机的这些比特。那么在这样一个理想场景中，服务器到客户机的吞吐量是多少？可以把比特想象成流体，把通信链路想象成管道：显然，服务器通过其链路泵出比特的速率不可能快于 $R_{s}$ bps，路由器转发比特的速率也不可能快于 $R_{c}$ bps。若 $R_{s} < R_{c}$，则服务器泵出的比特将顺畅地流过路由器，以 $R_{s}$ bps 的速率到达客户机，吞吐量为 $R_{s}$ bps；反之若 $R_{c} < R_{s}$，路由器转发比特的速度跟不上接收的速度，此时比特只能以 $R_{c}$ 的速率离开路由器，端到端吞吐量为 $R_{c}$。（还要注意：若比特持续以 $R_{s}$ 的速率到达路由器、而以 $R_{c}$ 的速率离开，路由器中等待发往客户机的比特积压将不断增长——这是极不希望出现的情形！）

因此，对这条简单的两链路网络，吞吐量为 $\text{min} \{R_{s}, R_{c} \}$，即**瓶颈链路**的传输速率。确定了吞吐量，就可以把从服务器向客户机传送 $F$ 比特大文件的时间近似为 $\frac{F}{\text{min}} \{R_{s}, R_{c} \}$。举个具体例子：假设你要下载一个 $F = 3200$ 万比特的 MP3 文件，服务器传输速率 $R_{s} = 2$ Mbps，你的接入链路 $R_{c} = 1$ Mbps，则传送该文件需要 32 秒。当然，这些吞吐量与传送时间的表达式只是近似，因为它们没有考虑存储转发时延、处理时延以及协议方面的问题。

<Figure src="ch01/fig1-20.webp" caption="图 1.20　从服务器向客户机传送文件时的吞吐量" />

图 1.20(b) 展示了一个服务器与客户机之间有 $N$ 条链路的网络，这 $N$ 条链路的传输速率分别为 $R_{1}, R_{2}, \cdots, R_{N}$。套用两链路网络的分析可知，从服务器向客户机传送文件的吞吐量为 $\text{min} \{R_{1}, R_{2}, \cdots, R_{N} \}$，仍然是服务器与客户机之间路径上瓶颈链路的传输速率。

再看一个由当今因特网引发的例子。图 1.21(a) 展示了连到某计算机网络上的两个端系统——一台服务器和一台客户机，考虑从服务器向客户机传送文件的吞吐量。服务器以速率 $R_{s}$ 的接入链路连到网络，客户机以速率 $R_{c}$ 的接入链路连到网络。现在假设通信网络核心中的所有链路都具有非常高的传输速率，远高于 $R_{s}$ 和 $R_{c}$——事实上，今天因特网的核心配置了充裕的高速链路，很少发生拥塞。同时假设整个网络中正在发送的比特只有从服务器到客户机的这些比特。由于本例中网络核心像一根粗管道，比特从源流到目的的速率仍然是 $R_{s}$ 与 $R_{c}$ 中的较小者，即 $\text{吞吐量} = \text{min} \{R_{s}, R_{c} \}$。因此，**当今因特网中吞吐量的制约因素通常是接入网**。

最后一个例子，考虑图 1.21(b)：10 台服务器和 10 台客户机连到某计算机网络的核心，此刻有 10 对客户-服务器在同时下载。假设这 10 个下载是网络中当前仅有的流量。如图所示，核心中有一条链路被这 10 个下载共同穿越，记其传输速率为 $R$。假设所有服务器接入链路的速率同为 $R_{s}$，所有客户机接入链路的速率同为 $R_{c}$，且核心中除这条速率为 $R$ 的公共链路之外，所有链路的传输速率都远大于 $R_{s}$、$R_{c}$ 和 $R$。那么这些下载的吞吐量各是多少？显然，若公共链路的速率 $R$ 很大（比如是 $R_{s}$ 和 $R_{c}$ 的一百倍），则每个下载的吞吐量仍约为 $\text{min} \{R_{s}, R_{c} \}$；但如果 $R$ 与 $R_{s}$、$R_{c}$ 相当，公共链路就成为瓶颈，10 个下载将公平地分享 $R$，每个的吞吐量约为 $\frac{R}{10}$。这个例子说明：**一条连接的性能不仅取决于它自己的接入链路，还取决于它与其他流量共享的公共链路**。

## 1.5　协议层次及其服务模型

从上面的讨论可以明显看出，因特网是一个极其复杂的系统：众多的应用与协议、各种类型的端系统、分组交换机，以及各种类型的链路级媒体。面对如此巨大的复杂性，我们还有希望把网络体系结构——至少是我们关于网络体系结构的讨论——组织起来吗？幸运的是，两个问题的答案都是"有"。

### 1.5.1　分层体系结构

在着手梳理关于因特网体系结构的思路之前，先看一个人类类比。其实我们日常生活中无时无刻不在处理复杂系统。设想有人请你描述航空系统：面对售票员、行李托运、登机口人员、飞行员、飞机、空中交通管制以及全球性的飞机航线系统，你该如何找出描述这个复杂系统的结构？

一种办法是描述你乘飞机旅行时所经历（或别人为你所做）的一系列动作：买票、托运行李、到登机口、登机；飞机起飞并按航线飞往目的地；飞机降落后，你在登机口下机、取回行李；如果旅途不愉快，你就向售票员投诉航班（徒劳无功）。这一场景如图 1.22 所示。

<Figure src="ch01/fig1-22.webp" caption="图 1.22　乘飞机旅行：动作序列" />

这里已经能看出与计算机网络的一些类比：你被航空公司从起点运到终点；在因特网中，分组被从源主机运到目的主机。但这还不是我们想要的类比。我们要在图 1.22 中找出某种**结构**。观察图 1.22 可以发现：两端都有**售票**功能；对已购票的旅客还有**行李**功能；对已购票且已托运行李的旅客还有**登机口**功能；对已通过登机口的旅客（即已购票、已托运行李、已通过登机口），还有**起飞与降落**功能；而在飞行途中，还有**航线**功能。这提示我们可以按**水平**方式来看待图 1.22 中的功能，如图 1.23 所示。

<Figure src="ch01/fig1-23.webp" caption="图 1.23　航空功能的水平分层" />

图 1.23 把航空功能划分为若干**层次**，为讨论航空旅行提供了一个框架。注意，每一层与其下面各层一起实现某种功能、某种服务：在售票层及其以下各层，完成"从值机柜台到值机柜台"的人员运送；在行李层及其以下各层，完成"从行李托运到行李提取"的人员与行李运送（注意，行李层只向已购票的人提供这一服务）；在登机口层，完成"从出发登机口到到达登机口"的人员与行李运送；在起飞/降落层，完成"从跑道到跑道"的人员及其行李运送。每一层通过以下两种方式提供其服务：(1) 在该层内执行某些动作（例如在登机口层，让人上下飞机）；(2) 使用紧邻其下那一层的服务（例如在登机口层，使用起飞/降落层"从跑道到跑道"的旅客运送服务）。

分层体系结构使我们能够讨论一个庞大而复杂系统中界定明确的特定部分。这种简化本身就有相当的价值：它提供了**模块化**，使改变某一层所提供服务的**实现**变得容易得多。只要该层向上一层提供相同的服务、并使用下一层相同的服务，那么当某一层的实现发生变化时，系统其余部分保持不变。（注意，改变服务的实现与改变服务本身是完全不同的两回事！）例如，如果登机口的功能改变了（比如改成按身高上下飞机），航空系统的其余部分仍保持不变，因为登机口层仍然提供相同的功能（让人上下飞机），只是改变之后用不同的方式来实现该功能。对于不断更新的大型复杂系统而言，"能够改变某一服务的实现而不影响系统其他组件"正是分层的又一重要优点。

#### 协议分层

关于航空公司的类比就说到这里，现在把注意力转向网络协议。为了给网络协议的设计提供结构，网络设计者把协议——以及实现这些协议的网络硬件和软件——按**层次**组织。每个协议属于某一层，正如图 1.23 中航空体系结构的每个功能属于某一层。我们同样关心某一层向上一层提供的服务，即所谓该层的**服务模型**。与航空例子一样，每一层通过以下两种方式提供其服务：(1) 在该层内执行某些动作；(2) 使用紧邻其下那一层的服务。例如，第 $n$ 层提供的服务可以包括从网络一端到另一端可靠地交付报文，这可以通过使用第 $n - 1$ 层不可靠的端到端报文交付服务、并增加第 $n$ 层检测与重传丢失报文的功能来实现。

协议层可以用软件、硬件或二者结合来实现。应用层协议（如 HTTP 和 SMTP）几乎总是在端系统中用软件实现，运输层协议也是如此。由于物理层和数据链路层负责处理特定链路上的通信，它们通常在与某条链路相关的**网络接口卡**（例如以太网卡或 WiFi 接口卡）中实现。网络层则常常是软硬件的混合实现。还要注意，正如分层航空体系结构中的功能分布在构成该系统的各个机场和飞行控制中心一样，第 $n$ 层的协议也分布在构成网络的端系统、分组交换机和其他组件之中——也就是说，这些网络组件中往往各有一份第 $n$ 层协议的实现。

协议分层具有概念上和结构上的优点 [RFC 3439]：如前所见，分层为讨论系统组件提供了有条理的方式，模块化使系统组件的更新更容易。不过要指出，有些研究者和网络工程师强烈反对分层 [Wakeman 1992]。分层的一个潜在缺点是，某一层可能重复低层的功能，例如许多协议栈既提供逐链路的差错恢复、又提供端到端的差错恢复。另一个潜在缺点是，某一层的功能可能需要只存在于另一层的信息（例如时间戳值），这违背了层间分离的目标。

把各层的协议合在一起，称为**协议栈**（protocol stack）。因特网协议栈由五层组成：物理层、链路层、网络层、运输层和应用层，如图 1.24 所示。如果你翻一翻本书目录，会发现我们大体上就是按因特网协议栈的各层来组织全书的，并采用**自顶向下**的方法：先讲应用层，然后逐层向下。

<Figure src="ch01/fig1-24.webp" caption="图 1.24　因特网协议栈" />

#### 应用层

应用层是网络应用及其应用层协议所在之处。因特网的应用层包含许多协议，例如 HTTP 协议（提供 Web 文档的请求与传送）和 SMTP（提供电子邮件的传送）。我们还将看到，某些网络功能——例如把 www.ietf.org 这类便于人记忆的因特网端系统名字转换为 32 比特网络地址——也要借助一个特定的应用层协议来完成，即**域名系统**（DNS）。第 2 章将会看到，创建并部署我们自己的新应用层协议是非常容易的。

应用层协议分布在多个端系统上：一个端系统中的应用使用该协议与另一个端系统中的应用交换信息分组。我们把应用层的这种信息分组称为**报文**（message）。

#### 运输层

因特网的运输层在应用端点之间传送应用层报文。因特网中有两个运输协议——TCP 和 UDP，二者都可以传送应用层报文。TCP 向其应用提供**面向连接**的服务，包括把应用层报文有保证地交付到目的地，以及**流量控制**（即发送方与接收方速度匹配）。TCP 还把长报文划分为较短的报文段，并提供**拥塞控制**机制，使源端在网络拥塞时抑制其发送速率。UDP 协议向其应用提供**无连接**服务，这是一种"极简"服务，不提供可靠性、不提供流量控制、也不提供拥塞控制。本书把运输层分组称为**报文段**（segment）。

#### 网络层

因特网的网络层负责把称为**数据报**（datagram）的网络层分组从一台主机移动到另一台主机。源主机中的因特网运输层协议（TCP 或 UDP）把一个运输层报文段和一个目的地址交给网络层，就像你把一封写有目的地址的信交给邮政服务一样；网络层则提供把该报文段交付给目的主机运输层的服务。

因特网的网络层包含著名的 IP 协议，它定义了数据报中的字段，以及端系统与路由器如何作用于这些字段。IP 协议只有一个，所有具有网络层的因特网组件都必须运行 IP 协议。因特网的网络层还包含**路由协议**，用于确定数据报在源与目的之间所走的路径。因特网有许多路由协议：如 1.3 节所述，因特网是网络的网络，在一个网络内部，网络管理员可以运行任何想要的路由协议。尽管网络层既包含 IP 协议又包含众多路由协议，它常被简称为 **IP 层**，这反映出 IP 是把因特网黏合在一起的"胶水"。

#### 链路层

因特网的网络层让数据报经源与目的之间的一系列路由器路由。要把一个分组从路由上的一个节点（主机或路由器）移动到下一个节点，网络层要依赖链路层的服务：具体地说，在每个节点，网络层把数据报下交给链路层，链路层把数据报交付给路由上的下一个节点；在下一个节点，链路层再把数据报上交给网络层。

链路层提供的服务取决于链路上所采用的具体链路层协议。例如，有些链路层协议提供从发送节点经一条链路到接收节点的可靠交付。注意，这种可靠交付服务不同于 TCP 的可靠交付服务——后者提供的是一台端系统到另一台端系统的可靠交付。链路层协议的例子包括以太网、WiFi 以及电缆接入网的 DOCSIS 协议。由于数据报从源到目的通常要经过若干条链路，一个数据报在其路径的不同链路上可能由不同的链路层协议处理——例如在某条链路上由 WiFi 处理，在下一条链路上由以太网处理。网络层将从各个不同的链路层协议获得不同的服务。本书把链路层分组称为**帧**（frame）。

#### 物理层

链路层的任务是把整个帧从一个网络元素移动到相邻的网络元素，而物理层的任务则是把帧中的一个个**比特**从一个节点移动到下一个节点。这一层的协议同样依赖于链路，并进一步依赖于链路的实际传输媒体（例如双绞铜线、单模光纤）。例如，以太网有许多物理层协议：一个用于双绞铜线，一个用于同轴电缆，一个用于光纤，等等。每种情况下，比特跨越链路的方式各不相同。

### 1.5.2　封装

图 1.25 展示了数据在发送端系统协议栈中下行的物理路径，在中间链路层交换机和路由器的协议栈中上下往返，然后在接收端系统的协议栈中上行。如本书后文将要讨论的，路由器与链路层交换机都是分组交换机。与端系统类似，路由器和链路层交换机也把其网络硬件和软件按层组织。但路由器和链路层交换机并不实现协议栈中的所有层，它们通常只实现下面几层：如图 1.25 所示，链路层交换机实现第 1、2 层，路由器实现第 1 至第 3 层。这意味着，例如因特网路由器能够实现 IP 协议（一个第 3 层协议），而链路层交换机不能。后文将会看到，链路层交换机虽然不认识 IP 地址，却能识别第 2 层地址，例如以太网地址。注意，主机实现了全部五层——这与"因特网体系结构把大量复杂性放在网络边缘"的观点是一致的。

图 1.25 还说明了**封装**（encapsulation）这一重要概念。在发送主机，一个应用层报文（图 1.25 中的 M）被交给运输层。最简单的情形下，运输层取出该报文，附加上将被接收端运输层使用的附加信息（即所谓的运输层首部信息，图 1.25 中的 $H_{t}$）。应用层报文与运输层首部信息一起构成**运输层报文段**，于是运输层报文段**封装**了应用层报文。附加的信息可能包括让接收端运输层把报文交付给正确应用所需的信息，以及让接收端判断报文中比特在途中是否被改变的差错检测比特。

随后运输层把报文段交给网络层，网络层添加网络层首部信息（图 1.25 中的 $H_{n}$），例如源端系统与目的端系统的地址，从而生成**网络层数据报**；数据报再被交给链路层，链路层（当然！）会添加自己的链路层首部信息，生成**链路层帧**。于是我们看到，在每一层，分组都有两类字段：**首部字段**与**载荷字段**，而载荷通常就是来自上一层的分组。

这里有一个有用的类比：通过公共邮政服务把一个公司内部备忘录从一个分公司寄到另一个分公司。假设 Alice 在某个分公司，想给另一个分公司的 Bob 寄一份备忘录。备忘录相当于**应用层报文**。Alice 把备忘录装进一个**公司内部信封**，在信封正面写上 Bob 的姓名和部门。内部信封相当于**运输层报文段**——它包含首部信息（Bob 的姓名和部门编号），并封装了应用层报文（备忘录）。当发送方分公司的收发室收到这个内部信封时，它把内部信封再装进另一个适合通过公共邮政服务寄送的**邮政信封**，并在邮政信封上写明发送方与接收方分公司的邮政地址。这里，邮政信封相当于**数据报**——它封装了运输层报文段（内部信封），而后者又封装了原始报文（备忘录）。邮政服务把邮政信封投递到接收方分公司的收发室，在那里开始**解封装**过程：收发室取出内部备忘录并转交给 Bob；最后，Bob 打开信封取出备忘录。

封装过程可能比上面描述的更复杂。例如，一个长报文可能被划分为多个运输层报文段（而每个报文段本身又可能被划分为多个网络层数据报）；在接收端，这样的报文段必须由其各个数据报重新装配而成。

## 1.6　面对攻击的网络

今天的因特网对许多机构（大大小小的公司、大学、政府机构）而言已成为关键任务系统，许多个人的职业、社交与私人活动也依赖因特网；还有数十亿"物"（可穿戴设备、家用设备等）正接入因特网。但在这一切便利与兴奋背后，还有一个阴暗面：在那里，"坏人"试图通过破坏我们联网的计算机、侵犯我们的隐私、让我们赖以生存的因特网服务瘫痪，来搅乱我们的日常生活。

**网络安全**这一领域，研究的正是坏人如何攻击计算机网络，以及我们这些即将成为网络专家的人如何防御这些攻击，或者更好的是，从一开始就设计出对这类攻击免疫的新体系结构。鉴于现存攻击之频繁、种类之繁多，以及未来更新、更具破坏性攻击之威胁，网络安全已成为计算机网络领域的核心议题。本书的特色之一，就是把网络安全问题推到前台。

由于我们尚未具备计算机网络与因特网协议的专业知识，这里先概览当今较为普遍的一些安全问题，为后续章节更实质性的讨论做个铺垫。因此我们只问：可能出什么问题？计算机网络为何脆弱？当今较常见的攻击有哪些？

### 恶意软件：坏人可经由因特网把恶意软件植入你的主机

我们把设备接入因特网，是为了收发数据——其中包括各种好东西：Instagram 帖子、搜索结果、流媒体音乐、视频会议、在线电影等等。但不幸的是，伴随这些好东西而来的还有恶意的东西——统称**恶意软件**（malware），它们也能进入并感染我们的设备。恶意软件一旦感染设备，就能干各种坏事：删除我们的文件；安装**间谍软件**收集我们的隐私信息（如社会安全号、口令、击键记录），再把这些信息（当然是通过因特网！）发回给坏人。被攻陷的主机还可能被编入一个由成千上万台同样被攻陷的设备组成的网络——统称**僵尸网络**（botnet）——坏人控制并利用它来分发垃圾邮件，或对目标主机发起**分布式拒绝服务攻击**（稍后讨论）。

今天很多恶意软件是**自我复制**的：一旦感染一台主机，它就从该主机出发，经由因特网寻找进入其他主机的途径；再从新感染的主机出发，继续寻找更多主机。这样，自我复制的恶意软件可以指数式快速传播。

### 拒绝服务攻击：坏人可攻击服务器与网络基础设施

另一大类安全威胁称为**拒绝服务**（denial-of-service, DoS）攻击。顾名思义，DoS 攻击使合法用户无法使用某个网络、主机或其他基础设施。Web 服务器、邮件服务器、DNS 服务器（第 2 章讨论）以及机构网络都可能遭受 DoS 攻击。多数因特网 DoS 攻击可归入以下三类之一：

::: tip 要点

1. **漏洞攻击**（vulnerability attack）：向目标主机上运行的有漏洞的应用或操作系统发送少数精心构造的报文。如果把正确的分组序列发送给有漏洞的应用或操作系统，服务可能停止，更糟的是主机可能崩溃。
1. **带宽洪泛**（bandwidth flooding）：攻击者向目标主机发送海量分组，多到把目标的接入链路堵塞，使合法分组无法到达服务器。
1. **连接洪泛**（connection flooding）：攻击者在目标主机上建立大量半开或完全打开的 TCP 连接（TCP 连接见第 3 章）。主机可能被这些虚假连接拖垮，以致不再接受合法连接。

:::

现在更详细地探讨带宽洪泛攻击。回想 1.4.2 节关于时延与丢包的分析可知：若服务器的接入速率为 $R$ bps，则攻击者需要以约 $R$ bps 的速率发送流量才能造成损害。若 $R$ 很大，单个攻击源可能无法产生足够流量来伤害服务器；而且，如果所有流量都来自单一源，上游路由器或许能检测到该攻击并在流量接近服务器之前封锁该源的全部流量。在**分布式拒绝服务**（DDoS）攻击中（如图 1.26 所示），攻击者控制多个源，让每个源都向目标猛烈发送流量。这样，所有受控源的流量速率之和需达到约 $R$ 才能使服务瘫痪。利用由成千上万台被攻陷主机构成的僵尸网络发起 DDoS 攻击，在今天屡见不鲜。DDoS 攻击比来自单一主机的 DoS 攻击难检测、难防御得多。每年针对因特网基础设施的大型 DDoS 攻击大约有 100 起 [Sitaraman 2022]。

在阅读本书的过程中，请不断思考这个问题：网络设计者能做些什么来防御 DoS 攻击？我们将会看到，针对三类 DoS 攻击需要不同的防御手段。

### 分组嗅探：坏人可窃听分组

今天许多用户通过无线设备上网，例如连 WiFi 的笔记本电脑，或带蜂窝连接的掌上设备（第 7 章讨论）。无处不在的因特网接入极其方便，也为移动用户带来了奇妙的新应用，但同时也造成一个重大安全弱点——只要把一个**被动接收器**放在无线发送器附近，该接收器就能获得所传输的每一个分组的副本！这些分组可能包含各种敏感信息，包括口令、社会安全号、商业秘密和私人消息。记录每一个飞过分组的副本的被动接收器，称为**分组嗅探器**（packet sniffer）。

嗅探器也能部署在有线环境中。在有线广播环境中（如许多以太网局域网），分组嗅探器可以获取局域网上发送的广播分组的副本。如 1.2 节所述，电缆接入技术也广播分组，因而同样易被嗅探。此外，若坏人得以接入某机构的接入路由器或接入链路，他可能植入嗅探器，复制进出该机构的每一个分组。被嗅探到的分组随后可离线分析，以提取敏感信息。

分组嗅探软件在各网站可免费获得，也有商业产品出售。据我们所知，有些教授在讲授网络课程时会布置实验作业，要求学生编写一个分组嗅探与应用层数据重建程序。事实上，与本书配套的 Wireshark [Wireshark 2025] 实验（见本章末的 Wireshark 入门实验）用的正是这样一个分组嗅探器！

由于分组嗅探器是被动的——即它不向信道中注入分组——因此难以检测。所以，当我们把分组送入无线信道时，必须接受一种可能性：某个坏人可能正在记录我们分组的副本。你可能已经猜到，对付分组嗅探的一些最好办法涉及**密码学**。第 8 章将讨论密码学在网络安全性方面的应用。

### 伪装：坏人可冒充你信任的人

制造一个具有任意源地址、任意内容和任意目的地址的分组，再把这个手工构造的分组发送到因特网中，让它忠实地被转发到目的地——这件事出奇地容易（随着本书的推进，你很快就会具备这样的知识！）。设想毫无戒心的接收方（比如一台因特网路由器）收到这样一个分组，把（虚假的）源地址当作真实地址，然后执行分组内容中嵌入的某个命令（比如修改自己的转发表）。这种用虚假源地址向因特网注入分组的能力称为 **IP 欺骗**（IP spoofing），它只是一个用户冒充另一个用户的众多方式之一。

要解决这个问题，我们需要**端点鉴别**（end-point authentication），即一种能让我们确信某条报文确实来自它所声称之处发源的机制。同样鼓励你在阅读本书各章时思考：对网络应用和协议而言，这该如何做到？第 8 章将探讨端点鉴别的机制。

在结束本节时，值得想一想：因特网当初怎么会变成这样一个不安全的地方？答案实质上是：因特网最初就是按"一群互相信任的用户连接在一个透明网络上"的模型设计的 [Blumenthal 2001]——在这个模型中（按定义）根本不需要安全。原始因特网体系结构的许多方面都深深反映了这种互信观念。例如，一个用户能向任何其他用户发送分组，这是默认能力，而不是需要申请/授予的能力；用户身份按其自报值采信，而不是默认加以鉴别。

但今天的因特网显然并不涉及"互相信任的用户"。尽管如此，今天的用户仍然需要在彼此未必信任的情况下通信：他们可能希望匿名通信，可能通过第三方间接通信（例如第 2 章将研究的 Web 缓存，或第 7 章将研究的移动性辅助代理），还可能不信任他们通信所依赖的硬件、软件乃至空气。随着本书的推进，我们面前有许多与安全相关的挑战：我们应当寻求针对嗅探、端点伪装、中间人攻击、DDoS 攻击、恶意软件等的防御手段。我们应当牢记：互相信任的用户之间的通信是例外，而不是常规。欢迎来到现代计算机网络的世界！

## 1.7　计算机网络与因特网的历史

1.1 至 1.6 节概览了计算机网络与因特网的技术。读到这里，你掌握的知识已足以在亲友面前露一手了！不过，若真想在下一次聚会上大放异彩，不妨在谈话中掺入一些关于因特网迷人历史的花絮 [Segaller 1998]。

### 1.7.1　分组交换的诞生：1961—1972

计算机网络领域与今天的因特网可追溯到 20 世纪 60 年代初，当时电话网是世界上占主导地位的通信网络。如 1.3 节所述，电话网用电路交换在发送方与接收方之间传送信息——考虑到语音在收发双方之间是以恒定速率传输的，这是个恰当的选择。60 年代初计算机日益重要，分时计算机出现，人们自然会考虑如何把计算机连接起来，以便在地理上分散的用户之间共享。这类用户产生的流量很可能是**突发式**的：一段时间有活动（例如向远程计算机发送一条命令），随后一段静默（等待回应或思考收到的响应）。

当时世界上有三个研究组在彼此不知情的情况下 [Leiner 1998]，开始把分组交换发明为电路交换的一种高效而健壮的替代方案。最早发表分组交换技术工作的是当时麻省理工学院的研究生 Leonard Kleinrock [Kleinrock 1961; Kleinrock 1964]；他运用排队论，优雅地证明了分组交换方法对突发式流量源的有效性。1964 年，兰德研究所的 Paul Baran [Baran 1964] 开始研究用分组交换在军用网络上传输保密语音；在英国国家物理实验室，Donald Davies 和 Roger Scantlebury 也在发展他们关于分组交换的想法。

MIT、兰德和 NPL 的工作为今天的因特网奠定了基础。但因特网还有一段"先造出来、再演示给人看"的悠久传统，这同样可以追溯到 60 年代。Kleinrock 在 MIT 的同事 J. C. R. Licklider [DEC 1990] 和 Lawrence Roberts 先后领导了美国**高级研究计划局**（ARPA）的计算机科学计划。Roberts 发表了 ARPAnet 的总体方案 [Roberts 1967]——ARPAnet 是第一个分组交换计算机网络，也是今天公共因特网的直系祖先。1969 年劳动节，第一台分组交换机在 Kleinrock 指导下安装于 UCLA；此后不久，又在斯坦福研究所（SRI）、加州大学圣巴巴拉分校和犹他大学安装了另外三台分组交换机（图 1.27）。到 1969 年底，这个因特网的襁褓前身已有四个节点。Kleinrock 回忆说，网络的第一次使用是从 UCLA 远程登录到 SRI，结果把系统弄崩了 [Kleinrock 2004]。

到 1972 年，ARPAnet 已发展到约 15 个节点，并由 Robert Kahn 作了首次公开演示。ARPAnet 端系统之间的第一个主机到主机协议——网络控制协议（NCP）——也已完成 [RFC 001]。有了端到端协议，就可以编写应用了：1972 年，Ray Tomlinson 写出了第一个电子邮件程序。

### 1.7.2　专用网络与网络互连：1972—1980

最初的 ARPAnet 是一个单一的封闭网络，要与 ARPAnet 主机通信，必须实际连接到另一台 ARPAnet IMP 上。70 年代初中期，除 ARPAnet 之外又出现了若干独立的分组交换网：连接夏威夷各岛大学的微波网络 ALOHANet [Abramson 1970]，DARPA 的分组卫星网 [RFC 829] 与分组无线电网 [Kahn 1978]；基于 ARPAnet 技术的 BBN 商用分组交换网 Telenet；由 Louis Pouzin 开创的法国分组交换网 Cyclades [Think 2012]；60 年代末 70 年代初的分时网络，如 Tymnet 和 GE 信息服务网 [Schwartz 1977]；以及 IBM 的 SNA（1969—1974），它与 ARPAnet 的工作并行 [Schwartz 1977]。

网络数量在不断增长。事后看来，为把这些网络连接起来而发展一个包罗万象的体系结构，时机已经成熟。在**国防高级研究计划局**（DARPA）资助下，Vinton Cerf 和 Robert Kahn 完成了互连网络的开拓性工作，实质上创造了"网络的网络" [Cerf 1974]；"互联网互连"（internetting）一词正是为描述这项工作而造出来的。

这些体系结构原则体现在 TCP 中。不过早期版本的 TCP 与今天的 TCP 差别很大：早期 TCP 把"经由端系统重传的可靠按序数据交付"（这仍是今天 TCP 的一部分）与"转发功能"（今天由 IP 承担）结合在一起。对 TCP 的早期实验，加上人们认识到对分组化语音这类应用而言，一个不可靠、无流量控制的端到端运输服务很重要，最终导致把 IP 从 TCP 中分离出来，并促成 UDP 协议的开发。今天我们看到的三个关键因特网协议——TCP、UDP 和 IP——到 70 年代末在概念上都已就位。

除 DARPA 的因特网相关研究之外，还有许多重要的网络活动在进行。在夏威夷，Norman Abramson 正在开发 ALOHAnet——一个基于分组的无线电网，使夏威夷各岛的多个远程站点能够互相通信。ALOHA 协议 [Abramson 1970] 是第一个**多址访问协议**，使地理上分散的用户共享单一的广播通信媒体（一个无线电频率）。Metcalfe 和 Boggs 在 Abramson 多址访问协议工作的基础上，为有线共享广播网开发了**以太网**协议 [Metcalfe 1976]。有趣的是，他们开发以太网的动机是需要连接多台 PC、打印机和共享磁盘 [Perkins 1994]。二十五年前，在 PC 革命和网络大爆发之前很久，Metcalfe 和 Boggs 就在为今天的 PC 局域网奠定基础了。

### 1.7.3　网络的激增：1980—1990

到 70 年代末，约有 200 台主机连到 ARPAnet；到 80 年代末，连到公共因特网（一个与今天因特网颇为相似的网络联合体）的主机数达到十万台。80 年代是大发展的十年。

这种增长很大程度源于若干把大学连接起来的独立努力。BITNET 在东北部若干大学之间提供电子邮件和文件传输；CSNET（计算机科学网）把无法访问 ARPAnet 的大学研究者连接起来；1986 年创建 NSFNET，为受 NSF 资助的超级计算中心提供接入。NSFNET 骨干网最初速度为 56 kbps，到 80 年代末已运行在 1.5 Mbps，并成为连接各区域网的主要骨干。

在 ARPAnet 共同体中，今天因特网体系结构的许多最后拼图正各就各位。1983 年 1 月 1 日，TCP/IP 被正式部署为 ARPAnet 的新标准主机协议（取代 NCP）。从 NCP 到 TCP/IP 的转换 [RFC 801] 是一次"旗帜日"事件——从那天起所有主机都必须转到 TCP/IP。80 年代后期，TCP 被作了重要扩展以实现基于主机的拥塞控制 [Jacobson 1988]；用于在人类可读的因特网名字（例如 gaia.cs.umass.edu）与其 32 比特 IP 地址之间进行映射的 DNS 也发展了起来 [RFC 1034]。

与 ARPAnet 的发展（这基本上是美国的努力）并行，法国在 80 年代初启动了 Minitel 计划——一个把数据网络带进每个家庭的雄心勃勃的方案。Minitel 系统由政府资助，由公共分组交换网（基于 X.25 协议族）、Minitel 服务器以及内置低速调制解调器的廉价终端构成。1984 年，法国政府向每个愿意要的法国居民家庭免费发放一台 Minitel 终端，Minitel 由此大获成功。Minitel 站点既有免费站点（如电话号码簿），也有向用户按使用量收费的私有站点。在 90 年代中期的巅峰时期，它提供两万多种服务，从家庭银行到专业研究数据库。在大多数美国人还没听说过因特网之前十年，Minitel 就已进入很大一部分法国家庭。

### 1.7.4　因特网大爆炸：20 世纪 90 年代

90 年代在一系列事件中拉开帷幕，这些事件象征着因特网的持续演进和即将到来的商业化：因特网的祖先 ARPAnet 停止存在；1991 年，NSFNET 取消了对其商业用途的限制；NSFNET 本身于 1995 年退役，因特网骨干流量由商业因特网服务提供商承载。

90 年代的主要事件是万维网应用的出现，它把因特网带进了全世界数以百万计的家庭和企业。Web 成为一个平台，催生并部署了数百个今天我们习以为常的新应用，包括搜索（如 Google、Bing）、因特网商务（如 Amazon、eBay）和社交网络（如 Facebook）。

Web 由 Tim Berners-Lee 于 1989 至 1991 年间在 CERN 发明 [Berners-Lee 1989]，其思想源自 Vannevar Bush 在 40 年代 [Bush 1945]、Ted Nelson 自 60 年代以来 [Xanadu 2012] 关于超文本的早期工作。Berners-Lee 及其同事开发了 HTML、HTTP、Web 服务器和浏览器的最初版本——Web 的四个关键组件。1993 年底前后，约有 200 台 Web 服务器在运行，这批服务器只是即将到来之浪潮的先声。大约同时，若干研究者正在开发带图形界面的浏览器，其中包括 Marc Andreessen——他与 Jim Clark 一起创办了 Mosaic Communications，即后来的 Netscape Communications 公司 [Cusumano 1998; Quittner 1998]。到 1995 年，大学生已每天用 Netscape 浏览器上网冲浪；大约同时，大大小小的公司开始运行 Web 服务器并在 Web 上进行交易。1996 年微软开始做浏览器，引发 Netscape 与微软的浏览器之战，几年后微软胜出 [Cusumano 1998]。

90 年代后半期是因特网大发展、大创新的时期，大公司和成千上万家创业公司创造了大量因特网产品与服务。到千年之交，因特网已支撑数百个流行应用，其中包括四个"杀手级应用"：

- 电子邮件，包括附件与可经 Web 访问的邮件；
- Web，包括网页浏览与因特网商务；
- 即时消息，带联系人列表；
- MP3 的点对点文件共享，由 Napster 开创。

有趣的是，前两个杀手级应用来自研究界，后两个则由几位年轻的创业者创造。

1995 至 2001 年，因特网在金融市场上经历了一轮过山车。数百家因特网创业公司在尚未盈利时就首次公开募股、开始在股市交易，许多公司在没有任何可观收入来源的情况下被估值数十亿美元。2000—2001 年因特网股票崩盘，许多创业公司关门。尽管如此，仍有一批公司在因特网领域成为大赢家，包括微软、思科、雅虎、eBay、Google 和亚马逊。

### 1.7.5　新千年

在 21 世纪的头三十年里，也许没有哪项技术比因特网以及联网的智能手机更深刻地改变了社会。而计算机网络的创新仍在继续：更快的路由器、接入网与骨干网中更高的传输速率等各方面都在进步。以下发展尤其值得关注：

::: tip 要点

1. **宽带接入大举进入家庭。** 自千年之交以来，家庭宽带接入被大规模部署——不仅有电缆调制解调器和 DSL，还有 1.2 节讨论的光纤到户、5G 固定无线和 LEO 卫星。这种高速接入催生了大量视频应用，包括用户生成视频的分发（如 YouTube、TikTok）、高清电影与电视剧的点播流媒体（如 Netflix）以及多人视频会议（如 Zoom、FaceTime、Google Hangouts）。
1. **高速无线接入日益普及。** 它不仅让人们在移动中保持持续连接，还催生了新的基于位置的应用，包括导航与地图（如 Google 地图、Waze）、网约车（如 Uber、滴滴）、外卖配送、本地商户搜索和婚恋服务（如 Tinder）。2011 年，接入因特网的无线设备数量超过了有线设备。这种高速无线接入为手持计算机（iPhone、Android、iPad 等）的迅速崛起铺平了道路，它们可以持续、无拘无束地接入因特网。
1. **在线社交网络。** Facebook、Instagram、Twitter、TikTok 和微信（在中国极受欢迎）等社交网络在因特网之上构建了庞大的人际网络。其中许多既被大量用于发消息，也用于分享照片和视频。今天许多因特网用户主要"生活"在一个或多个社交网络之中。通过各自的 API，在线社交网络为新形态的联网应用（包括移动支付和分布式游戏）搭建了平台。
1. **内容提供商自建专用网络。** 如 1.3.3 节所述，Google、微软等在线服务提供商部署了自己庞大的专用网络，不仅把其全球分布的数据中心连接起来，还通过与较低层 ISP 直接对等来尽可能绕过因特网。结果是，Google 能以几乎瞬时的速度提供搜索结果和邮件访问，仿佛其数据中心就运行在你自己的计算机里。
1. **应用上云。** 许多因特网商务公司现在把应用运行在"云"上——如 Amazon EC2、微软 Azure 或阿里云。许多公司和大学也把其因特网应用（如邮件和 Web 托管）迁移到云端。云服务公司不仅为应用提供可扩展的计算与存储环境，还让应用隐式地获得了它们高性能专用网络的接入能力。

## 1.8　小结

本章涵盖了极其丰富的内容！我们考察了构成因特网（乃至一般计算机网络）的各种硬件与软件部件。从网络边缘出发，看了端系统与应用，以及运输层为运行在端系统上的应用提供的服务；也看了接入网中常见的链路层技术和物理媒体。随后深入网络内部，进入网络核心，指出分组交换与电路交换是通过电信网传输数据的两种基本方式，并考察了二者各自的优缺点。我们还考察了全球因特网的结构，认识到因特网是"网络的网络"：其由较高层与较低层 ISP 构成的层次结构，使它得以扩展到容纳成千上万个网络。

在本导论性章节的后半部分，我们考察了计算机网络领域的若干核心议题。首先分析了分组交换网中时延、吞吐量和丢包的成因，为传输时延、传播时延、排队时延以及吞吐量建立了简单的定量模型；本书各章的习题中将大量使用这些时延模型。接着考察了协议分层与服务模型——这是网络领域的关键体系结构原理，本书后文也会反复回溯。我们还概览了当今因特网中较普遍的一些安全攻击，最后以一段简短的计算机网络史收束了对网络的介绍。可以说，第一章本身已构成一门计算机网络迷你课程。

是的，我们在第一章里确实走过了大量内容！如果你觉得有点应接不暇，不必担心：后续各章将重新回到所有这些思想，并以远为详细的篇幅展开（这是承诺，不是威胁！）。此时此刻，希望你合上本章时，对构成网络的各个部件已形成尚在生长的直觉，对网络术语已有尚在熟练的掌握（不要不好意思回头翻本章），并对进一步学习网络怀有日益强烈的愿望。这正是本书余下部分的任务。

## 附录 B　符号与公式速查

| 术语 | English |
| --- | --- |
| $L$ | [分组长度（比特）] |
| $R$ | [链路传输速率（比特/秒）] |
| $N$ | [源到目的之间的链路数（因而有 $N - 1$ 台路由器）] |
| $d$ | [两台路由器之间的距离（米）] |
| $s$ | [链路的传播速度（米/秒），约 $2 \times 10^{8}$～$3 \times 10^{8}$] |
| $a$ | [分组到达队列的平均速率（分组/秒）] |
| $F$ | [文件长度（比特）] |

| **公式** | **说明** |
| --- | --- |
| $d_{\text{trans}} = \frac{L}{R}$ | 传输时延 |
| $d_{\text{prop}} = \frac{d}{s}$ | 传播时延 |
| $d_{\text{nodal}} = d_{\text{proc}} + d_{\text{queue}} + d_{\text{trans}} + d_{\text{prop}}$ | 节点时延 |
| $d_{\text{端到端}} = N \frac{L}{R}$ | 存储转发端到端时延 |
| $d_{\text{end-end}} = N(d_{\text{proc}} + d_{\text{trans}} + d_{\text{prop}})$ | 端到端时延 |
| $\text{流量强度} = L \frac{a}{R}$ | 排队时延的关键参数，应 $\le 1$ |
| $\text{吞吐量} = \text{min} \{{R_{s}, R_{c} \} \}}$ | 两链路网络的吞吐量 |
| $\text{吞吐量} = \text{min} \{{R_{1}, \cdots, R_{N} \} \}}$ | 多链路网络的吞吐量 |
| $\text{平均吞吐量} = \frac{F}{T}$ | 文件传送的平均吞吐量 |
| $\text{传送时间} \approx \frac{F}{\text{min}} \{{R_{s}, R_{c} \} \}}$ | 大文件传送时间估计 |

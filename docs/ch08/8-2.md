# 8.2　密码学原理

密码学的历史至少可追溯到尤利乌斯·凯撒，但现代密码学技术（包括因特网中使用的许多技术）基于过去 30 年的进展。Kahn 的《破译者》[Kahn 1967] 与 Singh 的《密码故事：从古埃及到量子密码学的保密科学》[Singh 1999] 对密码学的漫长历史作了引人入胜的梳理。完整讨论密码学本身需要一整本书 [Kaufman 2002; Ferguson 2010; Bishop 2018]，因此这里只触及密码学的本质方面，特别是它在因特网中的实践。还要指出，虽然本节聚焦密码学在机密性方面的用途，但很快会看到密码学技术不可分割地织入了鉴别、报文完整性与不可否认性等等之中。

密码学技术使发送方能伪装数据，使入侵者无法从截获的数据中获得任何信息；接收方当然必须能从伪装后的数据恢复原始数据。图 8.2 说明了其中一些重要术语。

<Figure src="ch08/fig8-02.webp" caption="图 8.2　密码学组件" />

假设 Alice 想给 Bob 发报文。Alice 的报文在其原始形态（例如"Bob, I love you. Alice"）称为**明文**（plaintext）或 **cleartext**。Alice 用**加密算法**加密她的明文报文，使加密后的报文——称为**密文**（ciphertext）——对任何入侵者都显得不可理解。有意思的是，在许多现代密码系统（包括因特网中使用的那些）里，加密技术本身是**公开**的——已发表、已标准化、人人可得（例如 [RFC 1321; RFC 3447; RFC 2420; NIST 2001, 2025]），连潜在的入侵者也能拿到！显然，如果人人都知道编码数据的方法，那就必须有某种**秘密信息**来阻止入侵者解密所传数据——这就是**密钥**的用武之地。

图 8.2 中，Alice 提供一个密钥 $K_{A}$（一串数字或字符）作为加密算法的输入。加密算法以密钥与明文报文 $m$ 为输入，输出密文。记号 $K_{A}(m)$ 表示明文报文 $m$ 的密文形式（用密钥 $K_{A}$ 加密）。使用密钥 $K_{A}$ 的具体加密算法从上下文即可看出。类似地，Bob 向解密算法提供密钥 $K_{B}$，解密算法以密文与 Bob 的密钥为输入，输出原始明文。也就是说，若 Bob 收到加密报文 $K_{A}(m)$，他通过计算 $K_{B}(K_{A}(m)) = m$ 来解密。在**对称密钥**系统中，Alice 与 Bob 的密钥相同且保密。在**公钥**系统中使用一对密钥：其中一个密钥 Bob 与 Alice 都知道（事实上全世界都知道），另一个密钥只有 Bob 或只有 Alice 知道（而不是两人都知道）。下面两小节更详细地考察对称密钥系统与公钥系统。

## 8.2.1　对称密钥密码学

所有密码算法都涉及用一物替代另一物——例如取一段明文，计算并替换为相应的密文，从而造出加密报文。在研究现代基于密钥的密码系统之前，先用一个非常古老、非常简单的对称密钥算法"热热身"：据传出自尤利乌斯·凯撒的**凯撒密码**（cipher 即加密数据的方法）。

对英文文本，凯撒密码把明文中每个字母替换为字母表中其后第 $k$ 个字母（允许回绕，即 z 之后是 a）。例如若 $k = 3$，则明文中的 a 在密文中变成 d，b 变成 e，依此类推。这里 $k$ 的值就是密钥。例如明文"bob, i love you. Alice"变成密文"ere, l oryh brx. dolfh"。密文确实看起来像乱码，但如果你知道用的是凯撒密码，破译它并不需要多久——因为只有 25 个可能的密钥值。

凯撒密码的一种改进是**单表替换密码**（monoalphabetic cipher），它同样用一个字母替换另一个字母；但与按规则模式（例如所有字母都偏移 $k$）替换不同，任何字母都可以替换任何其他字母，只要每个字母有唯一的替换字母、反之亦然。图 8.3 中的替换规则给出了编码明文的一种可能规则。

<Figure src="ch08/fig8-03.webp" caption="图 8.3　一种单表替换密码" />

明文"bob, i love you. Alice"变成"nkn, s gktc wky. Mgsbc."。于是，与凯撒密码一样，这看起来像乱码。单表替换密码似乎也比凯撒密码更好：可能的字母配对有 $26 !$（约 $10^{26}$）种，而不是 25 种。暴力尝试全部 $10^{26}$ 种配对所需的计算量太大，不可能成为破解加密算法、解出报文的可行途径。然而，通过对明文语言作统计分析——例如知道字母 e 与 t 在典型英文文本中出现最频繁（分别占字母出现次数的 13% 与 9%），并知道某些特定的两字母、三字母组合经常一起出现（如 "in"、"it"、"the"、"ion"、"ing" 等）——就比较容易破译这种密码。如果入侵者对报文可能的内容有所了解，破译就更容易。例如，若入侵者 Trudy 是 Bob 的妻子，怀疑 Bob 与 Alice 有婚外情，她可能猜到文中会出现"bob"与"alice"这两个名字。如果 Trudy 确知这两个名字出现在密文中，并且手里有上面那条示例密文，她就能立刻确定 26 个字母配对中的 7 个，使暴力法需要检查的可能性减少 $10^{9}$ 倍。确实，如果 Trudy 怀疑 Bob 有婚外情，她很可能还期望在报文中找到其他一些"关键"词。

在考虑 Trudy 破解 Bob 与 Alice 加密方案的难易程度时，可以根据入侵者掌握的信息区分三种不同情形：

- **唯密文攻击**（ciphertext-only attack）。有些情况下，入侵者只能接触到截获的密文，对明文内容没有确定信息。我们已经看到统计分析如何有助于对加密方案实施唯密文攻击。
- **已知明文攻击**（known-plaintext attack）。上面看到，如果 Trudy 以某种方式确知"bob"与"alice"出现在密文报文中，她就能确定字母 a、l、i、c、e、b、o 的（明文，密文）配对。Trudy 也可能运气好，记录下全部密文传输，然后在某张纸上发现了 Bob 自己写下的其中某次传输的解密版本。当入侵者知道某些（明文，密文）配对时，我们称这是对加密方案的**已知明文攻击**。
- **选择明文攻击**（chosen-plaintext attack）。在选择明文攻击中，入侵者能够选择明文报文并取得其相应的密文形式。对迄今见过的简单加密算法，如果 Trudy 能让 Alice 发送"The quick brown fox jumps over the lazy dog"这条报文，她就能完全破解该加密方案。我们很快就会看到，对更精巧的加密技术，选择明文攻击并不一定意味着加密技术能被破解。

五百年前，人们发明了改进单表替换加密的技术，称为**多表替换加密**（polyalphabetic encryption）。其思想是使用多个单表替换密码，用某个特定的单表替换密码来编码明文报文中某个特定位置上的字母。于是同一个字母出现在明文报文的不同位置时，可能被编码成不同结果。图 8.4 给出一个多表替换加密方案的例子：它有两行凯撒密码（$k = 5$ 与 $k = 19$）。我们可以选择以重复模式 $C_{1}, C_{2}, C_{2}, C_{1}, C_{2}$ 使用这两个凯撒密码 $C_{1}$ 与 $C_{2}$——即明文的第一个字母用 $C_{1}$ 编码，第二、三个用 $C_{2}$，第四个用 $C_{1}$，第五个用 $C_{2}$，然后模式重复，第六个字母用 $C_{1}$、第七个用 $C_{2}$，依此类推。于是明文"bob, i love you."被加密为"ghu, n etox dhz."。注意明文中第一个 b 用 $C_{1}$ 加密，而第二个 b 用 $C_{2}$ 加密。这个例子中，加密与解密的"密钥"是关于两个凯撒密钥（$k_{1} = 5$、$k_{2} = 19$）以及模式 $C_{1}, C_{2}, C_{2}, C_{1}, C_{2}$ 的知识。

### 块密码

现在进入现代，考察今天对称密钥加密是如何做的。我们聚焦**块密码**（block cipher），它用于许多安全的因特网协议，包括 PGP（安全电子邮件）、TLS（保护 TCP 连接）与 IPsec（保护网络层传输）。

在块密码中，待加密的报文按 $k$ 比特一块处理。例如若 $k = 64$，报文被切成 64 比特的块，每块独立加密。为编码一个块，密码用一一映射把 $k$ 比特明文块映射为 $k$ 比特密文块。看一个例子：假设 $k = 3$，块密码把 3 比特输入（明文）映射为 3 比特输出（密文），表 8.1 给出一种可能的映射。注意这是一一映射，即每个输入都有不同的输出。这个块密码把报文切成 3 比特的块，并按上表映射加密每一块。你应当验证报文 `010 110 001 111` 被加密为 `101 000 111 001`。

<p class="tbl-cap">表 8.1　一个具体的 3 比特块密码</p>

| **输入** | **输出** | **输入** | **输出** |
| --- | --- | --- | --- |
| 000 | 110 | 100 | 011 |
| 001 | 111 | 101 | 010 |
| 010 | 101 | 110 | 000 |
| 011 | 100 | 111 | 001 |

继续这个 3 比特块的例子。注意表 8.1 中的映射只是众多可能映射之一。共有多少种可能的映射？回答这个问题要注意：一个映射无非是对所有可能输入的一个**置换**。共有 $2^{3} = 8$ 个可能输入（列在输入栏下），这 8 个输入可以按 $8 ! = 40 320$ 种不同方式置换。既然每种置换都指定一个映射，就有 40 320 种可能映射。我们可以把每种映射看成一个**密钥**——如果 Alice 与 Bob 都知道该映射（密钥），他们就能加密和解密彼此发送的报文。

对这个密码的暴力攻击，就是尝试用所有映射来解密密文。由于只有 40 320 个映射（$k = 3$ 时），这在台式 PC 上很快就能完成。为挫败暴力攻击，块密码通常使用大得多的块，例如 $k = 64$ 比特甚至更大。注意一般 $k$ 比特块密码的可能映射数为 $2^{k} !$，即使 $k$ 取中等大小（如 64），这个数也是天文数字。

<Figure src="ch08/fig8-05.webp" caption="图 8.5　一个块密码的例子" />

虽然如上面所述、$k$ 取中等大小时全表块密码可以产生健壮的对称密钥加密方案，但它们不幸难以实现。对 $k = 64$ 且给定映射，Alice 与 Bob 需要维护一张有 $2^{64}$ 个输入值的表，这是不可能完成的任务。而且，若 Alice 与 Bob 要更换密钥，他们各自还得重新生成该表。因此，提供所有输入输出之间预定映射的**全表**块密码（如上面例子）根本不可行。

因此，块密码通常使用**模拟随机置换表**的函数。图 8.5 给出 $k = 64$ 比特时这样一个函数的例子（改编自 [Kaufman 2002]）。该函数先把 64 比特块分成 8 块，每块 8 比特；每个 8 比特块经一张 8 比特到 8 比特的表处理（规模可管理），例如第一块由记为 $T_{1}$ 的表处理。接着把 8 个输出块重新组装成一个 64 比特块，然后把该块中 64 个比特的位置打乱（置换），产生 64 比特输出。这个输出再被反馈为 64 比特输入，开始下一轮；经过 $n$ 轮这样的循环后，函数给出 64 比特密文块。**轮**（round）的作用是让每个输入比特影响大多数（如果不是全部）最终输出比特。（若只做一轮，某个输入比特只影响 64 个输出比特中的 8 个。）这个块密码算法的密钥就是那八张置换表（假定打乱函数是公开的）。

今天有多种流行的块密码，包括 DES（数据加密标准）、3DES 与 AES（高级加密标准）。这些标准都使用类似图 8.5 的函数而非预定表（尽管更复杂、且各自不同）。这些算法也都使用一串比特作为密钥：例如 DES 使用 64 比特块与 56 比特密钥；AES 使用 128 比特块，可用 128、192 与 256 比特长的密钥。算法的密钥决定算法内部具体的"迷你表"映射与置换。对这些密码的暴力攻击就是遍历所有密钥、用每个密钥执行解密算法。注意密钥长度为 $n$ 时有 $2^{n}$ 个可能密钥。NIST [NIST 2001] 估计，一台能在一秒内破解 56 比特 DES（即一秒内试完 $2^{56}$ 个密钥）的机器，破解 128 比特 AES 密钥大约需要 149 万亿年。

### 密码块链接

在计算机网络应用中，我们通常需要加密长报文或长数据流。若按上面所述简单地应用块密码——把报文切成 $k$ 比特块并独立加密每块——会出现一个微妙而重要的问题。要看清这一点，注意两个或更多明文块可能完全相同，例如两个或更多块的明文都可能是 "HTTP 1.1"。对这些相同的块，块密码当然会产生相同的密文。攻击者看到相同的密文块时可能猜出明文，甚至可能通过识别相同密文块、利用对底层协议结构的知识来解密整个报文 [Kaufman 2002]。

为解决这个问题，我们可以在密文中混入一些随机性，使相同的明文块产生不同的密文块。设 $m(i)$ 表示第 $i$ 个明文块，$c(i)$ 表示第 $i$ 个密文块，$a \oplus b$ 表示两个比特串 $a$ 与 $b$ 的**异或**（XOR）。（回忆 $0 \oplus 0 = 1 \oplus 1 = 0$，$0 \oplus 1 = 1 \oplus 0 = 1$，两个比特串的异或按位进行。例如 `10101010` $\oplus$ `11110000` = `01011010`。）再记密钥为 $S$ 的块密码加密算法为 $K_{S}$。基本思想如下：发送方为第 $i$ 块生成一个随机 $k$ 比特数 $r(i)$，并计算

$$
c(i) = K_{S}(m(i) \oplus r(i))
$$

注意每一块都重新选一个 $k$ 比特随机数。发送方随后发送 $c(1), r(1), c(2), r(2), c(3), r(3)$ 等等。由于接收方收到 $c(i)$ 与 $r(i)$，它可以通过计算 $m(i) = K_{S}(c(i)) \oplus r(i)$ 恢复每个明文块。要特别注意：虽然 $r(i)$ 以明文发送、因而可被 Trudy 嗅探，但她无法得到明文 $m(i)$，因为她不知道密钥 $K_{S}$。还注意若两个明文块 $m(i)$ 与 $m(j)$ 相同，对应密文块 $c(i)$ 与 $c(j)$ 会不同（只要随机数 $r(i)$ 与 $r(j)$ 不同，而这以极高概率成立）。

举例来说，考虑表 8.1 中的 3 比特块密码。假设明文为 `010 010 010`。若 Alice 不引入随机性直接加密，得到的密文是 `101 101 101`。若 Trudy 嗅探到这个密文，由于三个密文块都相同，她可以正确推断三个明文块都相同。现在假设 Alice 生成随机块 $r(1) =$ `001`、$r(2) =$ `111`、$r(3) =$ `100`，并用上述技术生成密文 $c(1) =$ `100`、$c(2) =$ `010`、$c(3) =$ `000`。注意尽管明文块相同，三个密文块却不同。Alice 随后发送 $c(1), r(1), c(2), r(2)$ 等等。你应当验证 Bob 能用共享密钥 $K_{S}$ 得到原始明文。

细心的读者会注意到，引入随机性解决了一个问题却带来了另一个问题：Alice 必须发送两倍的比特数。确实，对每个密文比特，她现在还必须发送一个随机比特，使所需带宽翻倍。为了"既要有蛋糕又要吃掉蛋糕"，块密码通常使用一种称为**密码块链接**（Cipher Block Chaining，CBC）的技术。其基本思想是：只随第一条报文发送一个随机值，随后让发送方与接收方用已算出的密文块代替后续的随机数。具体地说，CBC 的工作方式如下：

1. 加密报文（或数据流）之前，发送方生成一个随机 $k$ 比特串，称为**初始向量**（Initialization Vector，IV），记为 $c(0)$。发送方以明文把 IV 发给接收方。
1. 对第一块，发送方计算 $m(1) \oplus c(0)$，即第一块明文与 IV 的异或；然后把结果送入块密码算法，得到相应密文块，即 $c(1) = K_{S}(m(1) \oplus c(0))$。发送方把加密块 $c(1)$ 发给接收方。
1. 对第 $i$ 块，发送方由 $c(i) = K_{S}(m(i) \oplus c(i - 1))$ 生成第 $i$ 个密文块。

下面考察这种做法的一些后果。第一，接收方仍能恢复原始报文：收到 $c(i)$ 后，它用 $K_{S}$ 解密得到 $s(i) = m(i) \oplus c(i - 1)$；由于接收方也知道 $c(i - 1)$，它随后由 $m(i) = s(i) \oplus c(i - 1)$ 得到明文块。第二，即使两个明文块相同，对应密文（几乎总是）不同。第三，虽然发送方以明文发送 IV，入侵者仍无法解密密文块，因为入侵者不知道密钥 $S$。最后，发送方只多送一个块（IV），对由数百块组成的长报文而言，带宽增加的幅度可以忽略。

举例来说，现在为表 8.1 中的 3 比特块密码确定明文 `010 010 010`、$c(0) =$ `IV` $=$ `001` 时的密文。发送方先用 IV 计算 $c(1) = K_{S}(m(1) \oplus c(0)) =$ `100`；然后计算 $c(2) = K_{S}(m(2) \oplus c(1)) = K_{S}()$`010` $\oplus$ `100`$=$ `000`，以及 $c(3) = K_{S}(m(3) \oplus c(2)) = K_{S}()$`010` $\oplus$ `000`$=$ `101`。读者应当验证：知道 IV 与 $K_{S}$ 的接收方能恢复原始明文。

CBC 在设计安全网络协议时有一个重要后果：我们必须在协议中提供把 IV 从发送方分发到接收方的机制。本章后面会看到几个协议是如何做到这一点的。

## 8.2.2　公钥密码学

两千多年来（从凯撒密码时代直到 20 世纪 70 年代），加密通信要求通信双方共享一个秘密——用于加密与解密的对称密钥。这种途径的一个困难是：双方必须以某种方式就共享密钥达成一致，而要做到这一点本身就需要安全通信。也许双方可以先见面、当面商定密钥（例如凯撒的两名百夫长可以在罗马浴场碰面），此后便可用加密通信。但在网络世界里，通信双方可能永远不见面，除了通过网络之外可能永远不交谈。

两方能否在没有预先共享秘密密钥的情况下进行加密通信？1976 年，Diffie 与 Hellman [Diffie 1976] 演示了一个算法（现在称为 **Diffie-Hellman 密钥交换**）正是做这件事——一种截然不同、精妙优雅的安全通信途径，它促成了今天公钥密码系统的发展。我们很快就会看到，公钥密码系统还有若干美妙性质，使其不仅可用于加密，还可用于鉴别与数字签名。有意思的是，后来发现与 [Diffie 1976] 和 [RSA 1978] 类似的思想，早在 20 世纪 70 年代初就由英国通信电子安全组的研究者在一系列秘密报告中独立提出 [Ellis 1987]。正如常有的事，伟大的思想会在许多地方独立萌发；幸运的是，公钥的进展不仅发生在私下，也发生在公众视野之中。

公钥密码学的使用在概念上相当简单。假设 Alice 想与 Bob 通信。如图 8.6 所示，Bob 与 Alice 并不共享单一秘密密钥（如对称密钥系统那样），而是由 Bob（Alice 报文的接收者）持有两个密钥——一个全世界（包括入侵者 Trudy）都可获得的**公钥**，和一个只有 Bob 知道的**私钥**。我们用 $K_{B}^{+}$ 与 $K_{B}^{-}$ 分别表示 Bob 的公钥与私钥。为与 Bob 通信，Alice 先取得 Bob 的公钥，然后用 Bob 的公钥与一个已知（例如标准化的）加密算法加密她要发给 Bob 的报文 $m$，即 Alice 计算 $K_{B}^{+}(m)$。Bob 收到 Alice 的加密报文后，用他的私钥与一个已知（例如标准化的）解密算法解密，即 Bob 计算 $K_{B}^{-}(K_{B}^{+}(m))$。下面会看到，存在这样的加解密算法与公私钥选取技术，使得 $K_{B}^{-}(K_{B}^{+}(m)) = m$；也就是说，对报文 $m$ 施加 Bob 的公钥 $K_{B}^{+}$（得到 $K_{B}^{+}(m)$），再对 $m$ 的加密版本施加 Bob 的私钥 $K_{B}^{-}$（即计算 $K_{B}^{-}(K_{B}^{+}(m))$），会还原出 $m$。这是个非凡的结果！这样，Alice 就能用 Bob 公开可得的密钥给 Bob 发送秘密报文，而双方都不必分发任何秘密密钥！很快会看到，我们还可以把公钥与私钥的加密次序对调而得到同样非凡的结果——即 $K_{B}^{+}(K_{B}^{-}(m)) = K_{B}^{-}(K_{B}^{+}(m)) = m$。

虽然公钥密码学很有吸引力，但一个担忧立刻浮现：既然 Bob 的加密密钥是公开的，任何人都能给 Bob 发送加密报文，包括 Alice，也包括某个冒充 Alice 的人。在单一共享秘密密钥的情形下，发送方知道秘密密钥这一事实本身就向接收方隐含地标识了发送方；而在公钥密码学中不再如此，因为任何人都能用 Bob 公开可得的密钥给 Bob 发送加密报文。这时就需要**数字签名**（8.3 节研究的话题）来把发送方与报文绑定起来。

### RSA

虽然可能有许多算法应对这些关切，但 **RSA** 算法（以其创始人 Ron Rivest、Adi Shamir 与 Leonard Adleman 命名）几乎已成为公钥密码学的同义词。先看 RSA 如何工作，再考察它为何有效。

RSA 大量使用模 $n$ 算术运算。先简要回顾模算术：$x \bmod n$ 就是 $x$ 除以 $n$ 的余数，例如 $19 \bmod 5 = 4$。在模算术中照常做加、乘与幂运算，但每次运算的结果都替换为除以 $n$ 后留下的整数余数。模算术中的加法与乘法可由以下几条有用事实简化：

$(a \bmod n) + (b \bmod n) \bmod n = (a + b) \bmod n$
  
  $(a \bmod n) - (b \bmod n) \bmod n = (a - b) \bmod n$
  
  $(a \bmod n) \times (b \bmod n) \bmod n = (a \times b) \bmod n$

由第三条事实可得 $(a \bmod n)^{d} \bmod n = a^{d} \bmod n$，这个恒等式我们很快会用到。

现在假设 Alice 想给 Bob 发送一条 RSA 加密报文，如图 8.6 所示。讨论 RSA 时始终要记住：报文无非是一个比特图案，而每个比特图案都能被唯一地表示为一个整数（连同比特图案的长度）。例如，若报文是比特图案 `1001`，它可表示为十进制整数 9。因此用 RSA 加密报文，等价于加密代表该报文的那个唯一整数。

RSA 有两个相互关联的组成部分：

- 公钥与私钥的选取；
- 加密与解密算法。

为生成 RSA 公私钥，Bob 执行以下步骤：

1. 选两个大素数 $p$ 与 $q$。$p$ 与 $q$ 该多大？值越大，RSA 越难被破解，但编解码耗时也越长。RSA 实验室建议 $p$ 与 $q$ 的乘积在 1 024 比特量级。如何寻找大素数见 [Prime 2025]。
1. 计算 $n = p q$ 与 $z = (p - 1)(q - 1)$。
1. 选一个小于 $n$ 的数 $e$，使它与 $z$ 没有（除 1 以外的）公因子（此时称 $e$ 与 $z$ **互素**）。用字母 $e$ 是因为该值将用于加密。
1. 找一个数 $d$，使 $e d - 1$ 恰好能被 $z$ 整除（即无余数）。用字母 $d$ 是因为该值将用于解密。换言之，给定 $e$，我们选 $d$ 使

$$
e d \bmod z = 1
$$

1. Bob 向全世界公开的公钥 $K_{B}^{+}$ 是数对 $(n, e)$；他的私钥 $K_{B}^{-}$ 是数对 $(n, d)$。

Alice 的加密与 Bob 的解密如下进行：

- 假设 Alice 想给 Bob 发送由整数 $m$ 表示的比特图案（$m < n$）。为编码，Alice 计算 $m$ 的 $e$ 次幂，再求 $m^{e}$ 除以 $n$ 的整数余数。换句话说，Alice 明文报文 $m$ 的加密值 $c$ 为

$$
c = m^{e} \bmod n
$$

- 与该密文 $c$ 对应的比特图案被发送给 Bob。
- 为解密收到的密文 $c$，Bob 计算

$$
m = c^{d} \bmod n
$$

这需要用到他的私钥 $(n, d)$。

作为 RSA 的一个简单例子，假设 Bob 选 $p = 5$、$q = 7$（诚然，这些值太小，远不安全），则 $n = 35$、$z = 24$。Bob 选 $e = 5$，因为 5 与 24 没有公因子。最后 Bob 选 $d = 29$，因为 $5 \times 29 - 1$（即 $e d - 1$）恰好能被 24 整除。Bob 公开 $n = 35$ 与 $e = 5$ 两个值，并保密 $d = 29$。看到这两个公开值后，假设 Alice 想给 Bob 发送字母 l、o、v、e。把每个字母解释为 1 到 26 之间的数（a 为 1，z 为 26），Alice 与 Bob 分别执行表 8.2 与表 8.3 所示的加密与解密。注意这个例子中我们把四个字母各当作一条独立报文；更现实的例子是把四个字母转成 8 比特 ASCII 表示，再加密所得 32 比特图案对应的整数（这样的现实例子产生的数太长，无法印在教材里！）。

### 会话密钥

这里要指出，RSA 所需的幂运算相当耗时。因此实践中 RSA 常与对称密钥密码学结合使用。例如，若 Alice 想给 Bob 发送大量加密数据，她可以这样做：首先 Alice 选一个用于编码数据本身的密钥，称为**会话密钥**（session key），记为 $K_{S}$。Alice 必须把会话密钥告知 Bob，因为这是他们将用对称密钥密码（如 DES 或 AES）共享的对称密钥。Alice 用 Bob 的公钥加密会话密钥，即计算 $c = K_{S}^{e} \bmod n$。Bob 收到 RSA 加密的会话密钥 $c$ 并解密，得到会话密钥 $K_{S}$。Bob 现在知道了 Alice 将用于其加密数据传输的会话密钥。

### RSA 为何有效？

RSA 的加解密看起来相当神奇。为什么先施加加密算法、再施加解密算法就能恢复原始报文？为理解 RSA 为何有效，再次记 $n = p q$，其中 $p$ 与 $q$ 是 RSA 算法所用的大素数。回忆在 RSA 加密下，报文（由整数唯一表示）$m$ 用模 $n$ 算术求 $e$ 次幂，即 $c = m^{e} \bmod n$。解密则用模 $n$ 算术把这个值求 $d$ 次幂。因此加密一步再解密一步的结果是 $(m^{e} \bmod n)^{d} \bmod n$。来看看关于这个量能说什么。如前面所述，模算术有一个重要性质：对任意 $a$、$n$、$d$，有 $(a \bmod n)^{d} \bmod n = a^{d} \bmod n$。于是取 $a = m^{e}$ 代入该性质，得

$$
(m^{e} \bmod n)^{d} \bmod n = m^{e d} \bmod n
$$

因此剩下的就是证明 $m^{e d} \bmod n = m$。虽然我们想为 RSA 去掉一些"魔法"，但要确立这一点，还得用一个相当神奇的数论结果：若 $p$ 与 $q$ 为素数、$n = p q$、$z = (p - 1)(q - 1)$，则 $x^{y} \bmod n$ 与 $x^{y \bmod z} \bmod n$ 相同 [Kaufman 2002]。把该结果用于 $x = m$、$y = e d$，得

$$
m^{e d} \bmod n = m^{e d \bmod z} \bmod n
$$

但记住我们选取 $e$ 与 $d$ 时使 $e d \bmod z = 1$。于是

$$
m^{e d} \bmod n = m^{1} \bmod n = m
$$

这正是我们要的结果！先求 $e$ 次幂（加密）再求 $d$ 次幂（解密），就得到原始值 $m$。更美妙的是：若先求 $d$ 次幂再求 $e$ 次幂——即把加密与解密的次序颠倒，先执行解密操作再施加加密操作——同样得到原始值 $m$。这个美妙结果直接来自模算术：

$$
m^{d e} \bmod n = m^{e d} \bmod n = (m^{e} \bmod n)^{d} \bmod n = m
$$

近年来，**椭圆曲线密码学**（ECC）已成为公钥密码学中 RSA 的替代方案，两者的优缺点见 [Gupta 2002; VMware 2025]。RSA 的安全性依赖于：目前没有已知算法能把公开值 $n$ 快速分解为素数 $p$ 与 $q$。若某人知道了 $p$ 与 $q$，那么给定公开值 $e$，他就能轻易算出秘密密钥 $d$。另一方面，是否存在快速分解算法尚不可知；在这个意义上，RSA 的安全性并无保证。ECC 的安全性依赖于求解一个同样困难的问题。随着量子计算的最新进展以及已发表的量子计算机快速分解算法，人们担心 RSA 可能无法永远安全 [MIT TR 2019; RSA 2024]。虽然这些算法的实际实现看来仍遥遥无期，但对后量子时代现代密码学的担忧已相当严肃，以至于美国国家标准与技术研究院公开征集、评估并提出了三项抗量子公钥密码算法标准草案 [NIST 2025]。

### 用公钥密码学协商共享密钥

后面几节会看到，公钥密码学不仅可用来提供加密服务，还可用来提供报文完整性、数字签名与鉴别。它还能为两个此前从未交互、因而无法事先选定共享秘密的通信实体派生一个对称密钥（共享秘密）。这在客户端-服务器应用中很有用——客户端与服务器想用共享对称密钥加密它们的交互。

做到这一点的方法称为 **Diffie-Hellman（DH）密钥协商协议**，以其发明者 Whitfield Diffie 与 Martin Hellman 命名。我们将在 8.6 节看到，DH 是用于保护因特网运输层通信的**运输层安全**（TLS）协议的核心组件。

DH 协议使用一个大素数 $p$ 与另一个小于 $p$ 的大数 $g$。Bob 或 Alice 选定 $p$ 与 $g$ 并公开其值，使双方（以及任何攻击者！）都知道。随后 Alice 与 Bob 各自独立选择私密值 $S_{A}$ 与 $S_{B}$。建议 $p$、$S_{A}$ 与 $S_{B}$ 的长度为 2 048 比特或更多。Alice 通过把 $g$ 求 $S_{A}$ 次幂再取模 $p$ 来计算她的公钥 $K_{A}^{+}$：

$$
K_{A}^{+} = g^{S_{A}} \bmod p
$$

Bob 类似地计算他自己的公钥 $K_{B}^{+}$：

$$
K_{B}^{+} = g^{S_{B}} \bmod p
$$

DH 的安全性依赖于：给定 $K_{A}^{+}$、$g$ 与 $p$，要确定上式中 $S_{A}$ 的值极其困难（确定 $S_{B}$ 同理）。确实，确定 $S_{A}$ 与 $S_{B}$ 的难度，与把 RSA 中的公开值 $n$ 分解为 RSA 素数 $p$ 与 $q$ 的难度相当。

现在看 Alice 与 Bob 如何在不显式交换共享秘密的情况下计算出共同的共享秘密。Alice 取人人皆知的 Bob 公钥 $K_{B}^{+}$，把它求她的秘密密钥 $S_{A}$ 次幂再取模 $p$：

$$
\text{Alice 算出的共享秘密} = (K_{B}^{+})^{S_{A}} \bmod p
$$

Bob 类似地计算：

$$
\text{Bob 算出的共享秘密} = (K_{A}^{+})^{S_{B}} \bmod p
$$

下面验证 Bob 与 Alice 确实算出同一个共享秘密——这里只需一点模算术的技巧。Alice 算出的共享密钥是 $(K_{B}^{+})^{S_{A}} \bmod p = (g^{S_{B}} \bmod p)^{S_{A}} \bmod p$，其中用了 $K_{B}^{+}$ 的定义。而按模算术规则，$(g^{S_{B}} \bmod p)^{S_{A}} \bmod p = g^{S_{B} S_{A}} \bmod p = g^{S_{A} S_{B}} \bmod p$。类似地，Bob 算出的共享密钥是 $(K_{A}^{+})^{S_{B}} \bmod p = (g^{S_{A}} \bmod p)^{S_{B}} \bmod p = g^{S_{A} S_{B}} \bmod p$，与 Alice 算出的共享密钥完全相同！

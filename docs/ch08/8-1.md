# 8.1　什么是网络安全？

我们从那对恋人 Alice 与 Bob 说起——他们想"安全地"通信。这究竟意味着什么？当然，Alice 希望只有 Bob 能看懂她发出的报文，即使他们是在不安全的介质上通信、入侵者（Trudy，那个入侵者）可以截获 Alice 发给 Bob 的任何东西。Bob 也希望确认他从 Alice 收到的报文确实是 Alice 发的，而 Alice 希望确认与她通信的人确实是 Bob。Alice 与 Bob 还希望确保他们报文的内容在传输中没有被改动。他们还希望能通信得起来（即没有人剥夺他们访问通信所需资源的权利）。基于这些考虑，可以识别出安全通信的以下理想性质。

- **机密性**（confidentiality）。只有发送方与预期接收方能看懂所传报文的内容。由于窃听者可能截获报文，这必然要求报文以某种方式**加密**，使截获的报文无法被截获者看懂。机密性这一侧面大概是"安全通信"一词最常被理解的含义。我们将在 8.2 节研究加密与解密数据的密码学技术。
- **报文完整性**（message integrity）。Alice 与 Bob 希望确保其通信内容在传输中未被改动，无论是恶意改动还是意外改动。对我们在可靠运输与数据链路协议中遇到的校验和技术加以扩展，就可以提供这种报文完整性。我们将在 8.3 节研究报文完整性。
- **端点鉴别**（end-point authentication）。发送方与接收方都应能确认通信对方的身份——确认对方确实是其所声称的那个人或那个东西。面对面的人际交流靠视觉识别轻易解决了这个问题；而当通信实体在彼此看不见的介质上交换报文时，鉴别就不那么简单了。当用户想访问自己的收件箱时，邮件服务器如何核实该用户就是他自称的那个人？我们将在 8.4 节研究端点鉴别。
- **运行安全**（operational security）。今天几乎所有组织（公司、大学等）的网络都连接到公共因特网，因此这些网络都可能被攻陷。攻击者可能试图向网络中的主机植入蠕虫、获取企业机密、测绘内部网络配置，并发起 DoS 攻击。我们将在 8.9 节看到，防火墙与入侵检测系统这类运行设备被用来对抗针对组织网络的攻击：防火墙位于组织网络与公共网络之间，控制进出该网络的分组访问；入侵检测系统执行"深度分组检查"，就可疑活动向网络管理员告警。

明确了网络安全的含义，接下来考虑入侵者究竟能接触到哪些信息、能采取哪些动作。图 8.1 说明了这个场景。发送方 Alice 想向接收方 Bob 发送数据。为在满足机密性、端点鉴别与报文完整性要求的前提下安全地交换数据，Alice 与 Bob 将交换控制报文与数据报文（很像 TCP 发送方与接收方交换控制报文段与数据报文段）。这些报文的全部或一部分通常会被加密。如 1.6 节所述，入侵者可能进行

- **窃听**——在信道上嗅探并记录控制报文与数据报文；
- **修改、插入或删除**报文或报文内容。

我们将会看到，除非采取适当的对抗措施，这些能力使入侵者能够发动各种各样的安全攻击：窥探通信（可能窃取口令与数据）、冒充另一实体、劫持正在进行的会话、通过压垮系统资源来拒绝向合法网络用户提供服务，等等。这类脆弱性的汇总见 CERT 协调中心 [CERT 2025]。

既然因特网中确实存在真实的威胁，那么我们需要安全通信的"Alice 与 Bob"在因特网中的对应物是什么？当然，Bob 与 Alice 可以是两个端系统上的人类用户——例如真实的 Alice 与真实的 Bob 确实想交换安全电子邮件；他们也可能是电子商务交易的参与者，例如真实的 Bob 想在网上购物时把信用卡号安全地传给某台 Web 服务器，真实的 Alice 想与她的银行在线交互。需要安全通信的各方也可能本身就是网络基础设施的一部分。回忆域名系统（DNS，2.4 节）或交换路由信息的路由守护程序（第 5 章）都需要两方之间的安全通信；网络管理应用（第 5 章考察的话题）也是如此。一个能主动干扰 DNS 查询（2.4 节）、路由计算（5.3、5.4 节）或网络管理功能（5.5、5.7 节）的入侵者，能在因特网中造成严重破坏。

至此我们确立了框架、几个最重要的定义以及网络安全的必要性，接下来深入密码学。密码学在提供机密性方面的用途不言自明；但我们很快就会看到，它对提供端点鉴别与报文完整性也至关重要——这使密码学成为网络安全的基石。
